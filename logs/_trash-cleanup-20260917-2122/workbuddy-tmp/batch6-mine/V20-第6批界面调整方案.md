## 〇、本轮最关键的一条架构事实（先说，因为它决定了后面所有做法）

**插件的 `store/layout.js` 自己就是宿主读的那个布局 store。**

`dsh-director-plugin/src/store/layout.js:280`：

```js
export const directorLayoutStore = createDirectorLayoutStore();
if (typeof window !== "undefined") window.__directorLayoutStore = directorLayoutStore;
```

宿主 `client.js:7111 / 9146` 读的就是 `window.__directorLayoutStore`。实测该 store 的 state：

```
directorPanelWidth: 300   directorPanelCollapsed: false   focusTarget: "director"
bottomPanelHeight: 180    bottomPanelCollapsed: true
activeNodeId / leftTab / dialogOpen / designStudioOpen / mindmapOpen / floatDockOpen
mmPos / sectionCollapsed{r2,r4,r6} / railPinned{r4,r7}
```

⇒ **左栏宽度 / 折叠 / 记忆面板高度与开合，全部是插件能直接写的字段**，不需要改宿主、也不需要 DOM 硬改状态。

第二条事实：**渲染进程没有任何文件/Electron 桥**。实测：

```
window.require / global / electron / process  → 全部 "undefined"
navigator.clipboard                            → object（可用）
```

⇒ 「打开文件 / 打开文件夹」这类需求**在本进程内不可能实现**（见需求 4 的降级判定）。

## 一、需求 1 —— 对话页左栏两条 + 折叠仍占位

**原话**：「对话的tap页面 总监和下面哪一个- 这两列不要, 在 现在总监列的最右侧增加最小化, 左右的宽度要允许调整, 最小化这个空白还是存在的, 最小化之后旁边的对话要占满」
**澄清结论（用户已选）**：**两条全删**；左栏折叠时**不再占位**；最小化入口由插件侧承担。

### 现状取证（真机实测）

| 元素 | 宿主源码 | 实测 rect | 内容 |
|:--|:--|:--|:--|
| 左栏容器 | `client.js:7331` | `[280, 76, 301, 718]` | 展开态 `width:directorPanelWidth, minWidth:180` |
| 蓝色「总监」条 | `client.js:7337` | `[280, 76, 300, 24]` | `span`「总监」(11px/600) + 项目名；`backgroundColor:var(--dsh-ac)` |
| 「总监对话 —」条 | `client.js:7342` | `[280, 100, 300, 40]` | `span`「总监对话」+ `button`「—」(30×27, `title="折叠总监面板"`) |
| 折叠态 | `client.js:7327` | 宽 **300** | `▶` + 竖排「总监面板 · 点击展开」 ⇒ **用户说的「空白还是存在的」** |

### 方案

1. **删两条**（可逆，沿用既有裁剪模式）：
   - 蓝色「总监」条 → trim（结构判据：`flex` + `justify-content:space-between` + `backgroundColor` 为 `--dsh-ac` + 首个子 `span` 文本恰为「总监」+ 宽度 = `directorPanelWidth`）
   - 「总监对话」条 → `up:0` 改为 **`up:1`**（整行隐掉 ⇒「—」一并去掉，符合「两条全删」）
2. **折叠态列宽归零**：命中折叠条（结构判据：`title === "展开总监面板"` 且含 `▶` + 文本「总监面板 · 点击展开」）⇒ 覆写 `width:0; minWidth:0; padding:0; border:0; overflow:hidden`。
   ⚠️ 原值先读后写（纪律 26），`restore` 按原值还原。
3. **最小化入口**：在左栏**最右上角**注入一个 `◀` 按钮（`data-testid="host-panel-min"`），点击调 `window.__directorLayoutStore.toggleDirectorCollapsed()`。
   自愈：MutationObserver 每轮检查按钮是否仍在，丢了就重建（宿主重渲染不会带走我们 append 的节点，但整块替换会）。
4. **宽度拖拽**：沿用宿主既有 9px 热区（不重复造）；额外在折叠态把它隐藏。

## 二、需求 2 —— R4/R7 hover 不好用 + 总监记忆

**原话**：「r4和r7的鼠标移动不好用」「总监记忆逻辑完善掉, 同时这一列同样加载鼠标移过来展开,移走缩回的逻辑」
**澄清结论（用户已答）**：「增加一个秒数，目前太灵敏了；总监及以下面的有不同的记忆索引等，把这边部分逻辑完善掉；这个固定也不好用需要修正；还要可以上下调整高度」

### 现状取证

| 面 | 现状 | 问题 |
|:--|:--|:--|
| 插件 R4/R7 rail | `RAIL_HOVER_MS = 5000`（hover **5 秒**才展开）；移出 `RAIL_RETRACT_MS = 600` | 「鼠标移动不好用」= 要停 5 秒，符合直觉的 0.5–1 秒内什么都不会发生 |
| 宿主 总监记忆 | `client.js:7369` `onMouseEnter → setBottomPanelCollapsed(false)` **无任何延迟** | 「太灵敏」 |
| 宿主 总监记忆 · 锁定 | `window.__dshMemoryLocked` 只挡 hover，点击标题时 `toggleBottomPanel()` **仍会翻转** | 「固定不好用」= 锁定态点一下还是会收/开 |
| 宿主 总监记忆 · 高度 | 内容区写死 `maxHeight:160`；store 里的 `bottomPanelHeight` **完全没被这个面板使用** | 「不能上下调整高度」 |
| 宿主 总监记忆 · 内容 | 写死一句「悬停查看记忆内容，数据自动持久化到IndexedDB」 | 「总监及以下有不同的记忆索引」= 内容不随作用域变 |

### 方案

1. **R4/R7 延迟可配**：`RAIL_HOVER_MS` 5000 → **500**（集中常量不变，仍单点）；`RAIL_RETRACT_MS` 600 → **300**。rail 已有「点击钉住」作为需要常开的路径，故缩短 hover 不会造成误触回归。
2. **总监记忆 hover 加延迟**：在 `document` **捕获阶段**接管 `mouseover/mouseout`（捕获早于宿主 React 的委托回调）→ `stopPropagation()` 拦掉宿主的即时展开，由我们按 `MEM_HOVER_MS`（默认 **700ms**）定时展开、按 `MEM_RETRACT_MS`（默认 **400ms**）延迟收回。锁定时（`__dshMemoryLocked`）两个方向都不生效。
3. **修锁定语义**：锁定 = **只锁"不许自动收"**；点击标题栏时**只切锁、不 toggle 面板**（覆盖 `resetLock` 行为）。⇒ 锁定时鼠标移开不缩回，再点解锁才恢复 hover 语义。
4. **上下调高**：在记忆面板上沿注入 6px 拖拽手柄（`cursor: row-resize`），拖动写 `setBottomPanelHeight(h)`（store 已 clamp 60..400）；同时把内容区 `maxHeight` 由 160 覆写为 `bottomPanelHeight - 22`。
5. **按作用域分记忆索引**：记忆面板内容改为读**插件自己的**作用域单一真相源 `store/hierarchy.js: scopeKeyOf(nodeId, node)`，分三档显示：全局 / 文件夹 / 会话；每档给「记忆条目数 / 索引文档数 / 库计数」——数字全部取自真实库（`plugin-db` / `docs-index`），取不到就说取不到。

### 验收判据

| 编号 | 判据 |
|:--|:--|
| M1 | `RAIL_HOVER_MS === 500` 且 `RAIL_RETRACT_MS === 300`（源码常量 + 运行时常量双读） |
| M2 | 鼠标移入 rail 后 **<800ms** 内 `data-rail-r4 === "open"`（正对照：移入后 200ms 仍为 `in`） |
| M3 | 记忆面板：移入后 **<1000ms** 展开；移入后 300ms 时仍为折叠（证明"加了延迟"而不是"没生效"） |
| M4 | 锁定态：移出后 1200ms 仍展开；点标题栏一次 → 锁定解除、面板状态**不翻转** |
| M5 | 拖动记忆面板上沿 +40px ⇒ `bottomPanelHeight` 从 180 变为 220（±4）；内容区 `maxHeight` 同步变化 |
| M6 | 记忆面板内容随 `data-scope-kind` 变化（切三个作用域，三档文案/数字至少两处不同） |

## 三、需求 3 —— R4 条目两行 / 详情 / 未完成项展开补说明

**原话**：「r4,其中这些文档, 已完成任务…换行是"T-INIT-0032026-08-24"这样, "T-INIT-0032026-08-24" 靠右。代办使用一样逻辑，未完成事项，然后才是对应的号。r4的已完成未完成任务还有文档，点击的时候可以查看详情，未完成任务我可以展开，增加补充说明之类的，在执行的时候读取尽量不影响上下文？…然后每一项点开的时候占用总监对话区，缩回去的时候在显示总监对话区」

### 现状取证

- 条目现在是**单行 flex**：`编号 | 优先级 | 任务 | 状态`（`renderR4Body` 内三处）。
- 实测截图：R4 宽 200px 时任务文字**逐字竖排换行**（截图 `-4dfebf32` 左边那列），因为 `clampText(r.task, 90)` 之后仍放不下。
- 没有详情视图（只有「文档」Tab 有钻孔视图 `dp-r4-doc-view`）；没有补充说明载体。

### 方案

1. **条目改两行**（三个 Tab 统一）：
   - 第 1 行：描述（任务正文，`whiteSpace:normal; wordBreak:break-word`）
   - 第 2 行：`编号` + `日期`（已完成/待办各自取 `date`）拼成一个不可拆的整体，`marginLeft:auto` **靠右**。
     格式即用户给的样例：`T-INIT-003` + `2026-08-24` → 渲染为 `T-INIT-0032026-08-24`（同一行、同一 `data-*` 内，便于断言"靠右"= 该 `span` 的 `offsetLeft` 明显大于父宽一半）。
2. **点条目 → 详情占用 R5**：`r4Detail` 状态；为真时 R5 区渲染详情卡（标题/编号/日期/优先级/关联文档/补充说明全文 + 返回），并支持 Esc 返回。缩回即恢复 R5 原内容。
3. **未完成项可展开写补充说明**：详情卡内 `textarea` + 「保存」；写入**插件独立库**（`plugin-db`，新 store `todoNotes`，键 = `scopeKey + "::" + taskId`）。
4. **「不影响上下文」的答案**（用户明确在问这一点）：
   - 说明**不写进** 03/04 台账 Markdown，也不进任何会被整篇读入的文档；
   - 只在 `logic/director-run.js` 拼提示词时，**按当前作用域 + 当前任务 id 取单条**，并截断到上限（≤600 字符）；
   - ⇒ 总监执行时上下文增量是 **O(1) 条**，不是整本台账。

### 验收判据

| 编号 | 判据 |
|:--|:--|
| R4-1 | 每条记录恰好 2 行：`[data-testid="dp-r4-row"]` 下 `[data-testid="dp-r4-desc"]` 与 `dp-r4-id` 各 1 |
| R4-2 | `dp-r4-id` 的右边缘与行右边缘差 ≤4px（"靠右"是几何断言，不是看文案） |

## 五、需求 5 —— 宽度可拖 + R4/R5/R7 无缝拼接

**原话**：「r4和r7的宽度都要允许自由拖拽, r4.r5,r7中间拼接的部分都改成无缝的, 靠在一起就行」

### 方案

1. **缝**：`S.cols.gap` 7 → **0**；三栏之间靠相邻 border 形成 1px 分隔线（`borderRight` 只画一次，避免 2px 双线）。
2. **拖拽**：store 新增字段 `railWidth: { r4: 200, r7: 210 }` + `setRailWidth(side, w)`（clamp 140..420）。
   - 只在**展开态**渲染 4px 拖拽条（`data-testid="dp-r4-resizer"` / `dp-r7-resizer`，`cursor:col-resize`）；
   - 拖动写 store（持久化 ⇒ 下次开机保持）；
   - 折叠态不渲染（用 rail 的 26px）。
   - ⚠️ `DEFAULTS` 已用「只合并已知字段」策略，**新增键是安全的**（老数据缺键走默认）。

### 验收判据

| 编号 | 判据 |
|:--|:--|
| C1 | `dp-cols` 的 `columnGap === "0px"` |
| C2 | 相邻两栏 `rect.right` 与下一栏 `rect.left` 差 ≤1px（无缝） |

## 六、需求 6 —— 「执行状态 / 调用技能」窗口始终不出现

**原话**：「我要的执行状态调用技能的窗口还是没有,具体实现逻辑也要完善」

### 现状取证（根因已定位）

- 窗口组件存在：`DirectorPage.js` 的 `dp-running`（板块 D），条件是 `running.length > 0` 才挂载。
- 数据源 `listAgentRuns()` 读 `DirectorDialog.js:87` 的模块级数组 `agentRuns`。
- `recordAgentRun()` 的**全部调用点都在 `DirectorDialog.js` 内**（436/535/550/560/603 行：自动审核 / 六维 / 路由候选 / 手选调用）。
- **总监页的执行链（`deliver() → runDirector()`）与 `consoleAct()` 七个动作一次都没记账** ⇒ 数组恒空 ⇒ 窗口永不挂载。
  ⇒ 这正是用户「还是没有」的原因：**不是窗口坏了，是没人往里写数据**。

### 方案

1. **把记账下沉到执行链**：`logic/director-run.js` 的五步各步结束、`logic/duties.js` 每个职责执行处调用 `recordAgentRun(key, status, note)`；`consoleAct` 七个动作 likewise。
2. **窗口语义升级为「执行状态」**：除「最近 5 分钟用过谁」，再显示**当前正在执行**（`busy` 时置顶一条 `running` 状态 + 步骤序号），执行结束转为 `ok/warn/fail`。
3. **补 `data-*` 供断言**：`data-count` / `data-generating` / 每条 `data-status`。
4. 空态仍不挂载（避免"空窗常驻像坏了"），但**引擎状态**改由 `dp-running` 之外的常驻位（R2.5 计数行）显示，保证"没有调用记录"这件事**可见**。

### 验收判据

| 编号 | 判据 |
|:--|:--|
| G1 | 运行一次 `consoleAct("review")` ⇒ `agentRuns.length ≥ 1`（此前恒 0，是**先证前提**） |
| G2 | 该次执行后 `dp-running` 挂载，且 `data-count ≥ 1` |
| G3 | 执行中（`busy===true`）`dp-running` 内存在 `data-status="running"` 的条目 |
| G4 | 负对照：清空 `agentRuns` 后 `dp-running` **不挂载**（证明它不是恒渲染的假窗口） |

## 七、需求 7 —— 「总监/对话」切换：合成一个按钮，移到 composer 统计行之前

1. **R8 里那两颗按钮合并**为一颗 `dp-scope-toggle`（文案随状态：`总监` / `对话`），点击在 `DIM.DIRECTOR ↔ DIM.CHAT` 之间切换 —— 这是**唯一的写入点**（`pickTarget` 仍复用，不新造分支）。
2. **把该按钮注入到宿主统计行之前**：`bridge/` 新增 `host-composer-slot.js`，在 `._6sWLG_root` 的**第一个子节点之前** `insertBefore` 我们的容器（`data-testid="dp-host-scope-toggle"`）。带：

   - MutationObserver 自愈（宿主重渲染后重新插入）；
   - 不可用 ⇒ **降级**：按钮退回渲染在 R8 原位（并行保留），并在 `data-*` 里写原因。
3. **R5 增加「对话」视图**：`r5tab` 增加 `chat` 一档。数据源 = 宿主自己的会话历史 `localStorage["dsh.conversation.chat." + scopeKey]`（实测该键存在），解析出 messages 后按左右分栏渲染；键不存在 ⇒ 明说「该会话没有对话历史」，**不显示空列表**。

## 八、需求 8 —— 把本地模型配到「标准模型选择」中

**原话**：「把本地模型的配置配到标准的模型选择中」

### 取证（三连否，必须如实上报）

1. **标准模型选择的真相源不在插件手里**：
   - 宿主标准选择器由 `@deepseek-ai/dsh-client-ui-model-selection` 提供，数据来自 RPC `session.models` / `llm.models`；
   - 默认模型落在 **`C:\Users\15142\.dsh\settings.yaml`**：
     ```yaml
     agent-default-model:
       provider: deepseek-official
       model: deepseek-v4-flash
       reasoningEffort: off
     ```
   - 可用 provider 包只有 `dsh-llm-deepseek` 与 `dsh-llm-pi-ai`（后者是 **OpenAI 兼容**通道）。**全仓无 `ollama` provider 包**（grep `ollama` 仅命中宿主 UI 里那支探测函数）。
2. **本机没有在跑本地模型**：插件已有的探测接口 `window.__dshCheckOllama(cfg)` 实测返回

3. **插件无权写这个配置**：渲染进程无 `require`/`electron`/`fs`（见 §〇第二条），写不了 `~/.dsh/settings.yaml`。

### 判定与后续

**⇒ 本项超出插件可及范围，且前置条件（本地模型在跑、存在可用的本地 provider）不满足 ⇒ 本轮不实现，如实上报。**

③ 由用户在设置 → 模型里选它。
（①③ 属用户侧动作；② 我可以改，但要先备份 `settings.yaml`，且**这条不属于本仓库基线**，需用户点头。）
