### 🔴 稳定 id —— 幂等的根基

```
workspace → ws_<workspaceId>   （未分组：ws___ungrouped__）
session   → se_<sessionId>
```

节点 id **必须由数据源主键派生**，不能用随机 id：否则每次同步都新建一套节点
（重复膨胀），且无法判定"已覆盖"。

真机反证：第二次同步 `created = 0 / updated = 10`，节点总数恒为 **11**（1+2+8）。

### 覆盖度自检 `auditCoverage()`

```js
{
  source: "localStorage",
  sessions: { total: 8, covered: 8, missing: [], rate: "100%" },
  folders:  { total: 2, covered: 2, missing: [], rate: "100%" },
  global:   { total: 1, covered: 1, rate: "100%" },
  ok: true
}
```

`missing[]` 可枚举未覆盖项 —— 直接回答"是否每一个都有总监"。

## 六、本轮修复的两个实测缺陷

### 缺陷 1：所有会话同名「会话 session-」

`shortId(id, 8)` 对 `session-4e8e9e49-…` 取前 8 位 = 常量前缀 `session-`
→ 8 个会话全部显示「会话 session-」，**无法区分**。

修复：新增 `sessionLabel()`，先剥离 `^session-` 再截断 → `会话 4e8e9e49`。

### 缺陷 2：面板停留在同步前的陈旧快照（0/8）

面板在**插件启动时**挂载并渲染首帧，此时自动同步（异步）**尚未完成**
→ 实测显示「⚠️ 存在未覆盖 · 会话 0/8 · 文件夹 0/2」，而真实覆盖度是 100%。

修复：新增 `util/bus.js` 事件总线。
- 写入方：`syncFromSource` / `summarizeTree` / `propagateUp` 完成后 `emitHierarchyChange()`
- 消费方：组件 `useEffect(() => onHierarchyChange(refresh))`；浮层 `show()` 时亦广播
