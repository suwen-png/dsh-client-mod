⇒ **需求自始至终是「原生 tab」，从未变成「浮层」。**

### 4.2 选型层 —— 方案 A 被误判（评分前提已被证伪）

`docs/04 §二` 的方案 A（宿主 Tab 集成）被打 **35 分**、落选，理由原文：

> 「需插件与宿主共享同一 `slots` 服务实例，而该实例由 app-shell 通过 `ctx.slots.install` 注入，插件侧能否拿到同一实例**未经实测**（高风险）」

**该前提今日已被证实为误判**（见 §五）：
- 插件 `apply(ctx)` **本就收到 ctx**，只是被 `void ctx;` 丢弃；
- 官方契约明确 `inject: ['slots']` + `ctx.slots.register`；
- `window.__DSH_SLOTS__` **从来不存在** —— 当初探测的是**猜错的名字**。

**修正后的评分**（仅改「实现成本」一项，其余不动）：

| 方案 | 信息密度 | 导航效率 | 可扩展性 | 实现成本 | UI一致性 | 合计 |
|:--|:--:|:--:|:--:|:--:|:--:|:--:|
| A 原生 Tab 集成（修正后） | 8 | 7 → **9** | 6 | 4 → **8** | 10 | **41** |
| C 混合（原选定） | 9 | 9 | 9 | 7 | 8 | 40 |
| **A′ = A 外壳 + C 内容（本次提案）** | **9** | **9** | **9** | **8** | **10** | **⭐45** |

> 导航效率 A 由 7 升 9：一 tab 直达（原估含「slot 可能拿不到需兜底」的不确定性成本）。
> 实现成本 C 由 7 降（**订正**）：DOM 兜底通道需自建 launcher + 浮层 + 遮挡处理，实际并不比注册 tab 便宜。

### 4.3 实现层 —— slot 通道探测错了名字

| 环节 | 现状代码 | 问题 |
|:--|:--|:--|
| 通道探测 | `mount.js#tryRegisterHostSlot` 读 `window.__DSH_SLOTS__` | 该全局**不存在** ⇒ 恒返回 false |
| 兜底 | 返回 false 后走 `mountHierarchyOverlay`（DOM 浮层） | 兜底被当成默认路径 |
| ctx | `client-entry` 导出的 `apply(ctx){ void ctx; … }` | **拿到 ctx 却丢弃** |
| inject | `var inject = []` | **未声明 `slots` 依赖** |

## 五、技术可行性（完整证据链）

### 5.1 tab 环是纯 slot 驱动

`dsh-client-ui-conversation/lib/client.js:9172`（实测原文）：

```js
children: active !== void 0 && renderSlot("conversation.view", {
    inspect,
    onInspectDone: () => { actions.setInspect(null); }
}, { only: active.id })
```

⇒ **注册 entry 即被接管，无需触碰宿主一行代码。**

### 5.2 插件已能拿到 ctx（契约确认）

| 证据 | 内容 |
|:--|:--|
| 产物尾部 | `var apply = function apply(ctx) { void ctx; return __entry.installBatch1({}); };` |
| 官方错误模板 | `"service \"${prop}\" is not declared by your plugin. Declare it on the plugin you return: { inject: ['${prop}', …], apply(ctx) { … } }"` |
| 官方示例 | `return { inject: ['slots'], apply(ctx) { ctx.slots.inject('conversation', () => ctx.slots.register({ name: 'conversation' }, …)) } }` |
| 真实同类 | `dsh-client-ui-trajectory` 正是用 `ctx.slots.inject("conversation.view", …)` 注册「**轨迹**」tab |

### 5.3 同族对照（trajectory 注册原文）

```js
ctx.slots.inject("conversation.view", () => ctx.slots.register({
    name: "conversation.view",
    id: "trajectory",
    order: 10,
    locale: NS,
    label: () => t("view.trajectory"),
    inject: (sessionId) => { … }
}, TrajectoryView));
```

**对照本需求**：`id: "director"`、`order: -1`（排在「对话」之前）、`label: () => "总监"`。

### 5.4 可行性结论

| 项 | 结论 |
|:--|:--|
| tab 注册 | ✅ 官方支持，同族已有先例 |
| 会话隔离（H3） | ✅ entry 的 `inject(sessionId)` 即**按会话实例化** |
| 零宿主改动（H2） | ✅ 纯插件侧 |
| 官方模块依赖 | ✅ `dsh-client-ui-slots` / `dsh-client-web-react` 均在冻结表 |
| 风险等级 | 🟢 低（新增注册，不动既有渲染） |

## 七、交互设计

### 7.1 双向联动矩阵（对照 `18号文 E.9`）

| # | 触发（源） | 结果（目标） | 传输机制 | 状态 |
|:-:|:--|:--|:--|:--:|
| L1 | R5 消息动作「分派到分支」 | 分支会话收到任务 | `autoForward`（既有） | ✅ 复用 |
| L2 | 分支会话产出结论 | R5 出现结果卡 + 状态机推进 | 会话事件订阅 | 🆕 |
| L3 | R5「通过/打回」 | `memoryDocs(review)` + 分支状态更新 | 既有 | ✅ 复用 |
| L4 | R3 点智能体/技能 | 新建分支 + R5 状态卡 | `createBranch` | ✅ 复用 |
| L5 | R4 点文件 | R7 切文档模式展示 | 局部状态 | 🆕 |
| L6 | R5/R7 点击聚焦 | R8 路由指示 chip 同步 | `focusTarget` | ✅ 复用 |
| L7 | R5「标记决策」 | `memoryDecisions` → R6 决策 Tab | `idbSaveDecision` | ✅ 复用 |
| L8 | **对话 tab 发消息 → 总监** | 总监页出现同一条并归纳 | **共享 store** | 🆕 ★核心 |
| L9 | **总监页发消息 → 对话 tab** | 原对话出现该消息 | **共享 store** | 🆕 ★核心 |

> **L8/L9 是「双向联动」的实质**：两 tab **共用同一 `session`**，因此不是「转发」，而是**同一数据源的两种视图** —— 用户在任一侧发消息，另一侧立即可见。这比 IPC 式转发更稳、无丢失。

### 7.2 「互相传送消息」的两种语义（需你确认口径）

| 口径 | 语义 | 实现 | 建议 |
|:--|:--|:--|:--|
| **① 同源视图**（本方案默认） | 两个 tab 看的是**同一个会话**，消息天然共享 | 共享 store，零搬运 | ✅ 推荐 |
| ② 跨会话投递 | 总监页是**独立会话**，消息需「发送过去」 | 需显式搬运 + 状态卡 | 备选 |

**本设计按 ① 出图**；若你要 ②（总监是独立会话），告知后我改 §7.1 的 L8/L9 与 §6.2 的 R5 数据来源。

### 7.3 时序（L8 为例）

```
用户(对话tab) 输入 ──▶ session.append(userMsg)
                            │
                            ├──▶ 对话tab 渲染（原生）
                            └──▶ 总监tab 订阅同一 store（R5 即时出现该消息）
                                        │
                                        └──▶ 总监归纳 → 生成/更新 R2 总览 与 R3 建议资源
```

// lib/client.js 尾部（构建产物契约）
const inject = ["slots"];                       // ← 声明依赖（当前为空数组）
function apply(ctx) {

## 十、风险与回滚

| 风险 | 概率 | 影响 | 应对 |
|:--|:--:|:--:|:--|
| slot 注册被宿主校验拒绝 | 低 | 高 | 先做**最小注册验证**（只注册一个空 tab）再展开 |
| 「总监」文案与原生 tab 尺寸不匹配 | 中 | 低 | 文案 2 字与「对话/轨迹」等宽（26px），风险极低 |
| 宿主内联总监代码（44 行残留）与新 tab 冲突 | 低 | 中 | 实测其**已不渲染**；不删（需授权），仅记录 |
| 8 层验证回归 | 低 | 中 | 每次改动全量重跑 536 项 |

**回滚**：`plugin-install.mjs --apply` 的逆 —— 移除 entry 注册即可回到浮层形态；**无需触碰宿主**，故**不属 §3.2 情形②**。
