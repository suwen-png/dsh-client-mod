## 二、技术架构（已确认）

### 2.1 Harness 桌面端架构
- **类型**：Electron 桌面应用
- **主进程**：`resources/app.asar`（8.8MB，不包含UI包）
- **UI运行时**：`resources/host/node_modules/@deepseek-ai/`
- **UI加载方式**：通过本地HTTP服务（`http://127.0.0.1:<port>/plugins/...`）加载
- **插件路由**：`dsh-client-modules` 包处理 `/plugins/` 路由
- **文件映射**：URL `/plugins/@deepseek-ai/<pkg>/client.js` → `package.json` 的 `exports["./client"]` → `lib/client.js`

## 四、未解决问题

### 4.1 b-2 标准对话滚动问题
- **现象**：消息列表无法上下滚动，发送消息后不自动滚到底部
- **已尝试方案**：
  1. 修改RWZidW_root的min-height和flex
  2. 修改RWZidW_scrollBody的flex
  3. 全局CSS注入（多种方式）
  4. CSS加载时机调整（IIFE + DOMContentLoaded + setTimeout）
- **根因分析**：
  - 原客户端滚动容器是`RWZidW_scrollBody`（带`data-conversation-scroll`属性）
  - 原客户端使用`toBottom()`函数和`useLayoutEffect`实现滚动
  - 浏览器环境中`slotError: "conversation.session"`，消息列表未渲染（可能是浏览器环境限制）
  - 桌面端实际状态需用户确认

### 4.2 a-1 总监对话上下伸缩面板
- **现象**：鼠标悬停展开/移开收回的面板未完全实现

## 七、转向web端开发的决策

### 7.1 决策原因
1. 当前客户端是二次开发封装，修改编译产物风险高
2. 反复修改b-2滚动问题未解决，说明编译产物修改有局限性
3. web端有完整的开发工具链（HMR、浏览器调试）
4. dsh web版本支持插件系统，可通过插件扩展功能

### 7.2 web端开发计划
1. 安装并启动 `npx @deepseek-ai/dsh web`
2. 安装 dsh-worktable 插件（GitHub: Aisland-SJL/dsh-worktable）
3. 在web端实现总监对话模式等功能
4. 逐步迁移dsh-client-mod的功能到web端插件
