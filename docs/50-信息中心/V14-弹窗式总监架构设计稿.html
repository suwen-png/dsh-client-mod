04层级联动（要求 07 · 09）

总监页外壳唯一，内容随层级切换。四段层级同构——项目级与文件夹级总监与对话级同一套结构与界面。

全局级 · gl_0
跨项目总览与调度。可访问全部下级数据。路由的最终兜底。
项目级 · prj_*
项目定位 / 目标 / 阶段 / 继承给下级，可覆盖。
文件夹级 · ws_*
工作区汇总。点击左侧文件夹即弹出本级总监。
对话级 · se_*
只管一段对话。看不到上级全局（单向可见）。
可见性方向：上级 → 下级 可读；下级 → 上级 不可见。 依据 17号文 §2.3「隔离 / 共享 / 继承」三条。

05单总监页 ＋ 智能路由（要求 08）

总监页只有一个。用户不先选对话，直接向总监说；总监整理确认后决定去向，且路由结果可确认、可回看。

06双向联动（要求 05 的"完全一致"如何保证）

① 总监 → 对话
总监区输入 → 总监整理 / 确认 → 派活或直转
→ 走原生 send 路径写入对话域
→ ChatFlow（右栏）与 ChatView（对话 tab）同时经 useSession 看到新消息
② 对话 → 总监
右栏 / 对话 tab 产生产出
→ 总监侧订阅该 session 的产出变化
→ 触发六维审核 → 通过则归档，不通过则带审核意见打回重执行
"完全一致"是结构保证，不是同步努力：右栏不持有副本，与主区域订阅同一 store、 走同一渲染器（renderSlot("conversation.chat.node")）。 依据 06号文 §0 选型：不从 ChatView 提取消息流（耦合深、风险高），改用轻量组件订阅同一数据。

为何会丢（五级根因 · 摘要）

① 入口被主动注销
批 C-2 移除 director tab 注册 ⇒ 宿主 MOD-A 布局分支判据永假，28 处代码活着、入口没了（不可达代码）。
② 迁移拆成两个世界
状态（layout store）与组件（DirectorFlow）迁入插件，渲染位置留在宿主，中间的桥没人修 ⇒ 迁入物零调用。
③ 契约反向固化"共用"
设计要"独立库 + 六 store"，落地成"共享库 + 三 store"，《锚点契约》再把这层共享冻结为不可动。
④ 需求真相源缺失
11 条散在 7 份文档，无一份声明自己是业务真相源；新文档只讲"怎么改"，于是需求被最新文档自动覆盖。
⑤ 版本控制面只有 6.8%
磁盘 3593 文件 / git 纳管 245。workspace/（宿主全部改造）与 snapshots/（唯一回滚点）均 0 纳管。
防复发（已立规）
业务不变量单点登记 · 改动前置核对 · 入口类改动需登记影响面 · 迁移三件套完整性检查 · 契约不得反向覆盖设计。
