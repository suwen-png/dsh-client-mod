📐 代码架构说明（AI 修改指南）
B 区数据分为三层：
① 文档层（docs/ 下的 markdown）— 总监负责维护，是数据源
② 状态层（overview state）— 从文档加载到 React state，驱动 UI
③ 统计层（computeStats()）— 自动计算进度/风险数/待办数/资产数

新增卡片步骤：
1. 在 overview state 加字段
2. 在 loadOverviewFromDocs() 加文档解析
3. 在 B 区 JSX 加 ov-card
4. 如需统计，在 computeStats() 加逻辑
核心变更：不再前端写死目标/风险/待办数字。所有数据由总监文档（project_overview.md / risks.md / tasks.json）维护，UI 只读展示+自动统计。编辑功能通过"编辑"按钮打开文档编辑器，修改后自动重新统计。

D 区整体结构：左侧导航 + 右侧内容（工具栏 + 列表）

• 智能体（5个）

点击切换右侧内容，带数量徽标
右侧内容区
• 工具栏：搜索框 + 筛选下拉 + 启用状态筛选 + 新建按钮
• 列表：每项含图标/名称/描述 + 查看/编辑/调用 三按钮
• 查看：弹出详情面板，显示完整 system prompt / 技能描述 / 逻辑规则
• 编辑：弹出编辑器，修改 system prompt / 技能逻辑 / 执行规则，持久化保存
导航项列表项结构点击"调用"行为数据存储改动
🤖 智能体 图标 + 名称 + 描述（system prompt 摘要）+ 查看/编辑/调用 创建新分支（新对话），将智能体的 system prompt 作为分支上下文，用户在新分支中与该智能体对话 agents.json（可扩展） 重构
⚡ 技能 图标 + 名称 + 触发词（如 /code）+ 描述 + 查看/编辑/调用 在当前对话中注入技能 prompt，相当于输入 /技能名，总监按技能逻辑处理当前消息 skills.json（可扩展） 新增内容
📋 执行逻辑 图标 + 名称 + 规则摘要 + 启用开关 + 查看/编辑/强制执行 强制 AI 按该逻辑执行，如"文件生成标准"则所有文件生成必须遵循命名/格式/注释规范；"回复标准"则所有回复必须遵循格式 state.config.duties + 规则文档 增强
技能内容修复：当前技能栏显示"2个已禁用"且技能内容为空。V10 中每个技能都有完整的：名称、触发词（/code、/doc 等）、system prompt、描述、启用状态。点击"查看"可看到完整 prompt，点击"编辑"可修改。

智能体 vs 技能 vs 执行逻辑 的区别：
• 智能体 = 角色（创建新分支，以该角色身份持续对话）
• 技能 = 工具（在当前对话中一次性注入特定处理逻辑，类似 / 命令）
• 执行逻辑 = 规则（全局强制约束 AI 的行为标准，如回复格式、文件规范）
