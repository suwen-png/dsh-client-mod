总监页外壳唯一，内容随层级切换。四段层级同构——项目级与文件夹级总监与对话级同一套结构与界面。 V14.1 新增：mhead 层级选择器（面包屑 + 下拉），不必回侧栏重点一次。

全局级 · gl_0

项目级 · prj_*

文件夹级 · ws_*

对话级 · se_*

06双向联动（要求 05 的"完全一致"如何保证 · 修订 §二 I2）

V14.0 用"覆盖整个 content 区"表达弹窗，导致右栏占据的位置就是对话 tab 的内容区 ⇒ "对话原貌"被遮住，却又要求它"原貌不变"，两条需求在同一块屏幕上冲突。 V14.1 用布局分屏做结构性解决。

通道机制为什么"完全一致"是恒真
① 总监 → 对话 总监区输入 → 总监整理 / 确认（确认卡）→ 转派或直转 → 走原生 send 路径写入对话域 右侧就是原生对话区，写入即显示，零同步代码、零延迟
② 对话 → 总监 原生对话区产生产出 → 总监侧订阅该 session 的产出变化 → 触发六维审核 → 通过归档 / 不通过带意见打回 总监只读订阅，不复制消息流 ⇒ 不存在"副本过期"这一失败模式

方案 C 的边界（必须显式声明，防止"悄悄改宿主"）

允许禁止
注入 <style id="dsh-director-split-style">（只写 padding 与装饰边框） 增删改任何节点
弹窗开启时生效、最小化 / 关闭时整段移除 改原生事件监听、改原生数据、改原生 store
给原生根节点加 data-dsh-director-split 属性（供样式选择器） 直接改原生节点的 style 属性（避免覆盖宿主内联样式）
判据（已真机执行）：弹出前后对宿主做全量 DOM 快照 diff，差异必须只有 <style> 标签与 data-* 属性。 V14.1 对应断言：「原生根 style 属性逐字节零改动」（真机 D1 已通过）。
