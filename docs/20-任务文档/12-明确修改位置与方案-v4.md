## 1. 问题与明确修改位置

### P1：总监页面给对话发消息没有反应

**根因分析**：
- InputBar 发送逻辑已添加总监模式判断，但可能 `window.__directorCurrentView` 或 `window.__directorLayoutStore` 未正确设置
- 调试标签已存在（gView/focus/direct/directCall），但用户未反馈具体值

**明确修改位置**：
- 文件：`lib/client.js`
- 位置1：InputBar 键盘回车逻辑（约行3542-3565）
- 位置2：InputBar 发送按钮逻辑（约行3717-3737）
- 位置3：DirectorView 挂载 useEffect（约行7372-7379）

**修改方式**：
1. 在 DirectorView 挂载时，确保 `window.__directorCurrentView = "director"` 和 `directorLayoutStore.setFocusTarget("director")` 被正确执行
2. 在 InputBar 发送逻辑中，添加 `window.__lastSendTarget` 全局变量，记录最近一次发送的目标（director/chat/standard），便于调试
3. 在总监tab标题栏添加 `lastSend` 标签，显示 `window.__lastSendTarget` 的值

**验证方法**：
- 点击对话小窗后，查看 `focus` 标签是否变为 "chat"
- 发送消息后，查看 `directCall` 标签是否 +1
- 查看 `lastSend` 标签显示的发送目标

### P2：消息在对话框的下面（被输入框遮挡）

**根因分析**：
- DirectorView 最外层用 `height:100%`，而标准对话 ChatView 用 `flex:1`
- `height:100%` 在父容器无明确高度时可能不生效，导致 DirectorView 高度超出可视区域
- 消息容器底部被输入框遮挡

**明确修改位置**：
- 文件：`lib/client.js`
- 位置：DirectorView 最外层 div（约行7427-7429）

**修改方式**：
```javascript
// 修改前
style: { display: "flex", flexDirection: "column", height: "100%", overflow: "hidden", position: "relative" }

// 修改后（与 ChatView 一致）
style: { display: "flex", flexDirection: "column", flex: 1, minHeight: 0, overflow: "hidden" }
```

**依据**：
- ChatView 最外层（行5960-5961）：`className: ChatView_module_css_default.root, style: { flex: 1, display: "flex", flexDirection: "column" }`
- `flex:1` 在 flex 布局中比 `height:100%` 更可靠
- `minHeight:0` 防止 flex 子项溢出

**验证方法**：
- 总监tab新发消息是否在输入框上方可见
- 消息容器底部与输入框之间是否有间距

### P3：总监消息未保留（持久化失效）

**根因分析**：
- 自定义 localStorage 可能在 Harness 插件环境中不可用或域隔离
- `saveDirectorStore`/`loadDirectorStore` 有错误日志但用户无法查看（F12不可用）
- 需要在页面上显示持久化状态

**明确修改位置**：
- 文件：`lib/client.js`
- 位置1：`loadDirectorStore` 函数（约行5414-5423）
- 位置2：`saveDirectorStore` 函数（约行5424-5430）
- 位置3：DirectorView 空状态显示（约行7472-7473）

**修改方式**：
1. 添加 `window.__directorPersistState` 全局变量，记录持久化状态：
   ```javascript
   window.__directorPersistState = {
       saveCount: 0,
       loadCount: 0,
       lastSaveTime: null,
       lastLoadTime: null,
       lastError: null,
       savedMessages: 0
   };
   ```
2. `saveDirectorStore` 成功时更新 `window.__directorPersistState`
3. `loadDirectorStore` 成功时更新 `window.__directorPersistState`
4. 总监tab标题栏添加 `persist` 标签，显示 `saveCount/loadCount` 和最后保存时间
5. 空状态显示"已加载N条历史消息"或"无历史消息（加载失败）"

**验证方法**：
- 发送总监消息后，查看 `persist` 标签的 `saveCount` 是否 +1
- 重启 Harness 后，查看 `persist` 标签的 `loadCount` 是否 >0
- 重启后总监消息是否保留

## 2. 标准对话原逻辑参考

### 发送逻辑
- `conversation.composer.bar` slot 的 inject 函数（行10450）接收 `sessionId`
- 获取 `shell = inputHub.shell(sessionId)`
- `keyboard: shell` 传给 InputBar
- 标准发送：`shell.submit(mode)` → `SessionInputShell.submit(mode)` → dispatch `{type:"enter", mode}`
- mode 有效值：`"queue"` / `"enter"` / `"accelerated"`

### 布局逻辑
- ChatView 三层结构（行5960-5968）：
  - `div.root`（`flex:1, display:flex, flexDirection:column`）
  - `div.scroll`（listRef，`ChatView_module_css_default.scroll`）
  - `div.column`（columnRef，`ChatView_module_css_default.column`）
- 输入框在 `conversation.composer.bar` slot，与 ChatView 并列

### 持久化逻辑
- chatStore 使用 `defineStore({ persist: "dsh.conversation.chat" })`（行31）
- 会话数据由 Harness 核心管理，存储在 `C:\Users\15142\.dsh\sessions\`
