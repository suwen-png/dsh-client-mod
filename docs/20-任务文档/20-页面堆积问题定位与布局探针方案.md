## 二、找原因

| # | 原因 | 置信度 | 依据 |
|---|------|:----:|------|
| C1 | **DirectorView 根容器无背景色**，conversation hero（blank composer 态的「探索未至之境」）在同一区域渲染，直接透出 | 高 | 根容器 style 无 background（8910行区）；hero 属 ConversationRoot 正常渲染 |
| C2 | **文档类面板浮层化**：总监文档面板/文档查看器未正确 dock 进 flex 布局（可能高度链断裂或 z-index/定位异常），呈浮动卡片 | 中 | 代码中面板均为 flex dock 设计，无 absolute——需探针数据确认是 height:100% 链断还是其他 |
| C3 | **多实例共存**：对话 tab 的总监小窗（b-1）与总监 tab 的 a-1 可能同时渲染，面板互相压盖 | 中 | b-1 面板（7131行区）与 a-1 均含总监文档/记忆面板，截图无法区分归属 |
| C4 | **版本标识缺失**：批次1删 badge 是正确的（太丑），但没有替代版本戳 | 高 | 既定事实 |

**关键限制**：C2/C3 靠读代码无法定论——页面真实渲染态（谁浮着、谁的 rect 是多少、z-index 多少）必须拿到运行时数据。这正是用户核心诉求：**AI 需要能"看到"页面**。

## 三、如何处理

### S1 布局探针（核心交付，本批实施）

新增 `window.__dshLayoutProbe`，让用户一条命令把页面真实布局发给我：

| 接口 | 作用 |
|------|------|
| `__dshLayoutProbe()` | 采集布局快照 → console 输出 + 返回 JSON 对象 |
| `__dshLayoutProbe.text()` | 输出紧凑文本树（直接粘贴在对话里发给我） |
| `__dshLayoutProbe.export()` | 导出 JSON 文件（dsh-layout-<时间戳>.json） |

**采集内容**：
- 版本戳（build/索引时间戳）、视口尺寸、时间
- DirectorView DOM 树遍历（≤400节点）：tag/class/文本摘要/getBoundingClientRect/position/z-index/背景色/display/visibility/overflow
- **自动重叠检测**：两两比对节点 rect，报告「重叠面积>小者30% 且 含非static定位或非auto z-index」的重叠对——直接定位"堆积"元凶

### S2 版本水印（本批实施）

R1 右侧增加小字版本戳：取 `DSH_DOCS_INDEX.generatedAt`（apply 时自动更新）→ 截图即可确认代码版本，无需 badge。

### S3 hero 遮挡修复（本批实施）

DirectorView 根容器加 `background: var(--dsh-bg0, #ffffff)` + `zIndex: 1`，形成独立层叠上下文，盖住 hero。

### S4 浮层面板修复（下批，依赖探针数据）

拿到 `__dshLayoutProbe` 快照后，根据 rect/z-index/position 实据定位 C2/C3 根因，再修。禁止凭猜修改。
