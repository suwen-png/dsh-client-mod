## 2. 标准对话原逻辑分析

### 2.1 发送逻辑（标准对话）

**调用链**：
```
用户输入 → InputBar
  → 键盘回车: keyboard.submit(mode)
    → SessionInputShell.submit(mode)  [行1438-1451]
      → shell.commitSend(imageIds)     [行1441] ★关键
      → conversation.sendSession(session, text, imageIds, mode)  [行1442]
        → session.prompt(content, mode)  [行137]
  → 发送按钮: inputActions.submit()
    → 同上
```

**关键步骤 `shell.commitSend(imageIds)`** [行1441]：
- 清空输入框 draft
- 提交附件状态
- 触发UI更新（输入框清空、消息队列更新）
- **总监实现缺少此步骤，可能导致UI不更新、输入框不清空**

**`sendSession` 定义** [行130-140]：
```javascript
async sendSession(session, text, imageIds, mode) {
    const attachments = this.draftImages(imageIds);
    const content = [...await this.serializeImages(...), ...text === "" ? [] : [{type:"text", text}]];
    const result = await session.prompt(content, mode);  // mode 直接传给 prompt
    if (!result.ok) throw new Error(...);
    this.releaseDraftImages(attachments);
}
```

**mode 有效值**：从 `resolveSubmitMode` 返回 `"queue"` / `"enter"` / `"accelerated"`。`"chat"` 无效。

### 2.2 布局逻辑（标准对话）

**三层结构** [行5951-5960]：
```
div.root [行5952]
  style: flex:1, display:flex, flexDirection:column
  └─ div.scroll (listRef) [行5955]
       className: ChatView_module_css_default.scroll
       └─ div.column (columnRef) [行5958]
            className: ChatView_module_css_default.column
            data-chat-flow: ""
            └─ 消息列表 (order.map → ChatNodeSeat)
```

**CSS class 作用**（推断）：
- `.scroll`: `overflow-y: auto`，滚动容器
- `.column`: `display: flex; flex-direction: column; min-height: 100%;`，消息列，可能包含 `justify-content: flex-end` 或等效机制

**自动滚动**：标准对话使用 `followRef` + `ResizeObserver` [行5750-5758]，监听 column 尺寸变化自动滚动。

**总监实现差异**：
- 只有一层 div，直接设置 `overflowY: "auto"` + `justifyContent: "flex-end"`
- 缺少中间的 column 层，导致 `flex-end` 与 `overflow` 叠加时行为异常
- 消息容器底部没有足够的 padding，新消息可能被输入框遮挡

### 2.3 持久化逻辑（标准对话）

**chatStore** [行23-41]：
```javascript
function createChatStore() {
    return defineStore({
        init: () => ({ selection:null, draft:"", view:null, inspect:null }),
        persist: "dsh.conversation.chat",  // ★ 使用 defineStore 的 persist 机制
        actions: { select, setDraft, setView, ... }
    });
}
```

**`defineStore` 的 persist 机制**：
- 由 `@deepseek-ai/dsh-client-runtime-client` 提供
- 自动处理存储（可能是 localStorage 或 IndexedDB）
- 自动处理序列化/反序列化
- 与 Harness 插件环境兼容

**会话数据持久化**：
- 会话消息（chat.order / chat.nodes）由 session 系统管理，不通过 chatStore
- session 数据可能存储在 `C:\Users\15142\.dsh\sessions\` 目录
- 这是 Harness 核心的持久化机制，与插件的 localStorage 不同

**总监实现差异**：
- 使用自定义 `loadDirectorStore`/`saveDirectorStore`，直接操作 `localStorage`
- localStorage key = `dsh.director.store.${sessionId}`
- **可能问题**：
  1. Harness 插件环境的 localStorage 可能域隔离，与主应用不同
  2. 插件卸载/更新时 localStorage 可能被清除
  3. sessionId 可能包含特殊字符，导致 key 不合法
  4. `saveDirectorStore` 中的 `JSON.stringify` 可能因循环引用失败

## 3. 差异对比表

| 维度 | 标准对话 | 总监实现 | 差异影响 |
|------|---------|---------|---------|
| 发送 | shell.commitSend + sendSession | 直接 sendSession | UI不更新、输入框不清空 |
| mode | queue/enter/accelerated | chat（已修复为queue） | 之前静默失败 |
| 布局 | 三层(root→scroll→column) | 一层(scroll+flex-end) | 消息被遮挡、滚动异常 |
| 自动滚动 | followRef + ResizeObserver | useLayoutEffect + 双重RAF | 可能时序不对 |
| 持久化 | defineStore persist | 自定义 localStorage | 可能域隔离、不兼容 |
| session获取 | this.shells.get(sessionId) | sessions.list.getSnapshot().byId[sessionId] | 可能获取到不同的session对象 |

## 4. 修复方案

### 4.1 P1 修复：发送逻辑对齐标准对话

**问题根因**：
1. 缺少 `shell.commitSend()`，导致UI不更新
2. `conv` 或 `sess` 可能为 undefined
3. 错误被 catch 吞掉，用户无感知

**修复方案**：

**方案A（推荐）：通过 InputBar 的标准路径发送**
- 不直接调用 `conv.sendSession`
- 而是模拟标准对话的发送流程：设置 draft → 调用 `keyboard.submit()` 或 `inputActions.submit()`
- 但这需要访问 InputBar 的内部状态，复杂度高

**方案B（可行）：补全 commitSend + 错误提示**
- 在 `__directChatSubmit` 和 `onForward` 中：
  1. 获取 `shell` 对象：`const shell = sessions.list.getSnapshot().byId[sessionId]?.shell` 或通过 `conversation.shells.get(sessionId)`
  2. 调用 `shell?.commitSend([])` 清空输入框
  3. 调用 `conv.sendSession(sess, draft, [], "queue")`
  4. 失败时在总监流中添加系统消息提示

**方案C（最简）：使用 session.prompt 直接发送**
- `sess.prompt([{type:"text", text: draft}], "queue")`
- 绕过 conversation.sendSession，直接调用 session.prompt
- 但可能缺少附件处理和错误处理

**优先方案**：方案B，补全 commitSend + 错误提示

**修改位置**：
- `__directChatSubmit`（行~10413）
- `__directorSubmit` 的 onForward 回调（行~10404）
- `sendToChat`（行~10577）

**修改内容**：
```javascript
// 修改前
window.__directChatSubmit = function(sessionId, draft) {
    try {
        const conv = concreteConversation(ctx);
        const sess = sessions.list.getSnapshot().byId[sessionId];
        if (sess) conv.sendSession(sess, draft, [], "queue").catch(...);
    } catch (e) {}
};

// 修改后
window.__directChatSubmit = function(sessionId, draft) {
    try {
        const conv = concreteConversation(ctx);
        const sess = sessions.list.getSnapshot().byId[sessionId];
        if (!sess) {
            console.error("[directChatSubmit] session not found:", sessionId);
            return;
        }
        // 补全 commitSend，清空输入框
        const shell = conv.shells?.get?.(sessionId);
        if (shell) shell.commitSend([]);
        // 发送消息
        conv.sendSession(sess, draft, [], "queue").catch((err) => {
            console.error("[directChatSubmit] send failed:", err);
        });
    } catch (e) {
        console.error("[directChatSubmit] error:", e);
    }
};
```

### 4.2 P2 修复：布局对齐标准对话（三层结构）

**问题根因**：
- 总监只有一层容器，`flex-end` + `overflow` 叠加导致消息被遮挡
- 缺少底部 padding，新消息在输入框下方

**修复方案**：改为三层结构，对齐标准对话

```
div.director-root
  style: flex:1, display:flex, flexDirection:column
  └─ div.director-scroll (messagesEndRef)
       style: flex:1, overflowY:auto, display:flex, flexDirection:column
       └─ div.director-column
            style: flex:1, display:flex, flexDirection:column, justifyContent:flex-end, gap:12, padding:16px, paddingBottom:24px
            └─ 消息列表
```

**关键点**：
1. scroll 层：`flex:1, overflowY:auto`，不设置 justify-content
2. column 层：`flex:1, display:flex, flexDirection:column, justifyContent:flex-end`，消息从底部排列
3. column 层底部 padding：`paddingBottom: 24px`，确保最后一条消息不被输入框遮挡
4. 自动滚动：滚动 scroll 层，不是 column 层

**修改位置**：
- DirectorView 消息容器（行~7455）
- DirectorFlow 消息容器（行~5670）
- ChatFlow 消息容器（行~7311）

### 4.3 P3 修复：持久化改用 defineStore 机制

**问题根因**：
- 自定义 localStorage 可能与 Harness 插件环境不兼容
- 域隔离、清除策略不明

**修复方案**：

**方案A（推荐）：使用 defineStore 的 persist 机制**
- 创建总监 store 时使用 `defineStore({ persist: "dsh.director.store", ... })`
- 与 chatStore 一致，确保环境兼容
- 但需要按 sessionId 隔离数据（一个 store 存所有会话的总监消息）

**方案B（可行）：改用 Harness 的 storage API**
- Harness 可能提供 `storage` API（如 `localStorage` 的封装）
- 需要研究 `@deepseek-ai/dsh-client-runtime-client` 的 storage API

**方案C（最简）：修复自定义 localStorage 的问题**
- 确保 sessionId 合法（替换特殊字符）
- 添加错误日志，定位保存/加载失败原因
- 在总监流中显示持久化状态（已保存N条/加载失败）

**优先方案**：方案C（最简，先验证问题根因），如不生效再改用方案A

**修改内容**：
1. `saveDirectorStore`：添加 try-catch 错误日志
2. `loadDirectorStore`：添加 try-catch 错误日志
3. sessionId 处理：`sessionId.toString().replace(/[^a-zA-Z0-9]/g, "_")`
4. 总监流空状态显示："本地存储：已加载N条 / 加载失败"
