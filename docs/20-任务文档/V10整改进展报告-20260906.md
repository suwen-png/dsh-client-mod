## 三、关键经验教训（已沉淀）

### 1. Harness插件开发关键注意事项

| 问题 | 教训 |
|------|------|
| credentials.yaml字段类型 | `version`和`refs`必须是字符串类型，不能是数字或对象 |
| 插件inject配置 | 只能inject web profile存在的服务（webServer），不能inject不存在的服务（sessions） |
| 插件环境恢复 | 损坏的snapshots会导致Harness无法启动，需删除`plugin-center/snapshots`和`journal` |
| 部署方式 | 用Python脚本不用PowerShell，避免编码和语法问题 |

### 2. GUI测试最佳实践

| 问题 | 教训 |
|------|------|
| 鼠标坐标测试不可靠 | DPI缩放125%导致坐标偏移，6轮测试失败 |
| Playwright CDP是最优方案 | Electron应用用`--remote-debugging-port=9222`启动，Playwright通过CDP连接，用CSS选择器精准定位 |
| force点击绕过overlay | Harness原生overlay层会拦截点击，用`click({force: true})`绕过 |
| 测试脚本要健壮 | 检查元素存在性而不是假设状态，避免因页面状态变化导致测试失败 |

### 3. 时间监控机制缺失

- **问题**：GUI测试鼠标坐标失败6轮才换方案，浪费大量时间
- **改进**：需要在execution-unified-standards中添加"同一方案3次失败强制换方案"的执行机制
- **改进**：需要添加"任务超过预计时间2倍触发预警"的时间监控机制
