## 二、阶段1：修复总监消息发送逻辑（M1）

### 2.1 问题分析

**现象**：总监tab中 `view:director` 显示正确，但发送消息没有走总监处理流程，直接发给了原对话系统。

**根因**：之前采用 `Object.defineProperty(shell, "submit", ...)` 覆盖 shell 对象的 submit 方法，但 shell 对象可能是冻结对象（Object.freeze），或 submit 是只读 getter 属性，导致 defineProperty 静默失败（被 try-catch 吞掉），InputBar 仍调用原始 submit。

**解决方案**：不修改 shell 对象，直接修改 **InputBar 组件**，在调用 `keyboard.submit()` 之前添加当前 tab 判断。这种方式不依赖于对象属性可写性，更可靠。

### 2.2 改动点

#### 改动1：conversation.composer.bar 的 inject 函数添加 currentView

**位置**：原 `inject: (sessionId) => { ... return { keyboard: shell, ... } }`

**修改**：在返回对象中添加 `currentView` 属性

```javascript
inject: (sessionId) => {
    // ... 原有逻辑 ...
    let currentView = "chat";
    try {
        const st = chatStore.getState();
        if (st && st.view) currentView = st.view;
    } catch (e) {}
    return {
        currentView,
        keyboard: shell,
        // ... 原有其他属性 ...
    };
}
```

**注意**：chatStore 在 apply() 函数作用域内，inject 函数也在 apply() 内，可以直接访问。

#### 改动2：InputBar 组件解构 currentView props

**位置**：InputBar 函数签名（约行3367）

**修改**：在 props 解构中添加 `currentView`

```javascript
function InputBar({ sessionId, useSession, useInput, inputActions, keyboard, currentView, ... }) {
```

#### 改动3：InputBar 组件 submit 前添加判断

**位置**：InputBar 中调用 `keyboard.submit(...)` 的地方（约行3542）

**原代码**：
```javascript
keyboard.submit(resolveSubmitMode(running, accelerated ? "accelerated" : "enter", subagent === null));
```

**修改为**：
```javascript
if (currentView === "director") {
    // 总监模式：走总监处理流程
    const draft = keyboard.snapshot.draft;
    if (!draft.trim()) return;
    // 调用总监处理（需要从props传入或全局访问）
    if (typeof window !== "undefined" && window.__directorSubmit) {
        window.__directorSubmit(sessionId, draft);
    } else {
        // fallback：正常发送
        keyboard.submit(resolveSubmitMode(running, accelerated ? "accelerated" : "enter", subagent === null));
    }
    keyboard.setDraft("");
    return;
}
keyboard.submit(resolveSubmitMode(running, accelerated ? "accelerated" : "enter", subagent === null));
```

**问题**：InputBar 组件无法直接访问 directorProcessMock 和 directorStoreFactory（它们在模块作用域内，但 InputBar 可能在不同的作用域）。

**解决方案**：在 apply() 函数中，把总监处理函数挂载到 window 上，InputBar 通过 window.__directorSubmit 调用。

```javascript
// 在 apply() 函数中，inject 函数之前
window.__directorSubmit = function(sessionId, draft) {
    const dStore = directorStoreFactory(sessionId);
    directorProcessMock(sessionId, draft, dStore, t, (instruction) => {
        try {
            const conv = concreteConversation(ctx);
            const sess = sessions.list.getSnapshot().byId[sessionId];
            if (sess) conv.sendSession(sess, instruction, [], "chat").catch(() => {});
        } catch (e) {}
    });
};
```

**注意**：directorProcessMock、directorStoreFactory、concreteConversation、ctx、sessions、t 都在 apply() 函数作用域内，可以直接访问。

## 三、阶段2：Tab记忆功能（M2）

### 3.1 需求

用户点击对话进入时，默认显示上次离开时的tab。比如上次点的是总监，下次进入还是总监。

### 3.2 现状分析

chatStore 已有 `persist: "dsh.conversation.chat"` 配置，理论上 view 字段会持久化到 localStorage。但初始值是 `null`，如果持久化存储中没有 view，就会是 null，默认显示对话tab（通过 resolveActiveView  fallback 到 DEFAULT_VIEW_ID = "chat"）。

### 3.3 改动点

#### 验证步骤

1. 打开Harness，切到总监tab
2. 完全退出Harness
3. 重新打开Harness，进入同一会话
4. 检查是否默认显示总监tab

#### 如不生效的修复方案

在 createChatStore 的 init 函数中，从 localStorage 读取持久化的 view 值：

```javascript
init: () => {
    let persistedView = null;
    try {
        const raw = localStorage.getItem("dsh.conversation.chat");
        if (raw) {
            const parsed = JSON.parse(raw);
            if (parsed && parsed.state && parsed.state.view) {
                persistedView = parsed.state.view;
            }
        }
    } catch (e) {}
    return {
        selection: null,
        draft: "",
        view: persistedView,
        inspect: null
    };
}
```

**注意**：defineStore 的 persist 机制可能已经处理了初始化，不需要手动读取。需要先验证再决定是否修改。

### 4.2 M3：小窗宽度状态store

**位置**：在 directorStores Map 之后新增

```javascript
const directorLayoutStores = new Map();
function createDirectorLayoutStore() {
    let state = {
        directorPanelWidth: 300,
        chatPanelWidth: 300,
        directorPanelCollapsed: false,
        chatPanelCollapsed: false,
        focusTarget: "director"
    };
    // 从localStorage恢复
    try {
        const raw = localStorage.getItem("dsh.director.layout");
        if (raw) state = { ...state, ...JSON.parse(raw) };
    } catch (e) {}
    const listeners = new Set();
    function notify() {
        try { localStorage.setItem("dsh.director.layout", JSON.stringify(state)); } catch (e) {}
        listeners.forEach(fn => fn());
    }
    return {
        getState: () => state,
        subscribe: (fn) => { listeners.add(fn); return () => listeners.delete(fn); },
        setDirectorWidth: (w) => { state = { ...state, directorPanelWidth: w }; notify(); },
        setChatWidth: (w) => { state = { ...state, chatPanelWidth: w }; notify(); },
        toggleDirectorCollapsed: () => { state = { ...state, directorPanelCollapsed: !state.directorPanelCollapsed }; notify(); },
        toggleChatCollapsed: () => { state = { ...state, chatPanelCollapsed: !state.chatPanelCollapsed }; notify(); },
        setFocusTarget: (target) => { state = { ...state, focusTarget: target }; notify(); }
    };
}
const directorLayoutStore = createDirectorLayoutStore();
function useDirectorLayoutStore() {
    const subscribe = (0, react.useCallback)((fn) => directorLayoutStore.subscribe(fn), []);
    return (0, react.useSyncExternalStore)(subscribe, directorLayoutStore.getState, directorLayoutStore.getState);
}
```

**关键问题**：对话小窗中需要显示原对话流。原对话流是通过 `conversation.view` slot 的 chat tab 渲染的（ChatView组件）。在总监tab中嵌入对话流需要复用ChatView组件。

**解决方案**：在总监tab的DirectorView中，通过 `renderSlot("conversation.view", { only: "chat" })` 渲染对话tab的内容，但只渲染消息流部分，不渲染输入框。

但这可能比较复杂，因为ChatView组件包含完整的对话流+输入框。需要拆分ChatView或找到只渲染消息流的方式。

**简化方案（阶段1）**：对话小窗先显示一个占位区域，提示"对话流将在此显示"，后续阶段再实现真实对话流嵌入。
