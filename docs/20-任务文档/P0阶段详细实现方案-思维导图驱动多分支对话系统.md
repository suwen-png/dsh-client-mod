## 二、数据模型设计（功能1）

### 2.1 存储位置

所有数据存储在 `localStorage`，key前缀 `dsh.director.`：

| 数据 | localStorage key | 说明 |
|------|-----------------|------|
| 思维导图节点 | `dsh.director.mindmap` | `{ nodes: MindNode[], edges: Edge[] }` |
| 分支对话消息 | `dsh.director.messages.{branchId}` | 按branchId隔离存储 |
| 总监调度记录 | `dsh.director.dispatches` | `DirectorDispatch[]` |
| 产出物清单 | `dsh.director.deliverables.{branchId}` | `Deliverable[]` |

### 2.2 核心数据结构

```javascript
// MindNode — 思维导图节点（三维定义）
{
  id: "node_xxx",           // 唯一ID
  parentId: "node_root",    // 父节点ID（根节点为null）
  name: "前端开发",           // 节点名称
  type: "code",             // 处理类型：doc/code/test/research/design/general
  agentId: "frontend-dev",  // 智能体角色
  model: "deepseek-coder",  // 绑定模型
  status: "in_progress",    // 状态：pending/in_progress/completed/error/paused
  branchId: "branch_xxx",   // 关联的分支会话ID
  contextSummary: "...",    // 上下文摘要（压缩后）
  inputFolder: "docs/design/",  // 输入文件夹
  outputFolder: "src/frontend/", // 输出文件夹
  dependsOn: ["node_arch"],     // 依赖的节点ID列表
  createdAt: 1234567890,
  updatedAt: 1234567890,
  // 布局信息（组件内部使用）
  x: 0, y: 0,
  expanded: true
}

// BranchMessage — 分支对话消息
{
  id: "msg_xxx",
  branchId: "branch_xxx",
  role: "user" | "assistant" | "system" | "director",
  content: "消息内容",
  timestamp: 1234567890,
  model: "deepseek-coder",  // 发送时使用的模型
  // director消息特有
  directorAction: "create_branch" | "assign_task" | "pass_context" | "review" | null
}

// DirectorDispatch — 总监调度记录
{
  id: "dispatch_xxx",
  timestamp: 1234567890,
  action: "create_branch" | "assign_task" | "pass_context" | "review" | "merge",
  fromBranch: "branch_director",
  toBranch: "branch_frontend",
  taskDescription: "开发登录页面",
  contextSummary: "项目背景...",
  inputFiles: ["docs/design/login.md"],
  status: "completed" | "pending" | "failed"
}

// Deliverable — 产出物
{
  id: "deliverable_xxx",
  branchId: "branch_xxx",
  name: "auth.ts",
  path: "src/frontend/auth.ts",
  type: "code" | "doc" | "config" | "other",
  status: "in_progress" | "completed" | "reviewed",
  createdAt: 1234567890,
  updatedAt: 1234567890
}
```

## 三、创建分支→自动添加思维导图节点（功能2）

### 3.1 交互流程

1. 用户点击思维导图中的"+"按钮或总监对话中说"创建前端开发分支"
2. 弹出创建分支弹窗（视图2）
3. 用户选择：处理类型（6种）→ 智能体角色 → 模型
4. 点击"创建"
5. 系统自动：
   - 创建host会话（branchId）
   - 在思维导图中添加节点（parentId=当前选中节点）
   - 传递上下文摘要（如果是总监创建）
   - 切换到新分支对话

### 3.2 实现步骤

1. 在 `lib/client.js` 中找到现有分支创建逻辑（`createBranch` 函数）
2. 修改：创建分支后调用 `mindmap.addNode()` 自动添加节点
3. 节点的 `parentId` = 当前选中的节点ID（或根节点）
4. 节点的 `branchId` = 新创建的分支会话ID
5. 触发思维导图重渲染

### 3.3 关键代码位置

- 现有分支创建：`lib/client.js` 中搜索 `createBranch` 或 `newBranch`
- 思维导图组件：`BranchMindMap` 组件（搜索 `BranchMindMap`）

## 四、点击思维导图节点→进入分支对话（功能3）

### 4.1 交互流程

1. 用户在思维导图中点击某个节点
2. 系统检查节点是否有关联的 `branchId`
3. 如果有：切换到对应分支对话（加载该分支的消息）
4. 如果没有（纯组织节点）：显示节点详情面板（视图4）
5. 节点高亮显示（选中态）

### 4.2 实现步骤

1. 给思维导图节点添加 `onClick` 事件处理
2. 点击时调用 `branchManager.switchBranch(node.branchId)`
3. 切换分支时：
   - 保存当前分支的消息（按branchId隔离）
   - 加载目标分支的消息
   - 更新UI（对话区标题、消息列表）
4. 节点选中态：添加 `selected` CSS类

### 4.3 消息隔离方案

```javascript
// 切换分支时
function switchBranch(branchId) {
  // 1. 保存当前分支消息
  const currentBranch = store.currentBranch;
  if (currentBranch) {
    localStorage.setItem(`dsh.director.messages.${currentBranch}`, 
      JSON.stringify(store.messages));
  }
  // 2. 加载目标分支消息
  const messages = JSON.parse(
    localStorage.getItem(`dsh.director.messages.${branchId}`) || '[]'
  );
  store.messages = messages;
  store.currentBranch = branchId;
  // 3. 更新UI
  renderConversation();
}
```

## 五、现有对话→自动生成思维导图（功能4）

### 5.1 交互流程

1. 用户在总监对话中点击"生成思维导图"按钮（视图1工具栏）
2. 系统分析当前对话历史，识别分支点
3. 分支点识别规则（5级优先级）：
   - P1：用户明确说"创建XX分支/切换到XX模型"
   - P2：模型切换事件（从对话元数据中检测）
   - P3：话题明显转变（AI检测，可选）
   - P4：长时间间隔（>10分钟无消息）
   - P5：用户手动标记
4. 生成树结构：根节点=对话主题，子节点=各分支
5. 在思维导图中渲染

### 5.2 实现步骤

1. 在工具栏添加"生成思维导图"按钮
2. 点击后调用 `mindmapGenerator.generateFromConversation(conversationId)`
3. 生成算法：
   - 遍历对话消息，识别分支点（P1-P2规则，P3-P5留到P1）
   - 构建树结构（根节点+子节点）
   - 每个分支点创建一个MindNode
   - 节点的 `branchId` = 该分支的会话ID
4. 保存到 `dsh.director.mindmap`
5. 触发思维导图重渲染

### 5.3 降级方案

- 如果AI检测不可用（Ollama未运行）：只使用P1-P2规则（明确的分支创建和模型切换）
- 如果没有检测到分支点：创建一个根节点+一个子节点（当前对话），提示用户手动添加分支

## 六、BranchMindMap组件数据驱动改造（功能5）

### 6.1 改造目标

现有BranchMindMap组件可能是硬编码或半数据驱动的，需要改为完全数据驱动：
- 节点数据来自 `dsh.director.mindmap.nodes`
- 连线数据来自 `edges`（或从parentId推导）
- 布局算法独立（可切换水平/垂直/树状）
- 节点状态（pending/in_progress/completed/error）通过CSS类显示

### 6.2 实现步骤

1. 找到现有 `BranchMindMap` 组件（搜索 `BranchMindMap` 或 `mindmap`）
2. 提取节点渲染逻辑为 `renderNode(node)` 函数
3. 提取连线渲染逻辑为 `renderEdges(nodes)` 函数
4. 布局算法：使用简单的树状布局（水平方向，根节点在左）
   - 计算每个节点的x/y坐标
   - GAP_X=160px（节点间距水平）
   - GAP_Y=24px（节点间距垂直）
5. 节点状态样式：
   - pending：灰色边框
   - in_progress：橙色边框+脉冲动画
   - completed：绿色边框+✓图标
   - error：红色边框+⚠图标
6. 节点点击：调用 `switchBranch(node.branchId)`
7. 节点悬浮：显示操作条（查看详情/重命名/删除）

### 6.3 V12设计系统对齐

| 设计维度 | 规范 | 实现 |
|---------|------|------|
| 根节点背景 | #2563eb（品牌蓝） | `.mm-node.root { background: #2563eb; color: #fff; }` |

## 七、总监调度基础（功能6）

### 7.1 总监能力范围（P0）

P0阶段总监只做3件事：
1. **拆解任务**：用户提需求→总监分析→输出任务拆解方案
2. **创建分支**：根据拆解方案，创建专业化分支（处理类型+智能体+模型）
3. **传递上下文**：创建分支时，传递项目背景摘要+任务描述

P0不做：审核流程、全局监控、流水线调度（这些在P1/P2）

### 7.2 交互流程

1. 用户在总监对话中说："我要做一个用户登录功能"
2. 总监回复：
   - 分析需求
   - 输出任务拆解方案（如：需求分析→架构设计→前端开发→后端开发→测试）
   - 询问用户确认
3. 用户确认后，总监自动：
   - 创建第一个分支（如"需求分析"，type=doc, agent=analyst, model=deepseek-v4）
   - 传递上下文（项目背景+任务描述）
   - 切换到该分支对话
4. 用户可以随时回到总监对话，说"创建下一个分支"

### 7.3 实现步骤

1. 在总监对话中添加特殊指令识别：
   - "创建XX分支" → 触发创建分支流程
   - "拆解任务" → 触发任务拆解
2. 总监回复模板：
   ```
   【任务拆解】
   1. 需求分析（文档型，分析师，DeepSeek-V4）
   2. 架构设计（文档型，架构师，DeepSeek-V4）
   3. 前端开发（开发型，前端工程师，DeepSeek-Coder）
   
   确认后我将依次创建分支并传递上下文。
   ```
3. 用户确认后，调用 `createBranchWithContext()` 函数
4. 该函数：
   - 创建分支（host会话）
   - 添加思维导图节点
   - 传递上下文（写入分支的第一条system消息）
   - 切换到该分支

### 7.4 上下文传递格式

```javascript
// 传递给新分支的上下文（作为第一条system消息）
{
  role: "system",
  content: `【项目背景】
${projectSummary}

【任务描述】
${taskDescription}

【输入文件】
${inputFiles.map(f => `- ${f}`).join('\n')}

【输出要求】
${outputRequirements}

【总监指令】
你是${agentName}，使用${model}模型。专注于${taskDescription}。
完成后通知总监审核。`
}
```

## 八、分支三维定义表单（功能7）

### 8.1 表单结构（视图2）

三步引导式表单：

**Step 1：选择处理类型（6种）**
- 📄 文档（doc）— 写文档、做方案、整理资料
- 💻 开发（code）— 写代码、调试、重构
- 🧪 测试（test）— 写测试、验证、质量检查
- 🔍 调研（research）— 查资料、做分析、评估方案
- 🎨 设计（design）— UI设计、原型、视觉稿
- ⚙️ 通用（general）— 其他任务

**Step 2：选择智能体角色**
- 根据处理类型推荐对应的智能体（如开发→前端工程师/后端工程师/全栈工程师）
- 也可以选择"自定义"

**Step 3：选择模型与配置**
- 模型下拉：DeepSeek-V4 / DeepSeek-Coder / DeepSeek-V4-Flash / Qwen2:7b（本地）
- 根据处理类型推荐模型（如开发→DeepSeek-Coder）
- 上下文传递选项（从父节点继承/手动输入/不传递）

### 8.2 实现步骤

1. 创建 `CreateBranchModal` 组件（弹窗）
2. 三步状态管理：`currentStep = 1/2/3`
3. Step 1：6个类型卡片，点击选中
4. Step 2：根据type过滤智能体列表，单选
5. Step 3：模型下拉+上下文选项
6. 底部：上一步/下一步/创建按钮
7. 创建时调用 `createBranch({type, agentId, model, contextSummary})`

### 8.3 智能体预设列表

## 九、上下文传递基础（功能8）

### 9.1 传递时机

P0阶段只在以下时机传递上下文：
1. 总监创建分支时（自动传递项目背景+任务描述）
2. 用户手动创建分支时（可选：从父节点继承/手动输入）

### 9.2 上下文摘要卡片（视图3）

进入分支对话时，顶部显示上下文摘要卡片：
- 来源：从总监/父节点传递
- 内容：项目背景+任务描述+输入文件列表
- 操作：展开/收起、编辑、查看完整对话、来源溯源

### 9.3 实现步骤

1. 创建分支时，将上下文摘要写入 `MindNode.contextSummary`
2. 切换到分支对话时，读取该节点的 `contextSummary`
3. 在对话区顶部渲染摘要卡片（可展开/收起）
4. 摘要卡片的"编辑"按钮：允许用户修改摘要
5. "查看完整对话"按钮：跳转到来源分支（总监或父节点）

### 9.4 上下文摘要数据结构

```javascript
{

  taskDescription: "开发登录页面，包含邮箱/手机号登录", // 任务描述
  inputFiles: ["docs/design/login.md"],            // 输入文件
  createdAt: 1234567890,
  editedAt: null,                                    // 用户编辑时间
  editedBy: null                                     // 用户/系统
}
```
