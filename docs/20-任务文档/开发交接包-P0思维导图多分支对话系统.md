## 三、P0阶段8项功能（按执行顺序）

### 执行顺序

```
1. 数据模型统一 → 2. 思维导图改造 → 3. 创建分支加节点
→ 4. 点击节点进对话 → 5. 三维定义表单 → 6. 上下文传递
→ 7. 总监调度 → 8. 生成思维导图
```

## 四、关键技术约束（铁律，不可违反）

### 4.1 项目铁律

1. **永远不要直接修改Harness原安装目录** — 只在 `dsh-director` 插件中修改
2. **修改对象是编译产物** — `lib/client.js`（332KB）是编译后的代码，修改时小心
3. **所有数据存localStorage** — key前缀 `dsh.director.`，按branchId隔离
4. **消息隔离** — 切换分支时先保存当前分支消息，再加载目标分支，防止丢失
5. **回滚方案** — git commit + localStorage备份 + 禁用插件即可复原

## 七、常见问题与解决方案

### Q1：找不到思维导图组件在哪里？
A：在 `lib/client.js` 中搜索 `BranchMindMap`、`mindmap`、`思维导图` 等关键词。如果没有现成组件，需要新建。

### Q2：client.js太大（332KB），怎么修改？
A：用搜索定位到具体函数/组件，用Edit工具精确替换，不要用Write覆盖整个文件。修改前先备份。

### Q3：localStorage数据怎么调试？
A：在浏览器控制台执行 `localStorage` 查看所有数据，`JSON.parse(localStorage.getItem('dsh.director.mindmap'))` 查看思维导图数据。

### Q4：消息隔离实现后消息丢失了怎么办？
A：检查切换分支时是否先保存了当前分支消息。添加console.log调试。数据双写（旧格式+新格式）作为安全网。

### Q5：总监调度的AI回复格式不稳定怎么办？
A：P0阶段采用半自动模式：总监输出拆解方案→用户确认→再创建分支。不做全自动。
