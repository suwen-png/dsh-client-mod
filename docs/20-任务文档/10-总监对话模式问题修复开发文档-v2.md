## 2. 根因分析

### P1 + P2 共同根因（核心）：`sendSession` 的 mode 参数无效

**证据链**：
1. `conv.sendSession(session, text, imageIds, mode)` 定义于行130，内部调用 `session.prompt(content, mode)`（行137）
2. 标准对话 InputBar 发送时调用 `keyboard.submit(resolveSubmitMode(...))`，有效值为 `"queue"` / `"enter"` / `"accelerated"`
3. `__directChatSubmit`（行10422）和 `__directorSubmit` 的 onForward 回调（行10408）均传入 `mode = "chat"`
4. `"chat"` 不是 `session.prompt` 认可的 mode，导致 prompt 静默失败或抛出被 catch 吞掉的错误

**影响范围**：
- P1：总监tab点击对话小窗后发消息 → `__directChatSubmit` → `sendSession(..., "chat")` → 失败
- P2：总监处理后自动转发 → onForward → `sendSession(..., "chat")` → 失败

**修复方案**：将两处 `"chat"` 改为 `"queue"`（标准对话默认 mode）

**概率**：95%

---

### P3 根因：自动滚动未生效 + justify-content: flex-end 叠加问题

**证据链**：
1. DirectorView 使用 `useLayoutEffect + requestAnimationFrame + scrollTop = scrollHeight`（行7361-7371）
2. 消息容器同时设置了 `justifyContent: "flex-end"`（行7333）
3. `flex-end` 使消息从底部排列，但当消息数量超过容器高度时，`flex-end` 会导致顶部消息被裁剪，且 `scrollTop = scrollHeight` 可能滚到最底部但新消息在可视区域下方
4. 探针 `scrollProbe` 已添加但用户未提供数据，无法确认 scrollTop/scrollHeight/clientHeight 的实际值

**可能的子根因**：
- a. `useLayoutEffect` 在 `state.messages.length` 变化时触发，但 `requestAnimationFrame` 内读取的 `scrollHeight` 可能是旧值（DOM 尚未更新）
- b. `messagesEndRef` 指向的元素不是实际滚动容器
- c. `justify-content: flex-end` 与 `overflow-y: auto` 叠加导致滚动行为异常

**修复方案**：
1. 移除 `justifyContent: "flex-end"`，改用 `margin-top: auto` 在第一条消息前添加占位，使消息贴底部
2. 或保留 `flex-end`，但确保自动滚动在 DOM 完全更新后执行（双重 requestAnimationFrame）
3. 添加探针显示 scrollTop/scrollHeight/clientHeight，验证滚动行为

**优先方案**：双重 requestAnimationFrame 确保 DOM 更新后滚动，保留 flex-end

**概率**：70%

---

### P4 根因：对话返回审核逻辑未区分消息来源

**证据链**：
1. DirectorView 中 `useEffect` 订阅 `chatOrder` 和 `chatNodes`（行7362+）
2. 检测到新的 `assistant` 或 `message` 类型节点时，调用 `directorReviewReturn`
3. 未区分消息是来自"总监转发"还是"用户直接在对话tab发送"
4. 用户明确要求："对话发的消息不需要总监审核"

**修复方案**：
1. 方案A（推荐）：完全移除对话返回审核逻辑，用户明确不需要
2. 方案B：添加标记，只审核从总监转发的消息的返回（需在转发时添加标记，复杂度高）
3. 方案C：在设置中添加开关，默认关闭

**优先方案**：方案A，完全移除，遵循用户指令

**概率**：90%

---

### P5 根因：持久化逻辑未验证

**证据链**：
1. `createDirectorStore` 创建时调用 `loadDirectorStore` 从 localStorage 加载（行5432）
2. `notify()` 中调用 `saveDirectorStore` 保存（行5440）
3. localStorage key = `dsh.director.store.${sessionId}`
4. 未在 Harness 环境中验证 localStorage 是否可用、是否域隔离

**修复方案**：
1. 添加探针显示 localStorage 中存储的消息数量
2. 在总监消息流中显示"已加载N条历史消息"提示
3. 验证后如不生效，改用 IndexedDB 或其他存储方案

**概率**：50%（需验证）

## 3. 执行逻辑理解

### 3.1 总监tab给总监发消息（当前正常）

```
用户输入 → InputBar键盘/按钮
  → 读取 dirView="director", focusTarget="director"
  → 调用 window.__directorSubmit(sessionId, draft)
    → directorProcess(sessionId, draft, dStore, t, onForward)
      → store.addMessage(user)  // 总监流显示用户消息
      → 语言整理/任务分类/上下文分析
      → store.addMessage(assistant)  // 总监流显示分析结果
      → if (config.autoForward) onForward(instruction)
        → conv.sendSession(sess, instruction, [], "chat")  // ❌ mode无效，失败
```

### 3.2 总监tab给对话发消息（当前失败）

```
用户点击对话小窗 → onContainerClick
  → directorLayoutStore.setFocusTarget("chat")
    → state.focusTarget = "chat"
    → window.__directorFocusTarget = "chat"
用户输入 → InputBar键盘/按钮
  → 读取 dirView="director", focusTarget="chat"（从store读取）
  → 调用 window.__directChatSubmit(sessionId, draft)
    → conv.sendSession(sess, draft, [], "chat")  // ❌ mode无效，失败
```

### 3.3 断点定位

| 步骤 | 状态 | 说明 |
|------|------|------|
| 焦点切换 | ✅ 正常 | onContainerClick → setFocusTarget → store更新 |
| InputBar判断 | ✅ 正常 | 从store读取最新focusTarget |
| __directChatSubmit调用 | ✅ 正常 | 函数被调用，探针directCall+1 |
| sendSession执行 | ❌ 失败 | mode="chat"无效，静默失败 |
| __directorSubmit调用 | ✅ 正常 | 函数被调用 |
| directorProcess执行 | ✅ 正常 | 总监流显示用户消息和分析结果 |
| onForward执行 | ✅ 正常 | 回调被调用 |
| sendSession执行 | ❌ 失败 | mode="chat"无效，静默失败 |

**结论**：所有逻辑链路正常，唯一断点是 `sendSession` 的 `mode="chat"` 无效。

## 4. 修复方案

### 4.1 P1+P2 修复：mode 参数修正

**修改位置**：
- 行10408：`__directorSubmit` 的 onForward 回调
- 行10422：`__directChatSubmit`

**修改内容**：
```javascript
// 修改前
conv.sendSession(sess, instruction, [], "chat")
conv.sendSession(sess, draft, [], "chat")

// 修改后
conv.sendSession(sess, instruction, [], "queue")
conv.sendSession(sess, draft, [], "queue")
```

**依据**：标准对话 InputBar 使用 `resolveSubmitMode` 返回 `"queue"` 作为默认 mode

**影响范围**：仅修改 mode 参数，不改变其他逻辑

---

### 4.2 P3 修复：自动滚动增强

**修改位置**：DirectorView 行7361-7371

**修改内容**：
```javascript
// 修改前
(0, react.useLayoutEffect)(() => {
    const el = messagesEndRef.current;
    if (el) {
        requestAnimationFrame(() => {
            if (messagesEndRef.current) {
                messagesEndRef.current.scrollTop = messagesEndRef.current.scrollHeight;
                setScrollProbe({...});
            }
        });
    }
}, [state.messages.length, state.status]);

// 修改后：双重RAF确保DOM完全更新
(0, react.useLayoutEffect)(() => {
    const el = messagesEndRef.current;
    if (el) {
        requestAnimationFrame(() => {
            requestAnimationFrame(() => {
                if (messagesEndRef.current) {
                    messagesEndRef.current.scrollTop = messagesEndRef.current.scrollHeight;
                    setScrollProbe({ triggered: Date.now(), scrollTop: messagesEndRef.current.scrollTop, scrollHeight: messagesEndRef.current.scrollHeight, clientHeight: messagesEndRef.current.clientHeight });
                }
            });
        });
    }
}, [state.messages.length, state.status]);
```

**同时修改**：DirectorFlow（行5651+）和 ChatFlow 的自动滚动也使用双重RAF

---

### 4.3 P4 修复：移除对话返回审核

**修改位置**：
- DirectorView 行7362+：移除 `chatOrder`/`chatNodes` 订阅和 `useEffect`
- 行5648+：移除 `directorReviewReturn` 函数（或保留但不调用）

**修改内容**：
1. 移除 `const chatOrder = useSession(...)` 和 `const chatNodes = useSession(...)`
2. 移除对应的 `useEffect`
3. 移除 `lastReviewedCount` ref
4. 保留 `directorReviewReturn` 函数定义（供未来使用），但不调用

**依据**：用户明确要求"对话发的消息不需要总监审核"
