## 三、三轮审核机制（每阶段通用）

### 3.1 三轮审核分工（每轮审核焦点不同，避免重复审同一件事）

| 轮次 | 审核焦点 | 阶段1简图审核内容 | 阶段2功能审核内容 | 阶段3样式审核内容 |
|:----:|---------|------------------|------------------|------------------|
| 第1轮 | **结构与完整性** | 区域是否齐全（R1-R8）、位置是否符合V9.1布局、比例是否合理 | 功能是否覆盖V9.1全部能力、有无遗漏（T8/T9/T10/T11对应入口） | 配色是否成体系、是否符合暗色主题、语义色是否齐全 |
| 第2轮 | **交互与可达性** | 交互态是否画全（展开/折叠/hover/焦点）、元素是否可达、操作路径是否≤2步 | 每个元素交互定义是否完整（点击/hover/数据/状态）、跨区联动是否闭环 | 对比度是否可读、状态色是否可区分（正常/hover/选中/禁用）、信息层级是否清晰 |
| 第3轮 | **边界与异常** | 空数据/超长文本/窄屏（1280px）/全折叠态的呈现 | 异常场景（无记忆/无分支/模型不可用/文档读取失败）的功能降级 | 极端内容下的样式鲁棒性（长项目名/多条风险/密集列表） |

### 3.2 单轮审核流程

```
产出当轮设计稿（HTML原型，可预览）
  → 对照该轮审核清单逐项检查
  → 输出审核记录表（问题/位置/严重度/修改方案）
  → 修改设计稿
  → 复审确认问题关闭
  → 进入下一轮
```

### 3.3 收敛标准（三轮后必须满足才允许进入下一阶段）

- 三轮审核记录完整，所有 P0/P1 问题已关闭（P2 可记录延后）
- 用户确认当轮最终稿
- 审核记录归档到本文档附录

## 五、对用户原始想法的补全点

用户原始流程：简图 → 审3轮 → 功能 → 审3轮 → 配色 → 审3轮。以下是我补全的部分：

| # | 补全点 | 理由 |
|---|--------|------|
| 1 | **阶段0基线冻结** | 不冻结现状就设计，会和已实现区域（R1/R3/R5/R6/R8）脱节，返工风险高 |
| 2 | **三轮审核分工明确化**（结构→交互→边界） | 三轮若都审同一件事等于只审一轮；分工后三轮有递进价值 |
| 3 | **简图拆三层**（框架/内部元素/交互态） | 只画静态位置会漏掉 hover展开、折叠、焦点切换等核心交互，这些是 R6/R7 的命脉 |
| 4 | **用 HTML 原型代替纯文字简图** | 项目已有 `消息排列位置-justify-flex-end草图.html` 先例，可视化审核比文字描述出错率低得多 |
| 5 | **功能映射落到元素级**（功能/数据/状态三列） | "区域有什么功能"太粗，落到按钮级才能直接转开发任务 |
| 6 | **收敛标准** | 三轮后必须满足什么才算过，避免无限循环修改 |
| 7 | **阶段4交付对接开发** | 设计不定稿到 T3a/T3b/T4 任务级，设计成果落不了地 |
| 8 | **异常态设计纳入第3轮** | 空记忆、无分支、模型挂掉这些场景不设计，运行时必出丑 |

| 4 | 配色倾向 | ✅ 沿用 Harness 原生暗色主题，**增加设置面板允许颜色调整**（主色/强调色可调，持久化） |

### 7.1 响应式策略（冻结）

- 布局骨架全部使用 flex + `clamp(min, vw%, max)`，禁止写死像素宽度
- 断点规则（按主区宽度，非设备宽度）：
  - `W ≥ 1100px`：三栏全显（导航/对话/a-2）
  - `W < 1100px`：a-2 自动折叠为边缘条，点击展开
  - `W < 860px`：导航列折叠为图标栏
- 高度方向：R2 总览卡片、R6 记忆面板均可折叠，折叠态优先保住对话区
- 所有可拖拽分栏保留拖拽手柄，拖拽值仍受 clamp 约束

### 7.2 颜色设置项（冻结，阶段3细化）

- R1 顶部栏右侧放 ⚙ 设置入口 → 弹出设置面板
- 设置项：主强调色（默认沿用 Harness 蓝）、次强调色、记忆面板高亮色
- 持久化：localStorage `dsh-v9-theme`，启动时读取注入 CSS 变量
- 默认主题 = Harness 原生暗色变量，用户调整仅覆盖变量，不改结构
