# 总监对话模式 — 问题审核与修复方案文档

## 1. 问题清单与根因分析

### 问题1：每次打开总监数据都为空（持久化失效）
**现象**：发送总监消息后，关闭重启 Harness，总监对话历史丢失。

**涉及函数**：
- `loadDirectorStore(sessionId)` — 行5412，从 localStorage 加载
- `saveDirectorStore(sessionId, state)` — 行5423，保存到 localStorage
- `createDirectorStore(sessionId)` — 行5429，创建时调用 loadDirectorStore
- `notify()` — 行5437，状态变化时调用 saveDirectorStore

**根因分析**：
代码逻辑本身正确（创建时加载、变化时保存）。可能原因：
1. **localStorage 域隔离**：Harness 可能使用了自定义协议（如 `http://127.0.0.1:2426`），localStorage 按域隔离。如果插件代码运行在不同的域，localStorage 不共享。
2. **sessionId 变化**：每次打开会话 sessionId 可能不同（但同一会话应该相同）。
3. **saveDirectorStore 未被调用**：notify() 中调用了 saveDirectorStore，但如果 addMessage 没有触发 notify，就不会保存。

**验证方法**：在 saveDirectorStore 和 loadDirectorStore 中添加 console.log，确认是否被调用及返回值。

**修复方案（概率90%）**：
- 确认 localStorage 可用后，当前代码应能工作。
- 若 localStorage 域隔离，改用 `ctx.get("settingsScope")` 或 Harness 提供的持久化 API。
- 临时方案：在 DirectorView 挂载时，从 localStorage 手动加载并调用 store.reset(loadedState)。

### 问题2：总监消息发送后跑到最上面（自动滚动方向错误）
**现象**：发送消息后，新消息出现在底部，但视图滚动到顶部，需要手动拉下去看。

**涉及函数**：
- `DirectorView` 组件 — 行7226
- `messagesEndRef` — 行7231，绑定到消息滚动容器
- `useEffect` — 行7232-7234，消息变化时调用 `scrollIntoView`

**根因分析**：
```javascript
useEffect(() => {
    messagesEndRef.current?.scrollIntoView({ behavior: "smooth" });
}, [state.messages.length, state.status]);
```
`Element.scrollIntoView()` 会把元素滚动到**视口顶部**，而不是滚动容器内部到底部。因为 `messagesEndRef` 绑定的是滚动容器本身（不是容器内的最后一个元素），scrollIntoView 会把整个容器滚到页面顶部，导致内容看起来在顶部。

**修复方案（概率95%）**：
改用 `scrollTop = scrollHeight`：
```javascript
useEffect(() => {
    if (messagesEndRef.current) {
        messagesEndRef.current.scrollTop = messagesEndRef.current.scrollHeight;
    }
}, [state.messages.length, state.status]);
```

### 问题3：总监tab小窗拖拽方向反了 + 对话tab总监小窗不能拖拽
**现象**：
- 总监tab中对话小窗能调整大小，但拖拽方向反（向右拖变小，向左拖变大）
- 对话tab中总监小窗完全不能调整大小

**涉及函数**：
- `DirectorView.onChatResizerMouseDown` — 行7252，总监tab对话小窗拖拽
- `ChatView.onDirectorResizerMouseDown` — 行5777，对话tab总监小窗拖拽
- `directorLayoutStore.setChatWidth` — 行5503
- `directorLayoutStore.setDirectorWidth` — 行5502

**根因分析**：

**3a. 对话tab总监小窗不能拖拽（明确bug）**：
```javascript
const onDirectorResizerMouseDown = useCallback((e) => {
    e.preventDefault();
    // ❌ 缺少 isDraggingDirector.current = true;
    const startX = e.clientX;
    const startWidth = layout.directorPanelWidth;
    const onMove = (ev) => {
        if (!isDraggingDirector.current) return; // ❌ 永远为 false，直接返回
        directorLayoutStore.setDirectorWidth(startWidth - (ev.clientX - startX));
    };
    ...
}, [layout.directorPanelWidth]);
```
对比 DirectorView 中的正确实现（行7252）有 `isDraggingChat.current = true;`，ChatView 中遗漏了这一行。

**3b. 拖拽方向反了（明确bug）**：
ChatView 中总监小窗在左侧，拖拽条在小窗右侧。向右拖拽时，小窗右边界右移，宽度应该**增加**。但代码是：
```javascript
setDirectorWidth(startWidth - (ev.clientX - startX)); // ❌ 向右拖拽时宽度减少
```
应该是：
```javascript
setDirectorWidth(startWidth + (ev.clientX - startX)); // ✅ 向右拖拽时宽度增加
```

**3c. 总监tab对话小窗方向**：
总监tab中对话小窗在右侧，拖拽条在小窗左侧。向右拖拽时，小窗左边界右移，宽度应该**减少**。当前代码：
```javascript
setChatWidth(startWidth + (ev.clientX - startX)); // ❌ 向右拖拽时宽度增加
```
应该是：
```javascript
setChatWidth(startWidth - (ev.clientX - startX)); // ✅ 向右拖拽时宽度减少
```

**修复方案（概率98%）**：
1. ChatView `onDirectorResizerMouseDown` 开头添加 `isDraggingDirector.current = true;`
2. ChatView 拖拽方向改为 `startWidth + (ev.clientX - startX)`
3. DirectorView 拖拽方向改为 `startWidth - (ev.clientX - startX)`

### 问题4：总监tab中给对话发消息发不出去
**现象**：在总监tab中，点击右侧对话小窗后，输入消息发送，消息没有发到对话。

**涉及函数**：
- `DirectorView` 对话小窗 onClick — 行7305，调用 `setFocusTarget("chat")`
- `directorLayoutStore.setFocusTarget` — 行5506，更新 state 和 window.__directorFocusTarget
- `InputBar` 键盘回车逻辑 — 行~3543，判断 dirView + focusTarget
- `InputBar` 发送按钮逻辑 — 行~3717，判断 dirView + focusTarget
- `window.__directChatSubmit` — 行~10200，直接发对话

**根因分析**：
代码逻辑看起来正确，但可能的问题：
1. **点击对话小窗后 focusTarget 未更新**：对话小窗内部元素（如标题栏折叠按钮）有 `e.stopPropagation()`，但点击小窗内容区域应该能触发 onClick。需要验证点击后 `focus:` 调试标签是否变为 chat。
2. **window.__directChatSubmit 发送失败**：`sessions.list.getSnapshot().byId[sessionId]` 可能返回 undefined，导致 `if (sess)` 不通过，消息静默丢弃。
3. **InputBar 中 dirView 判断时机**：`window.__directorCurrentView` 可能在发送时还未更新为 "director"。

**验证方法**：
1. 点击对话小窗后，查看标题栏 `focus:` 标签是否变为 chat。
2. 在 `window.__directChatSubmit` 中添加 console.log，确认 sess 是否存在、sendSession 是否被调用。

**修复方案（概率80%，需验证）**：
- 若 focusTarget 未更新：检查对话小窗 onClick 是否被内部元素阻止冒泡。
- 若 sess 为 undefined：检查 sessionId 是否正确传递，或改用 `sessions.byId[sessionId]`。
- 临时方案：在 `window.__directChatSubmit` 中添加错误日志，便于排查。

## 3. 不能落实/需进一步验证的地方

1. **持久化（问题1）**：代码逻辑正确，但不确定 localStorage 在 Harness 插件环境中是否可用、是否域隔离。需添加日志验证。
2. **给对话发消息（问题4）**：代码逻辑正确，但不确定是焦点切换问题还是发送函数问题。需添加日志验证。
3. **renderSlot 不可用**：总监tab中 slot 系统未注入 renderSlot，导致 ChatNodeSeat 无法使用完整交互。当前用 fallback 简化渲染。要实现完整交互，需研究如何从 slot 系统手动获取 renderSlot（可能是 ctx.slots 的某个 API）。

## 4. 审核结论

- **明确bug（概率>90%）**：问题2（自动滚动）、问题3a（ChatView拖拽未启用）、问题3b（ChatView拖拽方向反）
- **较可能bug（概率80-90%）**：问题3c（DirectorView拖拽方向）、问题4（发消息失败，需验证）
- **需验证（概率<80%）**：问题1（持久化）、renderSlot完整交互

**建议**：先修复明确bug（问题2、3a、3b），同时为问题1和问题4添加调试日志，验证后再修复。问题3c（DirectorView拖拽方向）需用户确认当前方向是否反了。
