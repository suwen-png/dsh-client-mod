## 2026-08-24 项目初始化

### 决策1：方案变更 — 从外部bundle注入改为原客户端直接改造

**背景**：原方案（12-Starfield主区覆盖与对话模式切换开发文档）走外部bundle注入路线，通过profile启用独立npm包，在apply(ctx)中往slot注入组件。存在main.page keyed slot注册时序导致组件不渲染的卡点。

**决策**：放弃外部bundle注入，直接修改Harness原客户端编译产物（lib/client.js），通过Junction符号链接替换原安装目录中的包。

**理由**：
- 直接在conversation.view list slot中新增总监tab，与对话/轨迹同层，无时序问题
- 只新增不修改原有代码，ChatView/TrajectoryView完全不动
- Junction零拷贝可切换，restore.ps1一键复原

### 决策2：总监职能定义

**来源**：starfield-agent项目 docs/10-架构设计/06-专项开发/总监内容构思落地方案-20260814.md

**核心定义**：总监层 = 会话预处理中枢，不执行业务、不调用工具、不运行大模型推理，仅做索引检索→按需加载→上下文筛选精简→模型路由→组装报文→写入提交列。

**总监处理流程（5步）**：
1. 整理语言（本地qwen2:7b，把用户口语化意图整理为精确指令）
2. 判断是否需要切新分支
3. 判断是否需要切模型（切模型自动调整分支）
4. 切换分支时判断传哪些上下文
5. 自动审核大模型产出

### 决策3：总监tab布局

**布局**：五区域竖向排列
1. 标题栏（总监 + 状态标签 + 自动转发开关 + ⚙设置）
2. 三面板占位（智能体/技能/执行逻辑，阶段1仅占位）
3. 总监对话流（用户↔总监，含思考路径）
4. 底部输入栏
5. 设置弹窗（阶段1仅自动转发开关）

### 决策4：消息流

**核心**：用户在总监tab发消息 → 总监预处理 → 自动转发整理后的指令到原对话系统 → 原对话tab显示大模型回复 → 轨迹tab显示调用链。

**关键**：总监只发整理后的指令，不发总监自己的回复。总监对话流独立于原对话流，但共享sessionId。

**自动/手动**：默认全自动提交（autoForward=true），可配置为手动确认（autoForward=false时总监回复下方显示"确认发送到对话"按钮）。

### 决策5：本地模型

**环境**：Ollama + qwen2:7b（4.4GB），端口11434，服务已运行。

**用途**：总监预处理（整理语言、模型路由、分支判断），低温度（0.3）。

**降级**：Ollama不可用时提示用户，可选择跳过总监直接发送。
