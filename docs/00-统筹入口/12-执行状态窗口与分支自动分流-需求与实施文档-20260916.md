## 四、设计

### 4.1 执行状态窗口（三态 + 拖动 + 吸附）

```
状态机（互斥）
  expanded  ──「—」/双击头部──▶  collapsed
     ▲                              │
     │◀──────── 点击条体 ───────────┘
     │
     └── 拖动松手时距边 <24px ──▶  docked（贴边缩进成条，点击回来）
```

- **把手**：头部行（`dp-running-head`）— 拖动位移用 `clamp(x, insetLeft+4, vw-w-insetRight-4)` 夹紧；拖动中**不改 React 之外的任何 store**（🔴 纪律 47：`setState(updater)` 更新函数必须纯；副作用放事件回调）。
- **最小化**：`collapsed` 态只渲染头部（含 `data-count` / `data-chain-status` 徽标 —— **信息不丢**），内容区 `display:none`。
- **靠边缩进**：`docked` 态贴边显示为窄条（左侧/右侧竖条或顶部/底部横条），正文用竖排/单行；点击恢复 `expanded` 并回到吸附前坐标。
- **默认进入 `collapsed`**（C1）⇒ 不再压住 R2.5 动作行 ⇒ **A1 不会回归**；同时恢复 `pointer-events:auto`（因为要可拖可点）。

### 4.2 分支自动分流链路（N2 + N3 + N4）

```
用户输入（例：写小说《X》）
  → routing.js 识别维度（小说场景 → A1..A8）      ← 复用，单目标扩为多目标
  → 逐条线：
      ① ctx.sessions.create({ workspaceId|cwd })  → 得 newSessionId      [复用]
      ② openSession(newSessionId) 或 deliverToChat(...,{sessionId})      [复用]
      ③ deliverToChat(该线简报, { sessionId, autoSend:true })            [复用]
      ④ createChild(...) + attachSession(...) 建节点并挂会话              [复用]
  → refreshBranchTree() ⇒ 分支导图出现 N 条新分支（带维度名）             [复用]
  → 任一步失败 ⇒ data-* 记降级原因 + UI 显示（纪律 19）
```

**CREATE 去向的修正（N2）**：`confirmRoute(DESTINATION.CREATE)` 增加真执行分支 —— 建会话 → 投递 → 记录新 sessionId；失败时 `note` 写明原因（现有文案「（未投递…）」保留为**降级文案**，不再是唯一行为）。

#### 4.2.1 维度表接口（第 1 轮审核整改项 ① · **第 4 轮审核按实现校正**）

新增纯函数模块 `src/logic/split-dimensions.js`（**新增文件**，不改既有模块）。

> 🔴 **第 4 轮审核更正（2026-09-16）**：本节 v1–v3 写的是**设计意图**，与最终实现有三处不符，已按 `src/logic/split-dimensions.js` **实际代码**逐字校正 —— 文档说错比不说更坏（读者会照错的写）。
> ① `plan` 的入参**不是**"已识别好的 key[]"，而是**需求原文 text**（意图识别在函数**内部**做）；
> ② 维度对象除 `{key,label,files,brief}` 外还有 **`stage`**（工序阶段，**排序依据** —— 漏了它就无法解释"A2 力量体系为何排在 A1 世界观之后"）；
> ③ 实际导出 **8 个**，v3 只登记了 3 个。

```js
export const SPLIT_DIMENSIONS   = Object.freeze([ /* 小说 8 条（A1–A8） */ ]);
export const NOVEL_HINTS        = Object.freeze([ /* 判"是不是小说意图"的关键词表 */ ]);
export const GENERIC_DIMENSIONS = Object.freeze([ /* 通用场景的备选维度 */ ]);

export function novelNameOf(text)            { /* 从原文抽《书名》，抽不到返回 "" */ }
export function isNovelIntent(text, extra)   { /* 意图判定（纯） */ }
export function branchTitle(dim, novelName)  { /* → "「A1 世界观」·《我的小说》" */ }
export function plan(text, opts)             { /* → { kind:"novel"|"generic"|"none", dims:[], name, reason } */ }
export function briefOf(dim, text, novelName){ /* → 投递给该分支的简报全文 */ }
```

**`SPLIT_DIMENSIONS` 单条结构（逐字取自源码）**：`{ key, label, stage, files, brief }`
`key` = 稳定标识（进 `data-*` 与节点 id）· `label` = 用户可见名（进分支名/导图标签）· `stage` = 工序阶段（排序）· `files` = 该线可读写的目录边界（进简报）。

**`plan(text, opts)` 语义（校正后）**：

| 入参 | 行为 |
|:-----|:-----|
| `text` = 需求原文 | 函数**内部**做意图识别：`isNovelIntent(text)` ⇒ 取 `SPLIT_DIMENSIONS`，否则取 `GENERIC_DIMENSIONS` |
| `text` 为空 | 返回 `{kind:"none", dims:[]}` —— **不猜、不给"默认三条"**（建空壳分支比"什么都没发生"更糟） |
| `opts.generic` | 显式指定走通用维度 |
| `opts.only` / `opts.max` | 白名单过滤 / 条数上限 |
| **排序** | 先按 `stage`，同 stage **按表内原始序**（用显式下标 Map，**不依赖 `Array#sort` 稳定性**） |
| 识别不到 | 返回 `kind:"none"` + `reason` ⇒ **不自动建**（R6） |

- **通用场景**：同一函数（`plan` 内部分流到 `GENERIC_DIMENSIONS`），**不是**另取 `logic/roles.js`。
- 🔴 **`briefOf` 必须显式带上"技能名 + 目录边界 + 不越界告诫"**（第 4 轮补：v3 的简报只写"你去写世界观"，落到实测是分支不加载技能、8 条线各自从零开始）。现行简报含「技能：加载 `multi-agent-novel-brain`，担任 A{N}」+ 只读/只写边界。
