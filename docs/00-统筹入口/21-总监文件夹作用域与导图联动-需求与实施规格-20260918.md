## 四、状态机（需求 3 / 4 / 10 / 11 的统一解）

```
                  ┌─────────────── 固定 pin = false（默认）───────────────┐
  侧栏点「文件夹/项目」 → setActiveNode(该节点) + dialogOpen=true + 缩回复位
  侧栏点「对话」        → dialogCollapsed = true（缩回，作用域**保留**）
  侧栏点「别处」        → 不动
                  └────────────────────────────────────────────────────┘

                  ┌─────────────── 固定 pin = true ───────────────────────┐
  侧栏点「文件夹」      → 不动（作用域不刷新）
  侧栏点「对话」        → 不动
  弹窗内「作用域下拉」  → 照常生效（I2）
  点 📌 取消固定        → 回到非固定分支（I1）
                  └────────────────────────────────────────────────────┘
```

**判定"文件夹 vs 对话"的依据**（`nav-hook` 现有能力）：
`flattenTree()` 已产出每节点的 `level`（`global` / `project` / `session`）。
⇒ `level === "session"` 判为对话；其余判为文件夹/项目。**不新增猜测逻辑**。

### 8.3 三个技术要点（都是踩过才知道）

| 要点 | 说明 |
|:--|:--|
| **Ctrl+滚轮必须用原生 `addEventListener`** | React 把事件委托挂在 root，而浏览器把 **root 级 wheel 视为 passive** ⇒ `preventDefault()` 在里面**无效**（页面照旧缩放）。要拦住必须自己挂 `{ passive: false }` |
| **`kRef` 不能省** | 「打开时定位」发生在 `doFit()` **之后**的同一 tick，此时闭包里的 `k` 还是**适应前**的值（1.0 而实际 0.3）⇒ 按错误的 k 算滚动位置，会定位到画布**别的地方**（表现为"定位不生效"）。故 `setK` 处一并写 ref |
| **`zoomRef` / `centerOn` 用 ref 传递** | `zoom()` 定义在早退之后、每次渲染都是新引用；写进 effect 依赖会让监听**每帧重挂** |

### 8.4 闸门抓到的真缺陷（TDD：先写判据后实现）

**`filterRowsByScope` 的 depth 重算（`ST-10` 红 → 修 → 绿）**

- 首版实现：父被滤时**递归上找**，但父**保留**时直接取"父的**原始** depth + 1"。
- 反例 `A→B→C→D`（四层），保留集合 `{A,C,D}`：C 的父 B 被滤 ⇒ 往上找到 A ⇒ C.depth = 1 ✅；
  但 D 的父 C **保留** ⇒ 取 C 的**原** depth(2)+1 = **3** ❌（正确是 C 重算后的 1+1 = **2**）。
- 现象：**四层链才暴露，两层链看不出** —— 这正是用户说的"注意多层结构的实现"。
- 修法：两个分支都递归（被滤的父不增层数、保留的父 +1）。
- 🔴 **`ST-16` 用"只看直接父"的坏实现做植入缺陷校准**，证明 `ST-9` 不是空判据。

### 8.7 闸门层的三处修正（前两处是"判据自己坏了"，第三处牵出一个**真产品缺陷**）

#### ① `C-M21` 恒假红 —— 把 `clickSel` 的 boolean 返回值误 push 进记名册

| 项 | 内容 |
|:--|:--|
| 现象 | 真机 `verify-mindmap` 红在 `C-M21 本脚本全部点击，落点均在目标元素子树内`，而上一轮同一套件是 113/113 |
| 真因 | 本轮新增的「上一级」点击写成 `clickMisses.push(await clickSel(...))` —— 而 `clickSel` 返回的是 **boolean**（点中/落空），且它**落空时自己已经 push 过一个对象** |

#### ② 作用域过滤改变了「连线 / 折叠 / 小地图」三段的前提

新增**常驻**诊断 `[血缘前提诊断]`（不是一次性探针），一次跑同时打出数据层与画布层：

```json
{"dataLayer":{"lineage":true,"rows":30,"withParent":2,"edges":2},
 "canvasLayer":{"nodes":2,"depthDist":{"0":2},"drawnEdges":0},
 "scope":{"scoped":"1","total":"2","dropped":"28","up":"0",
          "text":"📁 工作区 a11caaed（项目总监） · 2 节点（滤掉 28）"}}
```

- 血缘**完好**（30 行 / 2 条边），但作用域滤掉 28 行 ⇒ 画布只剩 **2 个互不相干**的节点
  ⇒ 连一条线都画不出、`depth` 全是 0 ⇒ 三段**没有对象可测**（纪律 31：先审口径，再判红）。
- 上一轮绿是因为**那时还没有作用域过滤**（画布直接显示全部 30 行）。

（每次断言 `scope-up` **递增** + `total` **单调不减**）。

#### ③ 连带修掉一个**真产品缺陷**：`scopeUp` / `centeredRef` 跨「关 → 开」残留
