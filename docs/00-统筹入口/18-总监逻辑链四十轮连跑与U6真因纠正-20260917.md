## 四、第 3 步：🔴 U6 真因纠正（本轮最重要的发现）

### 4.1 上一轮的结论

第二十三轮把 8 处「真实鼠标点了没反应」记为 **U6「CDP 合成鼠标在 Electron 下静默丢事件」**，并建了 `el.click()` 兜底。

### 4.2 本轮证伪

复跑 `verify-novel-split` 时注意到一个**异常信号**：**每一个**真实鼠标点击都走了兜底（导图关闭 / 清除 / 确认 / 恢复 / 展开 / 最小化，共 7–8 处）。"偶发丢失"不会**每次都丢** ⇒ 不是偶发。

对照探针（同一页面、同一坐标）：

| 状态 | `visibilityState` | `hasFocus()` | 收到的事件 |
|:-----|:------------------|:-------------|:-----------|
| 建立焦点前 | **`hidden`** | **`true`（骗人）** | 只有 `pointermove` |
| `Page.bringToFront` + `Emulation.setFocusEmulationEnabled` 后 | `visible` | `true` | **`pointerdown` / `mousedown` / `pointermove` / `pointerup` / `mouseup` / `click` 全部送达** |

⇒ **真因 = 漏装了可见性前提**。`hidden` 时 CDP 的 `mousePressed` / `mouseReleased` 被当成**"激活窗口"的那一下**整条吞掉，`mouseMoved` 照常送达。

> 🔴 **`document.hasFocus()` 在 `hidden` 时仍为 `true`** —— 这是**骗人的代理指标**。第二十三轮用它反推，得出了错误结论（纪律 86 里写着"窗口不可见已被否定"）。
> 🔴 **第二十三轮的旧结论已就地更正并留痕**（不删），见锚点 §八 纪律 86 的补充说明。

### 4.3 处置

- **新纪律 90**：真实鼠标失效第一查 `visibilityState`，只认它
- **前提推到 11 个真机套件**（`verify-flow` / `verify-mindmap` / `verify-design-studio` / `verify-walk` / `verify-register-gate` / `verify-v21` / `verify-v22` / `verify-orchestrate` / `verify-v17-sync` / `cdp-mouse` / `verify-director-logic`），`verify-novel-split` 单独接入并登记 **`NS-0v`**
- **不成立时判 INVALID 且早退**（纪律 24：测不了 ≠ 产品坏），避免消耗用户数据（纪律 82）
- **校准**：`DSH_FOCUS_CALIBRATE=hidden` 模拟遮挡 ⇒ **恰红 `NS-0v` 一条 + 早退零消耗**，日志里 `hasFocus: true` 与 `visibility: hidden` **并存** —— 完美复现那个骗人的代理指标

### 4.4 效果（同一套 `verify-novel-split`）

| | 修前 | 修后 |
|:--|:--|:--|
| 断言 | 95–99/107，W 段拖动 **0 位移**（947,82 → 947,82） | **108/108**，W 段 **947,82 → 605,408** 真动 |
| 兜底依赖 | 每轮 **8 处**全走 `el.click()` | **0 处** |
| 耗时 | 97s | **16s** |

> ⚠️ **未分离**：是 `setFocusEmulationEnabled` 改写了 `visibilityState`，还是 `bringToFront` 在特定窗口状态下才生效 —— 记为 **U9**。**不影响处置**：前提断言只依赖可直读的状态量，不依赖归因。
