## 一、审核通用原则

### 1.1 审核定位
- 审核是 AI 任务闭环的强制环节，**禁止跳过**
- 前置审核：文档初稿完成后、落地执行前
- 后置审核：执行产出完成后、交付用户前

### 1.2 审核类型
| 类型 | 触发时机 | 审核对象 | 审核标准 |
|:-----|:---------|:---------|:---------|
| 前置审核 | 文档完成后、执行前 | 设计文档/方案/任务清单 | §二 7维度 |
| 后置审核 | 执行完成后、交付前 | 代码/文档/设计等交付物 | §三 6维度 |

### 1.3 审核流程
```
接收审核对象 → 按检查清单逐项校验 → 汇总结果
  ├─ 全部通过 → 输出审核通过标记 → 进入下一环节
  └─ 存在不通过项 → 输出结构化整改清单 → 退回整改 → 复审循环
```

## 二、前置审核标准（7维度）

> 适用对象：设计文档、技术方案、任务清单、开发文档初稿

### 维度1：需求满足度
| 检查项 | 通过标准 |
|:-------|:---------|
| 核心诉求覆盖 | 用户必做项100%覆盖，无遗漏 |
| 可选诉求处理 | 可选项明确标注「已实现/未实现/延后」，无模糊 |
| 约束条件遵守 | 用户限制条件、边界、禁止项全部遵守 |
| 隐含诉求识别 | 用户未明说但合理推导的隐含需求已识别并处理 |

### 维度2：逻辑完整性
| 检查项 | 通过标准 |
|:-------|:---------|
| 逻辑漏洞 | 无逻辑断点、循环依赖、死分支 |
| 异常场景 | 异常路径、错误处理、降级方案已考虑 |
| 边界条件 | 边界值、极值、空值、并发场景已覆盖 |
| 状态流转 | 状态机完整，无非法状态跳转 |

### 维度3：函数/接口完整性
| 检查项 | 通过标准 |
|:-------|:---------|
| 函数定义 | 所有函数有明确入参、出参、返回值类型 |
| 参数流转 | 参数在调用链中无丢失、无类型不匹配 |
| 接口契约 | 接口输入输出格式明确，错误码定义完整 |
| 依赖关系 | 模块依赖、函数调用关系清晰，无循环依赖 |

### 维度4：项目规范符合性
| 检查项 | 通过标准 |
|:-------|:---------|
| 架构规范 | 符合项目分层架构，无跨层违规调用 |
| 编码规范 | 命名、注释、目录结构符合项目规范 |
| 文档规范 | 文档路径、命名、格式符合文档分类标准 |
| 业务约束 | 不脱离项目业务框架，不引入项目外无关技术 |

### 维度5：方案合理性
| 检查项 | 通过标准 |
|:-------|:---------|
| 多方案对比 | 推导了2~N个可行方案，评估了优缺点 |
| 最优选择 | 选定方案有明确理由，非随意选择 |
| 风险评估 | 方案风险点已识别，有应对措施 |
| 可执行性 | 方案可拆解为可执行原子任务，无空泛描述 |

### 维度6：任务清单可执行性
| 检查项 | 通过标准 |
|:-------|:---------|
| 原子任务 | 任务拆解到可独立执行的粒度，无过大任务 |
| 输入输出 | 每个任务有明确输入、输出、验收标准 |
| 依赖关系 | 任务间依赖关系清晰，执行顺序合理 |
| 责任人 | 每个任务明确责任人（AI/用户/外部） |

### 维度7：索引与引用完整性
| 检查项 | 通过标准 |
|:-------|:---------|
| 文档内索引 | 文档内有完善索引/目录，可快速定位 |
| 外部引用 | 引用的外部文档/规范路径正确，无断链 |
| 无冗余 | 文档内容无重复、无冗余章节，只含必要部分 |
| 可追溯 | 决策、方案有来源依据，可追溯到用户输入或规范文档 |

## 三、后置审核标准（6维度）

> 适用对象：代码、文档、设计方案等最终交付物

### 维度1：交付物与文档一致性
| 检查项 | 通过标准 |
|:-------|:---------|
| 无私自改动 | 交付物与前置审核通过的文档一致，无私自变更 |
| 变更可追溯 | 执行中如有文档调整，已回退重审并记录 |
| 范围一致 | 交付物范围与任务清单一致，无遗漏/无超范围 |

### 维度2：核心诉求达成度
| 检查项 | 通过标准 |
|:-------|:---------|
| 必做项达成 | 用户必做项100%实现并验证 |
| 可选项处理 | 可选项按文档约定处理，状态明确 |
| 功能验证 | 核心功能可运行/可验证，非纸面实现 |
| 用户体验 | 输出符合用户预期，无理解偏差导致的方向错误 |

### 维度3：缺陷与风险
| 检查项 | 通过标准 |
|:-------|:---------|
| 无新增Bug | 执行未引入新的逻辑错误、回归问题 |
| 运行风险 | 参数流转、函数调用无运行时风险 |
| 安全风险 | 无硬编码密钥、注入风险、权限越界 |
| 已知问题 | 遗留问题明确记录，有后续计划 |

### 维度4：边界与异常覆盖
| 检查项 | 通过标准 |
|:-------|:---------|
| 边界case | 边界值、极值、空值场景已处理 |
| 异常路径 | 异常捕获、错误处理、降级逻辑完整 |
| 并发场景 | 如涉及并发，竞态条件、死锁已考虑 |
| 兼容性 | 版本兼容、数据迁移策略明确（如涉及） |

### 维度5：项目规范符合性
| 检查项 | 通过标准 |
|:-------|:---------|
| 代码规范 | 命名、注释、格式符合编码规范 |
| 文档规范 | 交付文档路径、命名、格式符合规范 |
| 架构规范 | 符合分层架构，无跨层违规 |
| 业务约束 | 不脱离项目业务框架 |

### 维度6：归档与同步
| 检查项 | 通过标准 |
|:-------|:---------|
| 索引更新 | 05-项目大索引已同步更新新增/修改文档 |
| 任务清单更新 | 03-待完成/04-已完成任务清单状态已同步 |
| 工作快照更新 | 06-工作快照已记录当前进度和下一步 |
| 文档分类 | 文档按「执行中/正在使用/使用完成」正确分类 |

## 四、审核输出格式

### 4.1 审核通过
```
【前置审核通过】
审核时间：{时间}
审核维度：7/7 全部通过
备注：{可选补充说明}
```

```
【后置审核通过，任务闭环】
审核时间：{时间}
审核维度：6/6 全部通过
交付物：{交付物清单}
归档记录：{索引/任务清单/快照已更新}
```

### 4.2 审核不通过（结构化整改清单）
```
【审核不通过】
审核时间：{时间}
不通过维度：{维度编号+名称}

整改清单：
| # | 问题位置 | 问题描述 | 整改建议 | 责任人 | 优先级 |
|:--|:---------|:---------|:---------|:-------|:-------|
| 1 | {文件/章节} | {具体问题} | {怎么改} | {AI/用户} | {高/中/低} |

复审要求：整改完成后重新提交审核，直到全部通过
```

## 五、审核不通过处理流程

```
审核不通过 → 输出整改清单
  ├─ 文档类问题 → 修改文档 → 重新前置审核
  ├─ 执行类问题 → 修改交付物 → 重新后置审核
  ├─ 需求理解偏差 → 回到解表达步骤 → 重新走全流程
  └─ 方案不可行 → 回到推导处理方案步骤 → 重新选方案

循环直到审核通过，禁止带病进入下一环节
```

## 六、审核检查清单（可直接复用）

### 前置审核检查清单
- [ ] 维度1：用户必做项100%覆盖，可选/限制/隐含诉求已处理
- [ ] 维度2：无逻辑漏洞，异常/边界/状态流转完整
- [ ] 维度3：函数入参出参完整，参数流转无丢失，接口契约明确
- [ ] 维度4：符合架构/编码/文档/业务规范，不脱离项目框架
- [ ] 维度5：多方案对比，最优选择有理由，风险已评估
- [ ] 维度6：任务拆解到原子粒度，输入输出/依赖/责任人明确
- [ ] 维度7：文档内有索引，外部引用无断链，无冗余，可追溯

### 后置审核检查清单
- [ ] 维度1：交付物与审核通过的文档一致，无私自改动
- [ ] 维度2：核心诉求100%达成，功能可验证，符合用户预期
- [ ] 维度3：无新增Bug，无运行/安全风险，遗留问题已记录
- [ ] 维度4：边界/异常/并发/兼容性场景已覆盖
- [ ] 维度5：符合代码/文档/架构/业务规范
- [ ] 维度6：索引/任务清单/工作快照已同步更新，文档分类正确
