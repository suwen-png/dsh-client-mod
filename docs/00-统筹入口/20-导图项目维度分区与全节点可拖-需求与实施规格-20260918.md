### 3.1 模块分工（**三个单一职责**）

| 模块 | 职责 | 关键约束 |
|:---|:---|:---|

### 3.2 R3 父居中：后序遍历

```
walk(s, depth):
  row.y = 0                        # 占位，后序回填
  rows.push(row)                   # 父先入列 ⇒ 渲染序与旧版逐字节一致
  kidYs = [ walk(kid, depth+1) for kid in kids ]   # 环内回 undefined ⇒ 滤掉
  row.y = (kidYs[0] + kidYs[last]) / 2   if kidYs
          else  y0 + (leafSlot++) * dy
  return row.y
```

**依据**：`docs/10-架构设计/思维导图驱动的多分支对话管理系统-统一方案文档.md` §2.3 第 140 行原文
「布局算法：后序遍历，叶子分配纵向槽位，**父节点居中于子节点**」⇒ R3 **不是新需求**，
是"实现没跟上设计"（纪律 79 的形态之一）。

### 3.3 R1/R2 分区：两套 y 的分工

```
buildGroups(rows, opts)  # rows = **自动布局行**
  1. 归集  作品 → 维度 → 行
  2. 排序  作品按规模降序（兜底桶恒最后）；维度按自然序（未分流恒最后）
  3. 分配  shift = cursor - minY     # cursor = 分区槽位起点
           ny    = y + shift         # 整组平移，组内相对 y 顺序保持
```

🔴 **契约**：行数守恒 · 组内相对 y 顺序保持 · 不修改入参 · 输出新对象。

### 3.4 🔴 顺序铁律（**本需求最贵的一条**）

```
❌ 错：applyUserPos(baseRows, posMap) → buildGroups(placedRows)      # 先并位置、再分区
✅ 对：buildGroups(baseRows)         → applyUserPos(gres.rows, posMap) # 先分区、再叠加
```

**为什么**（机理详见 `mindmap-group.js` 的 `applyUserPos()` 头注）：

`shift = cursor - minY` 中 `minY` 取**组内最小 y**。若用户位置先并进去：

| 形态 | 后果 |
|:---|:---|
| 分区内**只有一行**（或用户拖的正是 `minY` 那行） | `shift = cursor - y` ⇒ `ny = cursor` ⇒ **用户拖到哪都被拉回分区槽位** |
| 分区内多行 | 拖一行改变 `minY` ⇒ `shift` 变化 ⇒ **同组其他成员全部跟着平移**（拖一个动一群） |

**真机症状与真因毫无表面关联**：X 与 Y 走的是两条完全不同的路径（X 分组不动、Y 被分组吸收）
⇒ 表现为"**拖拽只响应横向**"，看起来像拖拽事件链坏了。
