## §1 目标与验收定义

### 1.1 目标（单句）

**以小说项目《墟海》为唯一测试内容，跑通「任意入口进消息 → 总监判归属 → 复用而非新建 → 转发到目标对话 → 目标总监理解 + 语言整理 → 下发执行 → 产出回流 → 全链消息一致且可持续」这一条端到端链路，并使每一步都有可证伪读数与用户可感知证据。**

### 1.2 「测通」的三层可证伪定义（三层都过才算通）

| 层 | 定义 | 判据形态 | 当前状态 |
|:--:|:---|:---|:---|
| **L1 机制通** | 每个环节有产品落点、有纯函数、有离线单测 | 离线套件 `PASS / FAIL=0` | 大部分已具备，**N1/N2/N3/N5 无** |
| **L2 链路通** | 真机上完整跑一遍，每环节读数正确 | 真机闸门全绿 + 零跳过 | `verify-novel-split` **108/108**（已通）；`verify-director-logic` **28/29**（唯一红 = U10） |
| **L3 人可感知** | 用户不看日志、只点界面即可确认每环节 | **截图 + 界面读数**（纪律 57） | 🔴 **未建立**（本规格首要补项，见 N8） |

> 🔴 **L2 绿 ≠ L3 通**。历史上多次出现"闸门全绿但用户看不见/用不上"（16 号文 D4/D5/D6）。

### 1.3 不做什么（边界 · 越界即错）

1. **不改** `workspace/**`（宿主产物，`git` 不纳管，唯一回滚点 `snapshots/host-b6-20260911-before-patch`）；宿主侧改动须用户显式授权（台账 `T-PLUG-005-B6`）。

## §3 目标链路与协议（AI 实现依据）

### 3.1 链路（7 环节 · 每环节必须有产品落点与读数）

```
[0] 用户输入（任意节点：总监页 / 总监弹窗 / 原生 composer）
        │
        ▼
[1] 归属判定（新）        ← 输入文本 → {噪声? → 不建; else → 维度集 D + 置信 + 理由}
        │
        ├─ 无归属（未命中 / 噪声）→ 如实报"未识别到可执行需求"，**不建分支**（已有行为，保留）
        │
        ▼
[2] 复用决策（已有）      ← (作品名, 维度key) 命中存活索引 ⇒ reuse；否则 create
        │
        ▼
[3] 路由决策（扩候选集）  ← 目标 == 当前维度 ? 就地(local) : 转发（TRANSFER/DIRECT/CREATE）
        │
        ▼
[4] 目标总监接收（新）    ← 目标分支写入一条"接收凭证"消息（谁转来、何时、轮次）
        │
        ▼
[5] 理解 + 语言整理（升级）← organize() 产出「AI 可执行规格」（非人类摘要）
        │
        ▼
[6] 下发执行（已有）      ← briefOf() 简报 + 投递（已有通道）
        │
        ▼
[7] 产出回流 + 血缘一致（新）← 回收 → 归档为档案 + 同步上下游摘要（见 §3.4）
```

### 3.2 消息信封协议（**新增契约** · 只增字段）

现有 `appendDirectorMessage(nodeId, { role, text, parsed })`。**新增可选字段**（不改既有字段语义）：

| 字段 | 类型 | 语义 | 缺省 |
|:---|:---|:---|:---|
| `env` | `object` | 信封（见下） | 无 ⇒ 退化为旧行为（**保证既有调用点零改动可跑**） |
| `env.id` | string | 消息唯一 id（幂等键） | 自动生成 |
| `env.from` | string | 来源 nodeId | `null` |
| `env.to` | string | 目标 nodeId | `null` |
| `env.via` | `"local"\|"transfer"\|"direct"\|"create"` | 投递通道 | `"local"` |
| `env.round` | number | 本血缘内的轮次（单调递增） | `0` |
| `env.root` | string | 血缘根 nodeId（**一致性范围界定**） | 自身 |
| `env.parent` | string | 上游 nodeId（血缘父） | `null` |
| `env.ref` | string | 被转发的源消息 id（可追溯） | `null` |
| `env.cause` | string | 可读原因（降级 / 未命中 / 噪声 时必须非空） | `""` |

**约束**：`env` 全部可选；**不得**把 `env` 塞进 `text`（会污染语言整理与正则判据）。

### 3.3 归属判定协议（N1 核心 · 纯函数）

**输出契约**（`planAttribution(text, opts)` → 纯函数，禁 DOM / 禁 store / 禁时钟）：

```
{
  kind: "novel" | "generic" | "noise" | "none",
  dims: Array<{key,label,reason,score}>,   // 命中的维度（可能 1 个）
  reason: string,                          // 人类+AI 双可读的一句
  confidence: number,                      // 0~1
  ambiguous: boolean,                      // 命中多维度且分差 < 阈值 ⇒ true
  extent: "full" | "partial"               // full=全量派发(显式要求) / partial=局部
}
```

**判定规则（可解释、可测、非黑箱）**：

1. **前置**：先过 `noiseReasonOf()`；命中 ⇒ `kind="noise"`、`dims=[]`，**不建任何分支**（保留现状）。
2. **维度词表**：每维度的判定词必须**从 `SPLIT_DIMENSIONS` 派生**（`files` 目录名 + `brief` 关键词 + `label`），**禁止另立一份词表**（两份必漂移）。
3. **打分**：命中词数 × 权重；`stage` 相邻维度（如 A2↔A3）命中重叠时**降权**而非叠加。
4. **多维度**：允许返回多个维度（用户一句话可含"世界观 + 剧情"）。**不得**因为"保险"而返回全部 8 维。
5. **显式全量**：仅当文本含全量信号（"全流程 / 整部 / 从设定到正文 / 所有维度"）⇒ `extent="full"` 返回 8 维。
6. **歧义**：`ambiguous=true` 时**不得静默选一个**——须走 §3.3.1 的确认通道。
7. **零命中**：`kind="generic"`，走通用三段（`GENERIC_DIMENSIONS`），保留现状（**不得**判噪声）。

#### 3.3.1 归属歧义 / 误判的处置（**我补的，用户未提**）

- `ambiguous=true` ⇒ 在总监页给出**候选列表 + 各自理由**，由用户一键确认（复用 `routing.js` 的"待确认，不静默分发"原则）。
- 误判纠正入口：消息上提供「不是该对话」→ 重投到用户指定维度（**写 `env.ref` 指回原消息**，可追溯）。
- **超时/未确认** ⇒ 不投递，**如实标记"待确认"**（不得默认投递，纪律 54）。

### 3.4 血缘消息一致性协议（N3 · **我补的**）

用户原话：「同一个分支上下游的总监消息需要是一致的」。落地含义（三条，全部可测）：

| 规则 | 内容 | 可测判据 |
|:---|:---|:---|
| **R1 同一事实同源** | 同一条用户需求的文本、作品名、维度集，在**上游消息**与**下游消息**里必须**逐字同源**（同一变量来源，不得各自格式化） | 上下游两条消息中该字段 `===` 相等 |
| **R2 上游可见下游摘要** | 上游节点消息列表含下游产出**摘要行**（`env.parent` 指回），而不是必须点进下游才看得到 | 上游消息含 `data-said`/摘要且非空 |
| **R3 下游可见上游约束** | 下游简报含上游的**约束/边界**（`briefOf` 的 `bound` 段），不得下游自造边界 | 下游简报含上游 `bound` 逐字 |
| **R4 一致性范围 = 血缘** | 一致性只限 `env.root` 之内；**兄弟枝不共享** | 兄弟枝不得读到彼此消息（负对照） |

> ⚠️ `logic/branch-focus.js` 的 `upstreamChain()` **只管视图聚焦，不管消息语义** —— 不得引用它当"已实现一致性"。

### 3.5 对话持续性协议（N5 · **我补的**）

用户原话：「**总监对话的持续性一直没有看到**」。拆为三件可测的事：

| # | 问题 | 判据 |
|:--:|:---|:---|
| P1 | **触点窄**：只有 4 个动作写消息（统筹/派发/回收/运行总监链）；「登记为流转」不写 | 用户在总监页做**任一**产生结果的动作 ⇒ 消息数 **净增 ≥1**；若不写，界面**显式标明**（`T-PLUG-050` 二选一，须用户裁定） |
| P2 | **桶隔离导致"切会话即空"**：消息按作用域会话分桶，切一个会话=切一个桶 | 进入任意**曾有消息**的会话 ⇒ 该会话消息**可见且条数 = 库内条数**（不得 0） |
| P3 | **跨轮上下文**：新一轮派发是否带上一轮结论 | 第 N 轮简报含第 N−1 轮**结论摘要**（`session-dossier` 的总结），且**逐字同源** |

### N1 🔴 归属判定缺失：命中小说即派全部 8 维

- **判据**：
  1. `planAttribution("补充第三章剧情支线")` ⇒ `dims.length === 1` 且 `dims[0].key === "plot"`。

- **反例**：「全流程」判据若写成"含『全』字" ⇒ 「全局变量改名」会被误判 full ⇒ **必须用词组**且**加负对照**。
- **依赖**：`T-PLUG-058`（冷启动复用失效会掩盖"不新建"的效果，**须同轮处理或至少如实打印降级**）。

### N2 🔴 跨维度转发未打通：**两条平行分流通道未合并**

> ⚠️ **精确前提（先证后断，纪律 23）**：投递链**不是零基础**。
> `DirectorDialog.js#onConfirmRoute`（源码 617–649 行）**已实现**「按目标会话投递」：
> `targetSession = scopeKeyOf(targetNode.id, targetNode)`（走 `store/hierarchy.js` 单一真相源）、
> 目标是文件夹/全局时**如实告知不投递**（不静默改发当前会话）、`DIRECT` 才 `autoSend`。
> ⇒ **不得把它当"未接线"重写**。真实缺口是**候选集语义**与**两条通道未合并**。

- **现象**：在 A3 分支里输入属于 A5 的内容，**不会转发到 A5**（也**判不出**"这属于 A5"）。
- **根因（两条并行通道，互不识别）**：
  | 通道 | 入口 | 判定依据 | 产物 |
  |:---|:---|:---|:---|
  | **A · 维度派发** | `DirectorPage`「派发」→ `plan()` | **仅判"是不是小说"** ⇒ 全 8 维 | `dispatchBranches()` 建/复用 **8 条** |
  | **B · 单点路由** | `DirectorDialog` 输入 → `route()` | `scoreNodes()` 候选 = **层级树拍平节点**（`level: "project"｜"session"`） | 投递到**1 个**目标会话 |
  ⇒ 通道 B **认不出维度**（A1–A8 不是层级树节点），通道 A **不认内容**（无单维命中）。二者无交集。
- **落点**：
  1. `route()` 的 `ctx.nodes` **允许携带维度节点**（`{id, name, level:"dimension", dimKey}`）——**只增不改**既有字段与既有行为；
  2. `suggestDestination()` 增规则：命中 `level==="dimension"` 且 `nodeId === ctx.currentNodeId` ⇒ 返回**新增去向** `DESTINATION.LOCAL = "local"`（就地处理，不投递）；命中其他维度 ⇒ `TRANSFER`；
  3. `onConfirmRoute` 的 `TRANSFER` 分支：目标 = 该维度的**分支会话**（经 `planReuse().picked` 命中，**不另建**），投递时写 `env.via="transfer"` + `env.ref`（源消息 id）；
  4. `DirectorPage`「派发」按钮在 `planAttribution()` 返回 `extent="partial"` 时，**只派命中的维度**（N1 联动）。
- **判据**：
  1. 当前在 A3，输入 A3 话题 ⇒ `destination === "local"`，**零跨会话投递**（负对照：无新增消息到其他维度）。
  2. 当前在 A3，输入 A5 话题（正文写作要求）⇒ `destination === "transfer"`，且**目标 = A5 分支会话**（用 `planReuse()` 的 `picked` 对账）。
  3. 转发后**目标分支**出现一条 `env.via="transfer"` 消息，且 `env.ref` 指回源消息（可追溯）。
  4. 无匹配维度 ⇒ `destination === "create"`（保留既有语义）。
- **反例**：若判据只测"有流转"，则**任何投递**都能通过 ⇒ 必须断言**目标会话 id** 与**通道值**（`NS-4i` 同型口径）。
- **依赖**：`DESTINATION` 新增 `"local"` ⇒ **冻结契约只许新增**，允许；但须全仓 `grep DESTINATION` 确认无 `switch` 穷举处会漏分支。

### N3 🔴 上下游消息一致性无机制

### N4 🟡 语言整理未产出「AI 可执行规格」
