### 1.2 关键架构判断（自问自答，CP0/CP1）
**问：宿主无 fs、`callLocalModel` 是死代码，凭什么说「模型语义判断」今天就能做？**
答：插件**早已在驱动带活模型的宿主会话**——`director-dispatch.js` 用 `sendToSession(sessionId, brief)` 给分支会话投消息，宿主自己的大模型就会回复；`findSummary()` / `stateOfSummary()` 读回复。也就是说「调模型」这件事**不需要插件自己有 fs 或本地模型**：
> **开/复用一个专门的「L0 路由会话」→ 把需求 + 一份路由提示词投给它 → 等它回复一段 JSON 决策 → 插件解析 JSON 后只做执行（建分支/投简报/画节点）。**

这正好满足用户「模型判断、插件执行」的分工：判断者是宿主会话里的模型（已可用），插件是执行器。
- **降级路径**：模型没回 / 返回非 JSON / QUOTA / 超时 → 回落到现有 `plan()` + `planAttribution()` 关键词规则。**规则版从「主路径」降级为「离线兜底」**，且完整保留（它是唯一可离线测、可离线对账的判据，纪律 126 同族：判断与执行分离后，规则版就是判断层的可替换降级实现）。
- **不许造假**：模型版路由必须把 `routingSource`（`"model"` / `"rule-fallback"`）如实写进台账与读数，规则降级时必须带原因（纪律 19）。
