## 一、核心原则

1. **必读集合优先**：所有需求类型启动前，必须先加载项目必读集合（5份）：总统筹入口→AI对话执行约束规范→AI任务审核标准通用模板→本文档→项目大索引。未完成不进入业务处理
2. **需求驱动读取**：AI 先判断用户需求属于哪种类型，再按对应类型读取文档集，禁止全量加载 docs/
3. **关键词识别**：通过用户输入中的关键词匹配需求类型，模糊需求默认走「项目接手/速览」
4. **三层读取集**：每种需求类型定义「必读」「按需」「禁止」三层
5. **固定入口顺序**：所有需求类型都必须先读 `00-总统筹入口文档.md`，再按类型读取
6. **读取后校验**：任务完成前自检是否遗漏必读文档、是否多读无关文档

## 一·补、大文档局部读取指南（强制）

以下大文档禁止全量加载，必须按模块/章节局部读取（使用Read工具offset/limit参数）：

| 大文档 | 路径 | 大小 | 局部读取方法 |
|:-------|:-----|:----:|:-------------|
| 脚本统一索引清单 | `00-统筹入口/modules/hd_脚本统一索引清单.md` | ~15,000 tok | 先读§一整体统计+§二需求精准定位，再按脚本路径关键词Ctrl+F定位到具体脚本章节，只读该章节 |
| 08-技能作用记录（完整版） | `00-统筹入口/08-技能作用记录.md` | ~32,000 tok | **优先读摘要版**（9,165 tok），需要详细说明时再按技能名定位完整版对应章节 |
| 项目通用配置（完整版） | `99-个人沟通/项目通用配置.md` | ~24,000 tok | **优先读摘要版**（4,972 tok），需要详细规则时再按章节标题定位完整版对应章节 |

**局部读取操作步骤**：
1. 先读文档开头的目录/索引部分（前500 tokens）
2. 根据需求关键词定位到目标章节
3. 使用Read工具的offset/limit参数只读目标章节
4. 禁止一次性Read整个大文档

## 四、需求类型判断流程（AI强制执行）

```
第0步：加载必读集合（5份，所有类型强制）
  总统筹入口 → AI对话执行约束规范 → AI任务审核标准通用模板 → 本文档 → 项目大索引
第1步：读取用户输入，提取关键词
第2步：匹配需求类型总览表（第二节）
  ├─ 精确匹配（用户明确提到"写代码"/"部署"等）→ 直接确定类型
  ├─ 关键词匹配（多个关键词命中）→ 取命中数最多的类型
  └─ 无法匹配 → 默认走「类型1：项目接手/速览」
第3步：按对应类型的读取顺序，依次读取文档
  ├─ 先读 00-总统筹入口文档.md（所有类型强制，已在第0步加载）
  ├─ 再读该类型的「必读」文档（按顺序）
  └─ 最后按需读取「按需」文档
第4步：任务执行（遵循AI对话执行约束规范的10步流程）
第5步：读取校验（第五节）
```
