## 三、缺陷详情

### D7 · 总监不分辨无意义输入

`plan()` 的分支只有三态：命中小说意图 → A1–A8；未命中 → **通用三段兜底**；空文本 → none。
"未命中"把**两种完全不同的东西**归到了一起：**真·通用任务**（"帮我写一个爬虫脚本"）与**噪声**（"哈哈哈哈"）。
⇒ 7/8 噪声被当成通用任务，各建 3 个空壳分支（真机：会话 +3）。

**为什么必须修**：空壳分支**进导图**、**占分流索引**、**各投一份简报**（真机日志可见投了 3 次 `__directChatSubmit`）。
用户看到导图多出 3 个不知道干什么的框 —— 与第 19 批"一百多个会话"是**同型的污染**。

### D8 · 总监没有"对语言的整理"

| 环节 | 现状 | 缺口 |
|:-----|:-----|:-----|
| 派发消息 | `【总监派发】来源：原生输入框 · 场景：小说（A1–A8 分工）` + 8 行标签 | **没有"我把你的需求理解成了什么"** —— 用户原话只作为 `需求原文：` 原样转发给分支 |
| 回收消息 | `【回收产出】总裁定：…` + 8 行 × 「产出未读到 —— 宿主本轮运行失败：Insufficient Balance（QUOTA 402）」 | **同一个原因重复 8 遍**，不归纳、不分阶段、无整体判断 |
| 派发简报 | `需求原文：` + 原文**原样**（含噪声行、冗余、多段） | 未去噪、未归一、未结构化 |

用户原话「**总监对语言的整理，对于文字的描述**」正指这三处。

### D9 · 总监不做"项目把控"

`briefOf()` 的 `proj` 段写的是：
> 项目根：`D:\workspace\novels\墟海`
> 落点：先读项目根下的清单文件（`project.yaml` / `README.md` / `_BRAIN.md`，存在即读）确定本维度的**实际分区**…

**这句话把"把控项目"推给了分支**。总监自己**一个文件都没看**。
⇒ 8 个分支各自去摸索项目结构，总监对"这个项目现在有什么、到哪一步了"**零认知**。

### D10 · 审计消息写入后界面滞后一条

`DirectorPage.splitBranchesInner()` 的顺序：

```
setSplitInfo({...})            // ① 报账
await refreshBranchTree()      // ② 刷血缘
await refresh()                // ③ 刷面板（含消息列表）—— 此刻库里还没有新消息
lines = …                      // ④ 生成文本
await appendDirectorMessage(…) // ⑤ 写审计消息 —— 写完了，但没人再刷
```

`collectOutputs()` 同型。⇒ **界面永远要等下一次动作才看见上一次的结果**。
