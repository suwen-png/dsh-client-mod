### 其它必须知道的约束

| 约束 | 说明 |
|:-----|:-----|
| 构建模板字符串内**禁用反引号** | 会在构建期被当模板字面量求值而报错 |
| 写盘必须显式 LF | Windows 文本模式会把 LF 转 CRLF，导致 `git diff --numstat` 插删数 ≈ 文件行数（假重写） |
| 宿主 `conversation.view` 是 **list slot** | `tabs.length > 1` 才显示 tab 环；同族先例 `dsh-client-ui-trajectory` |
| 宿主 **无 React 错误边界** | 任一层抛错即卸载整棵 Shell 根 ⇒ 四个浮层全灭。故每层裹 `SafeLayer` |
| 持久化的"打开态"是**自锁死**放大器 | open 标志落库 ⇒ 首帧渲染缺陷会**每次重启必现**。凡 `open && 数据为 null` 的组合必须判空 |
| `ELECTRON_RUN_AS_NODE` | 启动 Harness 必须 `env -u` 清掉该变量与 `NODE_OPTIONS` |
| Harness 端口每次启动变化 | localStorage 按 **origin（含端口）** 分区 ⇒ 主存有丢失风险 ⇒ 设计图有 IndexedDB 冷备与自动恢复 |
| **重装后必须重启 Harness** | 插件在 boot 时装载。**单实例锁**会让"再启动一次"静默失败并复用旧进程（旧进程仍监听 9222，看起来像新实例）⇒ 必须先确认 `tasklist` 为 0、`netstat :9222` 已释放，再启动。**判据：新进程端口号与旧的不同** |
| **结束 Harness 的命令** | Git Bash 会把 `/F` 当路径转换 ⇒ 必须 `MSYS_NO_PATHCONV=1 taskkill /F /IM "DeepSeek Harness.exe"`（`taskkill //F` 也不行） |
| 原生窗口控件是**操作系统图层** | `z-index` 对它**完全无效** ⇒ 靠提高层级"压住它"是死路；只能让位（`util/safe-area.js`，见板块 E5） |
| **安全区断言必须防"平凡真"** | 若某环境的 `inset === 0`，"元素不越界"对任何元素都成立 ⇒ 等于没测。故 C15 先断言 `inset > 0 && boundary < 视口宽`（"本环境确实存在原生覆盖层"） |
| 🔴 产物 `inject` **必须**含 `"sessions"` | `ctx.<service>` 是 Proxy 陷阱：未声明 inject 的服务**读一下就抛错**，而外层 `try/catch` 会把它变成**静默降级**（血缘整条丢失，UI 只显示 `data-source=none` 且不给原因）。改 `build.mjs` 的 `inject` 后**必须重跑** `test-mindmap-logic.mjs` 的 F 段（产物自证 `inject` 含 sessions） |
| 读宿主服务一律**两级**读取 | `ctx.sessions`（要求 inject）→ `ctx.get("sessions")`（不要求）→ 再把失败原因写进 `diag` 并**显示在 UI 上**。**降级可以，无声不行** |

| **"量一次就存下来"的位置** | 只监听 `window.resize` 后存下 `bottom` | composer 在**空会话是居中大输入区**、有消息后**落到底部**（实测 top 287 → 690）；这一变**既无 resize 事件、也不改根元素盒尺寸** ⇒ 接不到 ⇒ 存的 bottom 永久过期（实测漂到 y=172，压住 R2.5/R2）。⇒ 加 500ms 轮询 + 只在值变化时 setState；断言用「与**当前**几何一致」（同一条公式算期望值，差 ≤2px）+ **跟随性正负对照**（挪一方 ⇒ 另一方必须跟着挪 ⇒ 恢复后回原值）（台账 #63/#66） |

| **有状态扫描器静默失步** | 用逐字符状态机剥注释，再扫 888KB 产物 | 产物里有正则字面量（`/["']/`），状态机遇引号"进入字符串"并一路吞到很远 ⇒ 之后**所有注释都被当代码** ⇒ 负断言拿一条纯注释判红。**失步比漏剥危险得多：漏剥只影响一条，失步让全文件的扫描断言一起假绿**。⇒ 改成**行级过滤**（无状态、不会失步；本项目块注释体一律以 `*` 开头，充分）（台账 #67） |

## 八、改动纪律（照做就不会重蹈覆辙）

1. **先跑基线校验**，确认没在读一份过期的"现状"。
2. **文档先行**：涉及界面改动的，先改设计稿（板块 D / **板块 E**），再改代码。
3. **改代码时同步标注**：文件头「这份文件在整体里的位置」+ 修复点三元组注释。
4. **每次改完必跑**：§六 的 1/1b/2/3/4 → 构建 → 安装（回读）→ **重启 Harness** → 5 → 6。
5. **改动视觉的，必须截图**。逻辑断言全绿 ≠ 界面可用 —— §七 7.2 的 5 个缺陷 + 7.3 的 6 个视觉缺陷，**全部**是在"逻辑全绿"状态下靠渲染截图才发现的。设计稿这类 HTML 也一样（div 配平 + 零反引号全绿，却有两处文本被裁）。
6. **新增闸门必须正负对照校准**（台账规则 F）。
7. **改完同步本文件 + 重新封存指纹**（`--write`）。
8. **不要新开版本号**（用户明确要求：不想再开一版）。基线演进 = 更新本文件 + 重新封存，**不新建 V17 文档**。
9. 🔴 **注释一律不要写在 `import` 子句里**（包括行内注释）。构建器与 lint 检查器**都**曾因此出事故，且都是"产物语法合法、行为静默错"这一类最难查的形态。要写注释就写在 import **语句上方**。
10. **改了 `import` / 导出，必须看构建日志的两行**：`✅ 产物语法自检通过` + `✅ import 绑定对账通过（… 360 = 360）`。数量不等就是静默少绑，别只看"构建成功"。
11. **重建产物后必须重启，并确认端口号变了**（单实例锁会让"再启动一次"静默复用旧进程）。"CDP 还在线"**不能**作为"新实例已起"的证据。
12. **外部环境的量（如窗口控件 inset）必须由环境读、不能写死**：写死会在另一种环境下变成新的缺陷。并且**断言要防"平凡真"**（见 §六 正负对照表末两行）。
13. 🔴 **凡「读宿主服务」的代码，先确认它在 `inject` 里声明过**。cordis 的 `ctx.<service>` 是 Proxy 陷阱：**未声明就按键会直接抛错**，而外层 `try/catch` 会把它变成**静默降级**（台账 #40 就是这么丢了整条血缘）。读取一律走**两级**：`ctx.x` → `ctx.get("x")`（后者不要求 inject），并把降级原因写进 `diag` 且**显示出来**。**降级可以，无声不行。**
14. 🔴 **订阅类 API 一律「先订阅、再触发」**。不要赌「事件一定是异步的」——`refreshX()` 在 ctx 通道里是**同步** notify，而"先 refresh 再 subscribe"会让首次打开永远停在初始快照（台账 #41）。
15. 🔴 **组件里的 hook 不能出现在 `if (!x) return` 之后**（台账 #19）；**组件里的 `useEffect` 顺序改动后必须重跑真机 e2e** —— 这两条都属于"逻辑断言全绿、界面已废"的类型。
16. 🔴 **测试桩只能有一份**。`verify-bundle.mjs` 曾自带一份极简 React 桩并与共享桩漂移，缺一个 `Component` 就让 **44 项断言级联失败**，报告读起来像"插件整个坏了"（台账 #47）。所有离线桩统一引用 `_platform-stub-impl.mjs`。
17. 🔴 **用真实鼠标/坐标驱动 e2e 时，坐标必须是"视口内且命中测试为自己"的**。用 `document.querySelector` 取到的**第一个**节点，在画布滚动后可能落在视口外（实测 x = -934）——CDP 的真实鼠标事件打在视口外等于什么都没点，现象却像"功能坏了"（台账 #44）。统一走 `focusVisibleNode()`。
18. 🔴 **每条断言都要问一句「它在反例上会不会也通过？」**（防平凡真）。本轮又抓到三条：[折叠全部] 的 `allCollapsed >= 0`、[toast] 的空集恒真、以及"跳过分支"掩盖真空段（台账 #45/#46）。**写断言的顺序是：先证明前提，再断言结果。**
19. **失败的 e2e 先看"页面还在不在"，再看功能**。分段脚本必须带 `state(tag)` 现场勘察行（每段打印页面是否挂载 / 元素是否齐）——本轮有 **4 段全红其实只是导图层被关掉了**，若无此行就会去改四个本来没坏的模块（台账 #43）。
20. **设计稿改完跑卫生五项**：`node scripts/verify-design-html.mjs "docs/50-信息中心/V16-设计图·需求图·交互逻辑.html"`（LF / 零反引号 / 字号 ≥10.5 / 标签平衡 / class 定义对账）必须 **5/5**。
21. 🔴 **负向断言必须先证明前提**。「空内容不登记」这类断言，如果被测输入框里可能留着上一轮的草稿，那条断言就是在**没有前提**的情况下做的 —— 产品会**正确地**登记一条，而报告写成"功能坏了"（台账 #52）。顺序永远是：**先证明前提 → 再断言结果**。
22. 🔴 **断言的对象必须与结论同源**。本轮三次假红全部是"挑错了对象"：
    「拖动后连线跟着动」挑了**第一条** path（未必连着被拖的框）→ 应挑**连着被拖框的那条**；
    「现在在做的事在最上面」扫的是**直接子节点**（`nd-now` 在 `bd` 里）→ 应按**文档序 + 真实几何**判；
    「R5 显示出该流转」用**DOM 里第一个会话 id** 登记（R5 按**宿主当前会话**过滤）→ 应走**同一来源**（真实 UI 路径）。
    **写断言前先问：我这个"判据"和我要证明的"结论"，指的是同一个东西吗？**
23. 🔴 **拖动类交互（手柄 / 抓手）必须先做命中测试，并确认手柄没被压住**。`pointerdown` 落在压住它的元素上时，框**纹丝不动**，现象与"拖动坏了"完全一样（台账 #50）。被压住的候选要把"谁压的"打进日志。
24. 🔴 **CDP 派发超时一律记账，绝不抛穿顶层 await**。一次 `Input.dispatchMouseEvent` 超时就会**终止整个进程、丢掉整轮已跑出的断言**（台账 #54）—— 这和"静默卡住"是同一类事故：都不能伪装成正常结束。所有指针/键盘派发统一记进 `cdpTimeouts`，收尾由 **E2** 断言，非零判 `INVALID`。
25. 🔴 **CSS 自定义属性里的 `var()` 是在"定义它的那个元素上"求值的**，不是在引用处。宿主的 `--dsw-alias-*` 定义在 `body` 上（真机回读 `documentElement` 上是**空串**，不是继承值）⇒ 把桥接写成 `:root{--dp-x:var(--dsw-alias-y)}` 会求值失败并**静默**落 fallback：背景压根没跟随宿主，却零报错、读属性一切正常（台账 #57）。**要跨"宿主令牌"取值，桥接必须挂在 `body` 以内能继承到令牌的元素上。**
26. 🔴 **动"别人"（宿主）的状态之前先读原值，恢复时按"原来是怎么设的"还原**。`removeProperty` 一刀切会把宿主**自己的内联值**一并删掉 —— 本轮因此把宿主毛玻璃背景改坏（`after = rgb(255,255,255)` ≠ `before`，台账 #57）：原本有内联值就**写回原值**，原本没有才 remove。并且**"能完全复原"本身要进断言**（`after === before`）—— 没有这条，"无副作用"就只是口头承诺。
27. 🔴 **"看起来相等"≠"同源"**。只比两侧当前色值，**抄一份同色值也能相等** ⇒ 宿主换主题/换背景图后照样不统一。要证明"读的是同一个变量"，必须做**正负对照**：改一方 ⇒ 另一方**必须立刻跟着变** ⇒ 恢复后回原值（verify-flow F5）。改完再加一条**客观度量**（如亮度扫描）去扫"改了一半"的漏网（F6：扫 130 个元素、深色 0 个），不要用肉眼代替。
28. 🔴 **断言扫源码之前先剥注释**（`stripComments()`）。注释里的"举例代码"会把负断言弄红 —— 危害是**逼人删注释（丢信息）而不是修代码**（台账 #59）。同理，扫源码的负断言要**按块**取文本（配平花括号），不要全文件搜字符串：本轮 C6 第一版全文件搜就误杀了三个"用简写但无害"的样式块。
    ⚠️ **剥注释的实现不许用"有状态的逐字符扫描器"** —— 本轮在 888KB 产物上实测它**静默失步**（被正则字面量 `/["']/` 里的引号带跑），之后全部注释都被当代码，负断言拿一条纯注释判红（台账 #67）。**失步比漏剥危险得多：漏剥只影响一条断言，失步会让全文件的扫描断言一起假绿。** 用**行级过滤**（无状态）；且负断言一律**按模块取块**（`__defs["<模块>"]`），别全文件搜 —— 同一个色值在别的模块里可能是**正当**的兜底默认（如 `var(--dp-ac, #b794f6)`）。
29. 🔴 **"看不见"不等于"不接收事件"：自身没有可见表面的容器必须显式 `pointer-events: none`。** 浮动/停靠类容器（药丸组、工具条、拖拽把手、遮罩）的**空白区域**默认照样吃鼠标事件 ⇒ 下层按钮**静默点不动**（台账 #61：`dp-send` 89×24 被吃 88×19）。判据只认**命中测试**（`elementFromPoint`），不认样式声明；而且必须**网格采样**（至少 5×5）—— 单点采样可能恰好落在真正的可点元素上，从而**测不到空隙**。同时别忘了**反向**：`none` 不能把功能本身弄废（三颗药丸必须仍可点）。
30. 🔴 **"量一次就存下来"的位置/尺寸，先问一句「它会不会变」。** composer 在空会话是居中大输入区、有消息后落到底部 —— 这一变**既没有 `resize` 事件、也不改变根元素盒尺寸**，只监听 resize 根本接不到（台账 #63：浮动组漂到 y=172 压住 R2.5/R2）。宿主没给订阅口时**轮询是可接受的**（本项目既有做法），关键是把它做成**正负对照**：挪一方 ⇒ 另一方**必须跟着挪** ⇒ **照原样恢复**后回原值（F11）。
31. 🔴 **诊断必须"数字对得上"，不能停在"操作一下就恢复了"。** 本轮把 `composerHero`（空会话居中）误判成"启动过渡视口"，就是拿相关性当因果（台账 #65）。可复现的判据是把**观测值反算回公式**（`innerHeight - composerTop + 12` 是否等于存下的 `bottom`）；对不上就不是那个原因。**按错诊断写的代码会白写**（我先加的 `ResizeObserver(documentElement)` 修不了它，已撤），**按错诊断写的注释更坏**——会把下一个人带偏，必须当场订正。

32. 🔴 **被自动化"逐个点击"的开合型控件，必须当场还原，且还原要有断言。** `ds-personalize`（⚙ 设置）/ `ds-ver-toggle` / `mm-personalize` / `mm-collapse-all` 点一下是**切换**，不是"执行一次就完"。点了不管，它会以两种方式反噬：① 吃掉后续的 Esc（`window` 捕获 + `stopPropagation`）；② 作为 `fixed` 浮层罩住别处按钮 ⇒ 让**后面若干条断言以"产品坏了"的形态炸掉**（台账 #68）。**关闭逻辑只留一处真相源**（`closeFloatLayers()`），别各段各写一遍 —— 各写一遍就一定有一处漏。
33. 🔴 **报"偶发红"时，先查闸门的"起点是否等价"，不要先查产品。** 本脚本**不重载页面**（连的是已运行的 Harness 实例）⇒ 状态跨运行保留：上一次跑完留下的折叠态 / 开着的浮层，会让下一次以不同状态起跑（台账 #68/#71）。**让每次运行的起点显式建立并断言**（`C13.0` / `C16.11p` / `C-M8p` / `C-M9p`），并在收尾**复原**（`C17.2`）—— 比"重跑到绿"可靠得多，也不会掩盖真问题。
34. 🔴 **断言"某个东西没动"时，必须配一条正对照，证明"能动的通道是通的"。** 「个性化挡住 Esc 后待确认没动」和「Esc 根本没进 handler」读出来**一模一样**（台账 #70）。做法：在同一状态、紧接着先跑一次**已知会成功**的同类操作（`C13.1n`：个性化未开时按 Esc，待确认必须被吃掉）。**否则这类断言在底层功能整体失效时照样全绿。**
35. 🔴 **凡"按个数对账"，先钉死量的是哪一类元素。** `data-collapsed` 同时打在**节点本体**和**框内控件**上 ⇒ 数出来是 2 倍，而报告读起来像"产品漏折了一半"（台账 #72）。同理适用于 `data-on` / `data-enabled` / `data-armed` 这类**一个语义标在两个元素上**的属性。**判据收紧到"精确等于"的价值就在这里：松判据（`> 0`）对口径错误完全无感。**

36. 🔴 **写 e2e 断言前先确认"容器是不是同一个"。** 五步过程区是 `director-messages` 的**兄弟节点**，而断言一直在 messages 里找它 ⇒ **恒 false 的假红**（第九轮 `cdp-click`）。正确顺序是：**先给被测结构一个语义锚点**（`data-testid="director-steps"`），**再按结构关系断言**（恰好 5 条）。**用选择器"碰运气找内容"是最脆的写法** —— 内容文案会变，结构关系不会。

37. 🔴 **一个属性名只能承载一个语义。** `data-dim` 同时被**审核维度**（6 个）与**四维流转徽标**（4 个）使用 ⇒ 选择器一抓 **10 个**元素、**一个根因连爆 3 条红**（第九轮 `cdp-click-dialog` D7）。看到这类断言红，**先数命中个数**：不对就说明选择器跨了语义。**不要靠"再收紧一点选择器"打补丁，要拆命名空间**（`data-review-dim` / `data-flow-dim`）。同理：语义不同 ⇒ 前缀必须不同。

38. 🔴 **测试桩/常量只能有一份真相源，且"只有一份"这件事本身要有闸门。** 09-12 修过 `verify-bundle` 的内联 React 桩，**次日 `verify-install` 原样再踩一次**（缺 `Component` ⇒ 32/33 NO，报错却指向产物）—— 手写"不许再犯"没用，必须**机器检查**（`lint-platform-stub.mjs`：L2 零内联桩 + L3 桩表 == 官方 10 项 + 注入反证）。**判据是"引用关系"，不是"内容相同"。**

39. 🔴 **e2e 脚本必须自带"收尾完整性"断言。** `verify-dialog` 在 600 行因 `launcher` 退役而 null 解引用，**脚本静默死亡**、其后 **100+ 条断言全丢**，而报告看起来只是"跑完了一段"（第九轮）。**事故形态有三层：红 → 跳过 → 崩溃**，一层比一层隐蔽（红有人看，跳过没人看，崩溃连"跑过"都看不出来）。做法：入口登记**预期断言总数**，收尾断言"实跑数 == 预期数"，不等即 `INVALID`。

40. 🔴 **扫源码找"坏形态"时，坏样本本身会污染判据 —— 连注释里都不能写。** `lint-platform-stub` 第一版**自己命中自己**：坏样本字面量写在源码里、注释里还留了一份（第九轮）。做法：样本**拼接构造**（`'{"react"' + '": {'`），注释**只描述、不写形态**。这是纪律 28「剥注释」的加强版 —— **剥注释能防"解释性污染"，防不了"样本污染"**。

41. 🔴 **凡"点了会写盘/落库"的闸门段，都要"快照 → 还原 → 还原断言"三件套。** `cdp-click.mjs` 的 I 段是一条真实写入链（翻转开关 → 保存本层 → 向上提交 → 恢复继承只清会话那层）⇒ 把「五项全关」**永久**写进 `__global__` 与 `ws_*` **两级**（第九轮续）。危害有**两重**：① 用户的**真实配置**被改坏；② **下一个闸门**以「产品缺陷」的形态报红（红在 `verify-flow`，根在 `cdp-click`）—— 这种**跨脚本栽赃**最难查。做法：段前快照全量、段后**写回+清掉新增+逐节点回读自证**（`I0`/`I8r`）。**闸门不许成为产品的破坏者。**

42. 🔴 **只要被测面是"持久化/累积"的，判据就必须是"跑程内"的。** 消息 store 按 sessionId 持久化、R5 只显示 `msgs.slice(-14)` ⇒ 对整段 `innerText` 做正则，问的是「**历史上**出现过这几个字吗」。同一条断言因此**两个方向都不安全**：假绿（`/1\./` 命中旧消息）与假红（`/全部职责已关闭/` 命中上一轮降级消息）**会同时出现在相邻两条断言上**；轮询里更直接 —— `done` 条件被旧数据**立即**满足 ⇒ 提前退出 ⇒ 去读一个**还没算完**的结果（`lastSteps === null` ⇒ rows=0）。做法：读**最新一条**，或要求**增量**（行数净增），并让轮询 `done` 只依赖**本轮才会出现**的信号。**写断言前问：这个数，上一轮会不会也让它成立？**
