# 测试流程与增量测试矩阵

> 文档编号：40-TEST-22 ｜ 版本：V1.0 ｜ 日期：2026-09-17
> 触发背景：用户裁定 —— 「测试太费 token，很多测试重复跑了很多遍，有些是反复打开关闭软件。
> 先写测试流程，确定要测什么、哪些能一起测、哪些测过没问题且没有相关改动下次就不必再测。」
> 关联：`00-统筹入口/10-当前基线-落死锚点-V16.md`（闸门清单与判据的权威出处）、
> `dsh-director-plugin/scripts/{test-plan,_test-ledger,run-live}.mjs`（本流程的**可执行实现**）

---

## 〇、一句话

**本轮测试集 = 可复算的取集判据算出来的，不是"感觉该跑就跑"。**
取集靠三条判据（A 指纹相等全跳 / B 改动集与闸门输入无交集全跳 / C 按覆盖面取集），
免重跑靠一份**台账**（`logs/test-ledger.json`），省钱靠**批量化**（同一批只启动一次进程）。

## 一、三笔被浪费的成本（问题定义）

| # | 现象（用户观察） | 真因 | 本流程的处置 |
|:-:|:-----------------|:-----|:-------------|
| 1 | 「重复了很多遍」 | 没有「该跑哪些」的判据 ⇒ 一律全量跑；且**同一份产物在一轮里被反复跑**（我刚跑完，并行会话又跑一遍） | 判据 A/B/C（§三）+ 台账（§五） |
| 2 | 「反复打开关闭软件」 | 真机套**逐套件各自启停** Harness ⇒ 一次验证开合七八次 | `run-live.mjs`：**整批只冷启动一次**（§二） |
| 3 | 「太消耗 token」 | 每套件把几百行输出全量回显；日志全文读回；"重跑到绿"式排障 | 成本红线（§六） |

> 🔴 反面教材（本仓真实发生）：`_offline-run.mjs` 里写死 `if (f === "verify-dialog.mjs")`
> 给某个套件特殊加桩 —— **一条手工特例**。判据一旦手工化，加第 2 个套件时就会漏，
> 而漏的后果是 **exit 2**（INVALID），读起来像"产品坏了"。

## 二、测试分层与批次（**每批一条命令**）

| 层 | 内容 | 数量（2026-09-17 实测） | 单批命令 | 能否拆开逐套件跑 |
|:--:|:-----|:----------------------:|:---------|:----------------:|
| L0 | 静态闸门：语法 / 模板 / 平台桩唯一性 / DOM 单位 / 依赖环 | 见 §八 结构类 | 并入批次 1 | ❌ 禁止 |
| L1 | 离线行为：纯函数 + 桩环境逻辑（70 套中 **56 套**） | 56 | `node scripts/test-plan.mjs --run --record` | ❌ 禁止 |
| L2 | 构建 / 装机 / 产物新鲜度 | 并入 L0/L1 | 见 §七 链路 | ❌ 禁止 |
| L3 | 真机 e2e（**14 套**，需活 Harness + CDP） | 14 | `node scripts/run-live.mjs <套件...>` | ❌ 禁止 |

> ⚠️ **数量列的时效**：上表数字为 **2026-09-17 实测**，只用来给量级。套件会随并行会话
> 增删 ⇒ **唯一权威是 `node scripts/test-plan.mjs` 的输出**（它会自己数），本表不许当判据引用。
> 维护项：数量差异超过 ±3 套时回来刷新本表。

**为什么不许拆开逐套件跑（不是洁癖）：**

1. **真机套**：Harness 冷启动一次要等到「页签环出现」才能自举起点（实测 t+58 s；不经
   常 120 s 都不出现）⇒ 逐套件跑 = 把这段等待乘以套件数。`run-live.mjs` 首套自举后
   后续套件**秒过**（同一页面复用）。
2. **宿主进程树在 bash 工具退出时被回收** ⇒ 「启动 + 等待 + 验证」必须**同一条命令**，
   拆开跑会得到"套件全 `ECONNREFUSED`"这种与产品无关的假失败。
3. **同一页面不可并行跑 CDP** ⇒ 拆开并行只会互相抢锁。

## 三、增量判据（该跑哪些 · 可复算）

### 3.1 三条判据

| 判据 | 成立条件 | 结论 | 为什么是**证明**而不是抽样 |
|:----:|:---------|:-----|:---------------------------|
| **A** | 产物内嵌指纹 == 台账里"全绿基准指纹"，**且**改动集为空或在闸门输入域之外 | **离线套件全部跳过**（真机套见下） | `lib/client.js` 是 `src/**` 的确定性函数，产物内嵌了 `src/**` 的内容指纹（构建时写死）⇒ 指纹相同 ⇒ **离线闸门的输入逐字节相同** ⇒ 结果不可能变 |
| **B** | 改动集非空，但与闸门输入域（`src/ lib/ build/ scripts/ package.json assets/`）**无交集** | **全部跳过** | 只动了 `docs/` 之类，没有任何闸门读它 |
| **C** | 其余（默认档） | **按覆盖面取集** | 见 3.2 |

> 🔴 **判据 A 的适用边界（第 3 轮审核修正）**：指纹相等只证明"**离线**输入未变"。
> **真机套件读的是活宿主**（页面状态、存储、CDP 会话），那些东西**不在指纹里** ⇒
> **真机套件永不因判据 A 跳过**。这条不能靠"感觉不会变"，因为本仓已被咬过：
> 同一个页面在两次运行之间可能被另一会话改过状态。

### 3.2 判据 C 的取集规则

```
跑 ⟸ 任一成立：
  ① 结构类（推导不出 src 覆盖面）          ← 它们证的是"工程完整性"，不是某个功能
  ② 该套件的覆盖面 ∩ 改动集 ≠ ∅
  ③ 该套件读产物（lib/client.js / __ModuleLoader__ / __dshBuildStamp）且 src/** 有改动
      —— 产物 = src 的函数，src 一动，读产物的闸门全部受影响，不能按文件级覆盖面跳
跳过 ⟸ 以上都不成立
```

**覆盖面是推导出来的，不是手抄表。** 提取规则在 `_test-ledger.mjs` 的 `surfaceOf()`：
从套件源码（**先剥注释**）里提取所有真实存在的 `src/**/*.js` 路径字面量
（含 `../src/...`、`"src/..."`、`SRC("...")` 等写法）。

> 🔴 本仓已被"手抄表"咬过两次（**两份 react 桩必漂移**）。同一个理由：
> 覆盖面手抄必漂移，所以它必须是**推导**。`--explain` 可逐套件复核每条依据。

### 3.3 用法

```bash
node scripts/test-plan.mjs                # 出计划（只读，不跑）
node scripts/test-plan.mjs --explain      # 逐套件打印"跑/跳过 + 依据"
node scripts/test-plan.mjs --run --record # 执行离线批次 + 写台账
node scripts/test-plan.mjs --all          # 强制全量（交付封存 / 怀疑判据本身时）
node scripts/test-plan.mjs --changed src/logic/flow.js   # 手工指定改动集
node scripts/run-live.mjs --plan          # 真机批次：只列清单，不启动
node scripts/run-live.mjs <套件...>       # 真机批次：只冷启动一次
```

**退出码（全仓统一）：`0` 通过 / `1` FAIL / `2` INVALID。**
`INVALID`（跑不起来：环境缺件、前提不成立）**不等于** FAIL，也**不写台账**（不污染基准）。

## 四、四类反模式（本仓真实踩过）

| # | 反模式 | 症状 | 正确做法 |
|:-:|:-------|:-----|:---------|
| 1 | **无判据全量跑** | 改一行 CSS 跑 70 套 | 判据 A/B/C 先出计划（成本 = 一条命令） |
| 2 | **逐套件启停真机** | 「反复打开关闭软件」 | `run-live.mjs` 只启动一次 |
| 3 | **判据写窄 ⇒ 假红** | 桩判据只认 `from "../src/` 一种写法 ⇒ `verify-dialog.mjs` 被漏加钩子 ⇒ exit 2，读起来像产品坏了 | 判据走**共享唯一真相源** `needsPlatformStub()`；宁可**过包含**（多给一个空钩子无害，漏给会造假红） |
| 4 | **拿旧结论当现状** | 「上次测过是绿的」 | 免重跑的依据必须是**指纹**（内容），不是**时间**（mtime 判据在本仓已被证伪：逐字节一致 ≠ 是新的） |

> 🔴 反模式 3 的延伸：**"没跑成"必须与"失败"可分辨**。批量执行器里
> `code === 2 ⇒ 打印 INVALID`，不允许与 FAIL 共用一种输出。

## 五、免重跑台账（`logs/test-ledger.json`）

```jsonc
{ "suites": {
    "verify-bundle.mjs": {
      "lastRunAt": "2026-09-17T…",   // 仅作痕迹，**不作为判据**
      "lastResult": "PASS",
      "passStamp": "eb945c53dfcc4a05", // ← 唯一判据：上一次通过时的产物内容指纹
      "surface": ["src/logic/flow.js", …]
    } } }
```

**推进规则（硬约束）：**

- `passStamp` **只在套件为绿时推进** —— 红不能盖住上一次的绿（否则一次环境性红会把基准抹掉，
  下次就只能全量重跑，与省钱目标相反）。
- 台账基准的取法：所有登记套件里「无红记录、出现次数最多的绿指纹」。
- INVALID **不写台账**。
- 台账是**缓存不是真相**：怀疑它时 `--all` 一把全跑，用结果覆盖。

## 六、成本红线（token / 时间）

| # | 红线 | 落地方式 |
|:-:|:-----|:---------|
| 1 | 每套件**只回显最后 3 行** | 批量执行器统一 `tail`，禁止整段输出回显 |
| 1b | **红的时候 3 行不够定位** ⇒ 允许单独重跑那一套看全量 | 单套重跑只对**离线**套件成立（离线套件不受"整批一次启动"约束）；真机套要重跑就整批重跑 |
| 2 | 真机**只冷启动一次** | `run-live.mjs` 前置探活：CDP 已在跑则**不重复启动**并告警 |
| 3 | 禁止读回 `logs/*.log` 全文 | 需要证据时读**末段**或按关键字过滤 |
| 4 | 禁止"重跑到绿" | 起点**显式建立并断言** + 收尾**环境复原**（比反复重跑可靠） |
| 5 | 承诺的功能必须跑，没跑的必须说 | 结果句里写清「跑了 N 套 / 跳了 M 套（判据 A：输入未变）」 |

## 七、标准链路（照抄即可）

### 7.1 日常改动（改一个功能）

```bash
cd dsh-director-plugin
node scripts/baseline-check.mjs          # ① 基线漂移必须先为 0
# …改 src/**…
node scripts/gen-source-map.mjs          # ② 生成映射
node scripts/gen-key-files.mjs           # ③ 改 src 必跑（它自己改 src ⇒ 要重建+重装+重封）
node scripts/test-plan.mjs --explain     # ④ **先看该跑哪些**（只读）
node scripts/test-plan.mjs --run --record # ⑤ 离线批次（一条命令）
node build/build.mjs                     # ⑥ 看两行：语法自检 + import 对账 N = N
node scripts/check-stale-build.mjs && node scripts/plugin-install.mjs --apply   # ⑦ 装机
node scripts/run-live.mjs <受影响真机套件...>   # ⑧ 真机批次（只启动一次）
node scripts/baseline-check.mjs --write && node scripts/baseline-check.mjs      # ⑨ 重封 + 复验漂移 0
```

### 7.2 纯文档改动

判据 B ⇒ **零套件**。（`node scripts/test-plan.mjs` 一条命令即可证明。）

### 7.3 交付 / 封存前

```bash
node scripts/test-plan.mjs --all --run --record   # 全量离线
node scripts/run-live.mjs <全部真机套件>           # 全量真机（仍只启动一次）
node scripts/_offline-run.mjs                     # 留一份完整日志作为交付证据
```
+ **曾红过的套件必须复跑**（不接受"上次红了这次跳"）。

## 十、维护与防漂移

1. **加新套件**：无需登记 —— `listSuites()` 自动发现 `scripts/{lint-,verify-,test-,prove-}*.mjs`
   （`_` 前缀为内部工具，不参与）。覆盖面与桩需求**自动推导**。
2. **改判据 = 改闸门**：判据变了必须**植入缺陷校准**（拿一个已知的坏样本验证它还抓得住），
   否则会出现"闸门永远绿"的空真。样本构造与期望值见 §十二。
3. **判据失效的兜底（第 1 轮审核新增）**：无论判据多稳，都必须有**周期对账** ——
   每 **10 次**改动或每周（取先到者）跑一次 `--all` 全量；两次全量之间若出现"跳过之后
   产品却坏了"的事故，**立即**回到全量并重审判据。
4. **假跳过（假绿）比假红危险（第 3 轮审核新增）**：覆盖面是**静态提取**的；套件若用
   **变量拼路径**读 `src/**`，提取会漏 ⇒ 该套件被判"无交集"而跳过 —— 这是**静默的危险**。
   反向保险：① 结构类一律跑（它们是提取不到的那批）；② 交付封存全量；
   ③ 提取规则升级时对全部套件重跑一次 `--explain` 人工过一遍。
5. **判据不许写窄**：宁可过包含。**漏给桩 ⇒ INVALID 假红**（已踩）；**多给桩 ⇒ 空钩子**（无害）。
6. **同一事实只留一份真相源**：桩判据、离线/真机分类、覆盖提取，全部只在 `_test-ledger.mjs`。
7. **台账在 `logs/`**（不入交付物）；基准漂移时以 `--all` 结果为准。

## 十二、判据自校准（防止"闸门永远绿"）

任何判据改动后必须跑一次**植入缺陷校准**：造一个已知坏样本，确认闸门仍抓得住。

| 判据 | 植入的坏样本 | 期望 |
|:-----|:-------------|:-----|
| 指纹判据 | 改一处 `src/**` 后不重建 | 产物指纹 ≠ src 指纹 ⇒ 拒跑（`run-live.mjs` 前置校验） |
| 覆盖面判据 | 造一个引用不存在 `src/xx.js` 的假套件 | 不计入覆盖面（`existsSync` 挡掉） |
| 桩判据 | 造一个 import `src/**` 且不存在的套件 | `needsPlatformStub() === true` |
| 分类判据（离线/真机） | 在文件里写 `connectOverCDP` | 被归为真机套 |

> 本仓同类教训：`lint-cdp-templates.mjs` 的**自检**环节曾发现"判据污染"（坏样本字面量
> 写在源码里、注释里也留一份）⇒ 样本必须**拼接构造**，不许字面量常驻。
