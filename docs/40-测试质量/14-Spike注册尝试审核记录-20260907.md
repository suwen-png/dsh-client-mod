## 三、根因假设（待证）

1. **启动期 pnpm/锁文件校验**：profile 是 pnpm workspace，host 启动可能触发 install 校验；手改+junction 与 pnpm 状态机不一致导致挂起（attempt 2 已同步 lockfile 仍失败 → 弱化此假设）。
2. **host face 插件校验**：空 apply / 缺 bundle.patch / 缺某必需导出，导致组合器抛错 fail-loud（dsh-director 有真实服务 + bundle.patch；与我们的差异点集中在此）。
3. **组合器对未知 bundle 的失败传播**：任一 bundle 行失败即全 boot 中止（fail-loud 设计），缺 stderr 可见性 → 下一步取证。
