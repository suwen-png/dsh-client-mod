## 一、测试体系总览

### 1.1 测试分层

```
单元测试 → 集成测试 → 端到端测试 → 性能测试 → 安全测试 → 用户验收测试
```

### 1.2 测试金字塔

| 层级 | 占比 | 执行速度 | 负责人 |
|:-----|:----:|:---------|:-------|
| 单元测试 | 70% | 快（秒级） | 开发工程师 |
| 集成测试 | 20% | 中（分钟级） | 开发+测试 |
| 端到端测试 | 10% | 慢（十分钟级） | 测试工程师 |

## 二、测试用例管理

### 2.1 用例状态流转

```
待使用 → 进行中 → 已完成
   ↑                    │
   └──── 回归测试 ──────┘
```

| 状态 | 定义 | 处理规则 |
|:-----|:-----|:---------|
| 待使用 | 已编写但未执行 | 可修改，可删除 |
| 进行中 | 正在执行 | 仅追加执行记录，禁止修改用例内容 |
| 已完成 | 执行完毕 | 仅追加回归测试记录，禁止清空重写 |

### 2.2 用例编写规范

**用例模板**：
```
## TEST-{编号}: {用例标题}

| 字段 | 值 |
|:-----|:---|
| 用例ID | TEST-{编号} |
| 所属模块 | {模块名} |
| 优先级 | P0/P1/P2 |
| 前置条件 | {前置条件} |
| 测试步骤 | 1. {步骤1} 2. {步骤2} ... |
| 预期结果 | {预期结果} |
| 实际结果 | {执行后填写} |
| 执行状态 | 未执行/通过/失败/阻塞 |
| 执行人 | {执行人} |
| 执行时间 | {时间} |
```

### 2.3 优先级定义

| 优先级 | 定义 | 覆盖率要求 |
|:-------|:-----|:-----------|
| P0 | 核心功能，阻塞主流程 | 100% 覆盖 |
| P1 | 重要功能，影响用户体验 | ≥ 90% 覆盖 |
| P2 | 次要功能，边缘场景 | ≥ 70% 覆盖 |

## 三、测试执行规范

### 3.1 单元测试

**要求**：
1. 每个函数必须有对应的单元测试
2. 测试文件命名：`{源文件名}_test.py` / `{源文件名}.test.ts`
3. 测试目录与源码目录结构对应
4. 使用 AAA 模式：Arrange（准备）→ Act（执行）→ Assert（断言）

**命令**：
```bash
# Python
pytest --cov=. --cov-report=html --cov-fail-under=80

# TypeScript/JS
npm test -- --coverage --coverageThreshold='{"global":{"lines":80}}'
```

### 3.2 集成测试

**要求**：
1. 测试模块间接口调用
2. 测试数据库读写
3. 测试外部 API 调用（使用 mock 或测试环境）
4. 测试完整业务流程

**命令**：
```bash
# Python
pytest tests/integration/ -v

# TypeScript/JS
npm run test:integration
```

### 3.3 端到端测试

**要求**：
1. 模拟真实用户操作流程
2. 覆盖核心用户旅程
3. 在测试环境执行
4. 包含 UI 交互测试

**工具**：
- Python: Playwright / Selenium
- TypeScript/JS: Playwright / Cypress

### 3.4 性能测试

**指标**：
| 指标 | 阈值 | 说明 |
|:-----|:-----|:-----|
| 响应时间 | P95 ≤ 500ms | 95% 请求响应时间 |
| 吞吐量 | ≥ 100 QPS | 每秒查询数 |
| 并发用户 | ≥ 50 | 同时在线用户数 |
| 错误率 | ≤ 0.1% | 请求失败率 |
| 内存占用 | ≤ 512MB | 峰值内存 |

**工具**：locust / k6 / JMeter

### 3.5 安全测试

**检查项**：
1. SQL 注入防护
2. XSS 跨站脚本防护
3. CSRF 跨站请求伪造防护
4. 认证与授权校验
5. 敏感数据加密
6. 依赖漏洞扫描（npm audit / pip-audit）

**工具**：OWASP ZAP / npm audit / pip-audit / Snyk

## 四、质量门禁标准

### 4.1 合并门禁（MR/PR 合并前）

| 门禁项 | 阈值 | 不达标处理 |
|:-------|:-----|:-----------|
| 单元测试通过率 | 100% | 阻断合并 |
| 代码覆盖率 | ≥ 80% | 阻断合并 |
| 静态检查错误 | 0 | 阻断合并 |
| 代码评审 | 至少1人批准 | 阻断合并 |
| 安全漏洞（高危） | 0 | 阻断合并 |

### 4.2 部署门禁（上线前）

| 门禁项 | 阈值 | 不达标处理 |
|:-------|:-----|:-----------|
| 集成测试通过率 | 100% | 阻断部署 |
| 端到端测试（P0） | 100% 通过 | 阻断部署 |
| 性能测试 | 全部达标 | 阻断生产部署 |
| 安全测试 | 0 高危 | 阻断部署 |
| 预发验证 | 通过 | 阻断生产部署 |

### 4.3 发布后监控

| 监控项 | 告警阈值 | 处理 |
|:-------|:---------|:-----|
| 错误率 | > 1% | 自动回滚 |
| 响应时间 | P95 > 1s | 告警，排查 |
| 业务指标 | 下降 > 20% | 告警，排查 |
| 资源占用 | CPU > 80% / 内存 > 80% | 告警，扩容 |

## 五、测试报告规范

### 5.1 测试报告模板

```markdown
# 测试报告 - {版本号}

> 测试周期：{开始时间} ~ {结束时间}
> 测试环境：{环境}
> 测试负责人：{负责人}

## 一、测试概览
| 指标 | 值 |
|:-----|:---|
| 用例总数 | {N} |
| 通过 | {N} |
| 失败 | {N} |
| 阻塞 | {N} |
| 通过率 | {X}% |
| 代码覆盖率 | {X}% |

## 二、缺陷统计
| 严重程度 | 数量 | 已修复 | 未修复 |
|:---------|:----:|:------:|:------:|
| 致命 | {N} | {N} | {N} |
| 严重 | {N} | {N} | {N} |
| 一般 | {N} | {N} | {N} |
| 轻微 | {N} | {N} | {N} |

## 三、测试结论
{通过/有条件通过/不通过}

## 四、遗留问题
1. {问题描述} - {责任人} - {计划修复时间}
```

### 5.2 缺陷严重程度定义

| 级别 | 定义 | 修复时限 |
|:-----|:-----|:---------|
| 致命 | 系统崩溃、数据丢失、核心功能不可用 | 24小时内 |
| 严重 | 主要功能异常、性能严重不达标 | 3天内 |
| 一般 | 次要功能异常、UI问题 | 下个版本 |
| 轻微 | 文字错误、样式微调 | 按需修复 |
