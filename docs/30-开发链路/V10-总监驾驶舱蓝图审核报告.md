## 二、需补充的 12 个设计细节

### 2.1 A 区相关（4 项）

#### ① "驾驶舱"按钮的具体功能未定义
- **现状**: 设计图中写"展开/收起驾驶舱快捷面板（快速操作：新建会话、清除缓存、重启提示等）"
- **问题**: "等"字不明确，到底有哪些快捷操作？面板长什么样？
- **建议**: 明确定义驾驶舱快捷面板的 5-8 个固定操作，如：新建会话、清除缓存、重启 Harness、导出对话、Ollama 状态、文档索引刷新、项目切换、全屏模式

#### ② "阶段"标签的编辑交互未定义
- **现状**: "点击可快速编辑阶段"
- **问题**: 点击后是弹出输入框？还是下拉选择预设阶段？编辑后如何同步到 project_overview.md？
- **建议**: 点击后弹出下拉选择（预设：需求分析/设计中/开发中/测试中/已发布/维护中）+ 自定义输入，选择后自动更新 overview.phase 并同步写入文档

#### ③ 设置弹窗内容过多，需分类
- **现状**: 设置弹窗整合了自动转发、导出日志、清除缓存、滚到底、Ollama配置、外观设置、执行逻辑职责、数据管理，共 8 类
- **问题**: 全部堆在一个弹窗里会很长，用户体验差
- **建议**: 设置弹窗内部分为 4 个 tab：①通用（自动转发/外观/密度）②模型（Ollama endpoint/模型/temperature/参数）③执行逻辑（4个职责开关+规则编辑）④数据（导出/导入/清除缓存/重置）

#### ④ 原 C 区"总监待命"状态标签的去向
- **现状**: 设计图说"移入设置弹窗的状态栏"
- **问题**: 用户可能希望在导航栏就能看到总监当前状态（待命/处理中/错误），而不是打开设置才看到
- **建议**: 在 A 区"总监"tab 上增加状态指示点（绿色=待命/黄色=处理中/红色=错误），设置弹窗内保留详细状态信息

### 2.2 B 区相关（3 项）

#### ⑤ 项目总览文档的具体格式未定义
- **现状**: "数据由总监文档维护（project_overview.md / risks.md / tasks.json）"
- **问题**: 这三个文档的具体字段结构是什么？loadOverviewFromDocs() 如何解析？
- **建议**: 明确定义三个文档的 YAML Front Matter 结构（见数据模型设计文档），如 project_overview.md 包含 positioning/goal/phase/progress 字段

#### ⑥ 项目资产统计的扫描方式和性能
- **现状**: "实时扫描统计（文档数/包数/脚本数/代码行数）"
- **问题**: client.js 运行在渲染进程，扫描文件系统需要 Node.js fs API，且每次渲染都扫描会有性能问题
- **建议**: 资产统计不做实时扫描，改为：①apply.ps1 执行时生成资产统计 JSON ②client.js 启动时读取该 JSON ③提供"刷新统计"按钮手动触发。避免运行时频繁扫描

#### ⑦ 进度自动计算的公式
- **现状**: "待办完成率自动计算"
- **问题**: 公式是什么？已完成待办数/总待办数？还是加权计算？手动覆盖的优先级？
- **建议**: 进度 = 已完成待办数 / 总待办数 × 100%，取整。用户可在编辑模式手动覆盖，手动覆盖后显示"手动"标记，不再自动计算

### 2.3 D 区相关（5 项）

#### ⑧ 智能体创建分支后的分支管理
- **现状**: "智能体调用=创建新分支（新对话）"
- **问题**: 创建分支后，用户如何查看所有分支？如何切换回主线？如何删除分支？分支之间的对话历史如何隔离？
- **建议**: 在 A 区"驾驶舱"快捷面板中增加"分支管理"入口，显示当前所有分支列表，支持切换/删除/重命名。D区智能体列表中已调用的智能体显示"已创建分支"状态

#### ⑨ 技能调用时无用户消息的处理
- **现状**: "技能调用=在当前对话注入prompt"
- **问题**: 如果当前对话为空（没有用户消息），点击技能调用什么？
- **建议**: 技能调用分两种模式：①有用户消息时=用技能处理最近一条用户消息 ②无用户消息时=将技能的 system prompt 作为系统消息插入，等待用户输入后自动按该技能处理

#### ⑩ 执行逻辑规则的触发场景
- **现状**: "执行逻辑调用=全局强制规则（文件生成标准/回复标准等）"
- **问题**: 4个职责（语言整理/上下文记忆/执行逻辑/返回审核）每个都有详细规则，但规则在什么场景触发？是全局生效还是按需触发？
- **建议**: 执行逻辑分为两类：①全局规则（开关控制，开启后所有对话都遵循）②场景规则（点击"强制执行"后，下一次AI回复必须遵循该规则）。规则内容可编辑，存储在 duties 规则文档中

#### ⑪ 查看/编辑弹窗的统一组件设计
- **现状**: "查看/编辑弹窗"
- **问题**: 智能体/技能/执行逻辑三类数据的查看和编辑弹窗结构不同，需要分别设计
- **建议**: 统一弹窗组件，内部根据类型渲染不同内容：
  - 智能体：名称/图标/描述/system prompt（大文本框）/启用开关
  - 技能：名称/图标/触发词/描述/prompt（大文本框）/启用开关
  - 执行逻辑：名称/描述/规则内容（大文本框）/启用开关/触发方式（全局/按需）

#### ⑫ 数据持久化存储位置
- **现状**: "agents.json / skills.json 存储"
- **问题**: 存在哪里？localStorage（5MB限制）/ IndexedDB / 项目文件？
- **建议**: 优先存储在项目目录下的 `config/agents.json` 和 `config/skills.json`（通过 Node.js fs 读写），回退到 localStorage。这样数据随项目走，切换项目时自动切换对应配置

## 三、3 个技术风险点

### 风险 1：编译产物中实现统一弹窗组件的复杂度
- **风险**: client.js 是编译后的 React 产物，JSX 都是 `react_jsx_runtime.jsx()` 调用，新增复杂弹窗组件（含表单、大文本编辑、tab切换）代码量很大，容易出错
- **缓解**: 弹窗使用简单的绝对定位 div + 原生 form 元素，不引入复杂组件库。大文本编辑用 textarea，不引入代码编辑器
- **优先级**: 中

### 风险 2：D 区三态切换时的状态保持
- **风险**: 在智能体/技能/执行逻辑三个 tab 间切换时，搜索关键词、筛选条件、滚动位置是否保持？如果每次切换都重置，用户体验差
- **缓解**: 每个 tab 独立维护自己的搜索/筛选/滚动状态，存在独立的 state 中，切换时不重置
- **优先级**: 低

### 风险 3：与 dsh-director 插件的侧边栏入口冲突
- **风险**: dsh-director 插件有自己的侧边栏入口（左下角"总监"按钮），V10 重构后总监 tab 内部已经有完整功能，插件侧边栏入口是否还需要？
- **缓解**: 保留插件侧边栏入口作为快速打开总监 tab 的方式，不重复实现功能。点击侧边栏入口 = 切换到总监 tab
- **优先级**: 低
