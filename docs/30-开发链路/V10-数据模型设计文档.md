## 二、project_overview.md

### 2.1 格式
Markdown 文件，顶部 YAML Front Matter 存储结构化字段，正文存储详细描述。

### 2.2 YAML 字段

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| positioning | string | 是 | "" | 项目定位（一句话） |
| goal | string | 是 | "" | 项目目标（一句话） |
| phase | string | 是 | "开发中" | 当前阶段（需求分析/设计中/开发中/测试中/已发布/维护中/自定义） |
| progress | number | 否 | 0 | 进度百分比（0-100），progressManual=false 时被自动计算覆盖 |
| progressManual | boolean | 否 | false | 是否手动设置进度 |
| createdAt | string | 否 | 当前日期 | 创建日期（ISO 格式） |
| updatedAt | string | 否 | 当前日期 | 最后更新日期（ISO 格式） |

### 2.3 完整示例

```markdown
---
positioning: "DeepSeek Harness 原客户端修改工作区，实现总监对话模式"
goal: "完成 V10 总监驾驶舱重构，三tab共存，文档索引53篇"
phase: "开发中"
progress: 65
progressManual: false
createdAt: "2026-08-27"
updatedAt: "2026-09-02"
---
```

## 三、risks.md

### 3.1 格式
Markdown 文件，按"未关闭"/"已关闭"两个 section 组织风险项。

### 3.2 风险项结构

每个风险项为三级标题 `###`，格式：`### [严重程度] 风险标题`

| 元素 | 格式 | 说明 |
|------|------|------|
| 严重程度 | `[高]` / `[中]` / `[低]` | 标题前缀 |
| 发现日期 | `- **发现日期**: YYYY-MM-DD` | 列表项 |
| 描述 | `- **描述**: 文本` | 列表项 |
| 缓解措施 | `- **缓解措施**: 文本` | 列表项 |
| 状态 | `- **状态**: open / closed` | 列表项 |
| 关闭日期 | `- **关闭日期**: YYYY-MM-DD` | 已关闭项必填 |
| 解决方案 | `- **解决方案**: 文本` | 已关闭项必填 |

### 3.3 完整示例

```markdown
# 项目风险记录

## 未关闭

### [高] 编译产物修改风险高
- **发现日期**: 2026-08-28
- **描述**: 修改 client.js 编译产物，语法错误会导致 Harness 白屏
- **缓解措施**: 每次修改后 node --check 验证，apply 前自动快照
- **状态**: open

### [中] Ollama 服务不稳定
- **发现日期**: 2026-09-01
- **描述**: 本地模型调用超时或失败，总监回退到规则模板模式
- **缓解措施**: 增加超时重试（60s），未连接时显示明确引导
- **状态**: open

## 已关闭

### [低] PowerShell 5.1 中文乱码
- **发现日期**: 2026-09-01
- **关闭日期**: 2026-09-01
- **描述**: .ps1 脚本含中文时，PowerShell 5.1 按 GBK 解读导致乱码
- **解决方案**: 全部 11 个 .ps1 文件加 UTF-8 BOM
- **状态**: closed
```

### 3.4 解析规则
- `## 未关闭` section 下的所有 `###` 项 = 未关闭风险
- 未关闭风险数 = B 区风险卡片显示的数字
- 严重程度从标题的 `[高]/[中]/[低]` 提取
- 关闭风险 = 将该项从"未关闭"section 移到"已关闭"section，补充关闭日期和解决方案

## 四、tasks.json

### 4.1 格式
JSON 数组，每个元素为一个任务对象。

### 4.2 任务字段

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| id | number | 是 | Date.now() | 唯一标识 |
| title | string | 是 | "" | 任务标题 |
| status | string | 是 | "todo" | todo / doing / done |
| priority | string | 否 | "medium" | high / medium / low |
| createdAt | number | 是 | Date.now() | 创建时间戳 |
| completedAt | number/null | 否 | null | 完成时间戳 |
| branch | string | 否 | "main" | 所属分支 |
| description | string | 否 | "" | 任务描述 |
| assignee | string | 否 | "" | 负责人 |

### 4.3 完整示例

```json
[
  {
    "id": 1,
    "title": "完成 V10 布局重构设计文档",
    "status": "done",
    "priority": "high",
    "createdAt": 1756800000000,
    "completedAt": 1756886400000,
    "branch": "main",
    "description": "完成 A/B/D 三区详细设计文档和数据模型设计",
    "assignee": "总监"
  },
  {
    "id": 2,
    "title": "A 区整合导航栏代码实现",
    "status": "todo",
    "priority": "high",
    "createdAt": 1756886400000,
    "completedAt": null,
    "branch": "main",
    "description": "重构顶部导航栏，整合原 C 区，增加驾驶舱快捷面板和设置弹窗4tab",
    "assignee": "总监"
  },
  {
    "id": 3,
    "title": "D 区智能体调用=创建分支",
    "status": "doing",
    "priority": "high",
    "createdAt": 1756890000000,
    "completedAt": null,
    "branch": "code-agent",
    "description": "点击智能体调用按钮时，创建新分支并切换到该分支对话",
    "assignee": "总监"
  }
]
```

### 4.4 统计规则
- 未完成待办数 = `status !== "done"` 的数量
- 已完成数 = `status === "done"` 的数量
- 进度 = `Math.round(已完成数 / 总数 × 100)`（progressManual=false 时）
- 总数 = 0 时，进度显示为 "—"

## 五、assets.json

### 5.1 格式
JSON 对象，由 apply.ps1 自动生成，client.js 只读。

### 5.2 字段

| 字段 | 类型 | 说明 |
|------|------|------|
| generatedAt | string | 生成时间（ISO 格式） |
| docs.total | number | 文档总数 |
| docs.byType | object | 按类型统计的文档数 |
| packages | number | 目标包数（固定8） |
| scripts | number | 脚本数（scripts/ 下 .ps1 文件数） |
| snapshots | number | 快照数（snapshots/ 目录数） |
| codeLines.clientJs | number | client.js 总行数 |
| codeLines.totalModified | number | 修改的代码行数（估算） |

### 5.3 完整示例

```json
{
  "generatedAt": "2026-09-02T10:33:00+08:00",
  "docs": {
    "total": 53,
    "byType": {
      "core_memory": 3,
      "project_index": 5,
      "constraints": 8,
      "task_docs": 12,
      "dev_docs": 10,
      "test_docs": 5,
      "info": 10
    }
  },
  "packages": 8,
  "scripts": 17,
  "snapshots": 12,
  "codeLines": {
    "clientJs": 10150,
    "totalModified": 3200
  }
}
```

### 5.4 生成时机
- apply.ps1 执行时自动生成
- 不做实时扫描（性能考虑）
- client.js 提供"刷新统计"按钮，点击后提示用户重新 apply

## 十、数据加载优先级与回退

### 10.1 加载顺序
```
启动 DirectorView
  ↓
尝试从项目文件加载（config/*.json / docs/*.md）
  ├─ 成功 → 使用文件数据
  └─ 失败 → 尝试从 localStorage 加载
       ├─ 成功 → 使用 localStorage 数据
       └─ 失败 → 使用预设默认数据
```

### 10.2 保存顺序
```
数据修改
  ↓
写入项目文件（config/*.json / docs/*.md）
  ├─ 成功 → 完成
  └─ 失败 → 写入 localStorage（回退）
       ├─ 成功 → 显示警告"文件写入失败，已保存到浏览器存储"
       └─ 失败 → 显示错误
```

3. 迁移完成后保存为最新版本
