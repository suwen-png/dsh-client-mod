# V10 交互流程设计文档

> **版本**: V10-interaction-v1.0
> **日期**: 2026-09-02
> **定位**: 定义总监驾驶舱 V10 所有核心交互的完整流程
> **原则**: 每个交互有明确的触发条件、执行步骤、状态变化、异常处理

## 一、智能体调用流程（创建分支）

### 1.1 触发条件
- 用户在 D 区智能体列表中，点击某个智能体的"调用 →"按钮
- 该智能体必须是已启用状态（enabled=true）

### 1.2 完整流程

```
用户点击"调用 →"
    │
    ▼
① 前置检查
   ├─ 智能体是否已启用？
   │   └─ 否 → 显示 toast"该智能体已禁用，请先启用" → 终止
   ├─ Ollama 是否可用？
   │   └─ 否 → 显示 toast"Ollama 未连接，智能体无法执行" → 终止（仍创建分支，但提示）
   └─ 通过 → 继续

    │
    ▼
② 创建分支
   ├─ 生成 branchId = "{agentId}-{timestamp}"
   ├─ 创建分支对象 { branchId, agentId, agentLabel, createdAt, status:"active" }
   ├─ 写入 branches.json
   ├─ 设置 window.__dshCurrentBranch = 分支对象
   ├─ 触发自定义事件 "dsh-branch-created"（detail=分支对象）
   └─ DirectorView 监听事件 → 更新 currentBranch state + branchList

    │
    ▼
③ 切换到分支对话视图
   ├─ 过滤消息：只显示该分支创建后的消息 + 系统消息
   ├─ 在消息区插入系统消息："🤖 已创建【代码工程师】分支，智能体已就绪。"
   ├─ 显示分支状态栏（顶部）：分支名称 + 返回主线按钮
   └─ 焦点移到输入框

    │
    ▼
④ 智能体初始化（可选）
   ├─ 如果用户最近有消息，自动用该消息作为第一个任务
   │   └─ 调用 callLocalModel(agent.systemPrompt + 任务)
   │       ├─ 成功 → 插入 assistant 消息（智能体产出）
   │       └─ 失败 → 插入系统消息"智能体初始化失败：{原因}"
   └─ 如果没有最近消息，等待用户输入

    │
    ▼
⑤ 完成
   └─ 显示 toast"已创建【代码工程师】分支"
```

### 1.3 状态变化
| 状态项 | 变化前 | 变化后 |
|--------|--------|--------|
| currentBranch | null | 分支对象 |
| branchList | 原有列表 | 原有列表 + 新分支 |
| filteredMessages | 全部消息 | 分支过滤后的消息 |
| 分支状态栏 | 隐藏 | 显示 |

### 1.4 异常处理
- Ollama 不可用：仍创建分支，但提示用户"智能体将使用规则模板模式"
- 分支创建失败：显示错误，不切换视图
- 智能体初始化失败：不影响分支使用，用户可手动输入

## 二、技能调用流程（注入 Prompt）

### 2.1 触发条件
- 用户在 D 区技能列表中，点击某个技能的"调用 →"按钮
- 该技能必须是已启用状态
- 或者用户在输入框输入触发词（如 `/code`）后按回车

### 2.2 完整流程（按钮调用）

```
用户点击"调用 →"
    │
    ▼
① 前置检查
   ├─ 技能是否已启用？
   │   └─ 否 → toast"该技能已禁用" → 终止
   └─ 通过 → 继续

    │
    ▼
② 判断当前对话状态
   ├─ 有最近用户消息？
   │   ├─ 是 → 模式A：用技能处理最近一条用户消息
   │   └─ 否 → 模式B：将技能 prompt 作为系统消息，等待用户输入
   └─

    │
    ▼
③ 模式A：处理最近消息
   ├─ 插入系统消息："⚡ 调用【代码生成】技能处理：{消息摘要}"
   ├─ 设置 state.status = "calling-local-model"
   ├─ 调用 callLocalModel(skill.prompt + "\n\n## 待处理内容\n" + 用户消息)
   │   ├─ 成功 → 插入 assistant 消息（技能产出，Markdown 渲染）
   │   └─ 失败 → 插入系统消息"技能执行失败：{原因}"
   ├─ 设置 state.status = "done"
   └─ 保存对话历史

    │
    ▼
④ 模式B：等待输入
   ├─ 插入系统消息："⚡ 已加载【代码生成】技能，输入内容后将按该技能处理。"
   ├─ 设置 pendingSkill = skill 对象
   └─ 焦点移到输入框
   │
   └─ 用户输入消息后 → 自动使用 pendingSkill.prompt 处理 → 清除 pendingSkill

    │
    ▼
⑤ 完成
   └─ toast"已调用技能：{技能名称}"
```

### 2.3 触发词调用流程
```
用户在输入框输入 "/code 生成一个排序函数" → 按回车
    │
    ▼
① 解析触发词
   ├─ 匹配 /^\/(\w+)\s*(.*)$/
   ├─ trigger = "code", content = "生成一个排序函数"
   └─ 在 skills.json 中查找 trigger === "/code" 的技能
       ├─ 找到 → 继续
       └─ 未找到 → 作为普通消息发送 → 终止

    │
    ▼
② 执行技能
   └─ 同模式A：用 skill.prompt + content 调用本地模型
```

## 三、执行逻辑强制执行流程

### 3.1 触发条件
- 用户在 D 区执行逻辑列表中，点击某个规则的"强制执行"按钮
- 该规则的 triggerMode = "ondemand"（按需触发）
- 全局规则（triggerMode=global）不需要点击，开关开启后自动生效

### 3.2 完整流程

```
用户点击"强制执行"
    │
    ▼
① 前置检查
   ├─ 规则是否已启用？
   │   └─ 否 → toast"该规则已禁用" → 终止
   ├─ triggerMode === "ondemand"？
   │   └─ 否 → toast"该规则为全局规则，已自动生效" → 终止
   └─ 通过 → 继续

    │
    ▼
② 设置强制规则
   ├─ 设置 pendingForceRule = 规则对象
   ├─ 插入系统消息："📋 已强制加载【语言规范整理】规则，下一次 AI 回复将遵循该规则。"
   ├─ 显示 toast"已强制加载规则：{规则名称}"
   └─ 焦点移到输入框

    │
    ▼
③ 下一次 AI 回复时应用规则
   ├─ 用户输入消息 → 总监处理
   ├─ 在调用本地模型前，将 pendingForceRule.rules 追加到 prompt 中
   │   prompt = 原有 prompt + "\n\n## 强制规则\n" + pendingForceRule.rules
   ├─ 调用本地模型
   ├─ 模型返回后，审核返回内容是否遵循规则
   │   ├─ 遵循 → 正常显示
   │   └─ 不遵循 → 插入系统提示"返回内容未完全遵循强制规则，已标记"
   └─ 清除 pendingForceRule（一次性）

    │
    ▼
④ 完成
   └─ 规则已应用，pendingForceRule 清除
```

### 3.3 全局规则自动生效流程
```
总监处理消息时
    │
    ▼
检查 state.config.duties 中 enabled=true 的全局规则
    │
    ▼
按 triggerPhase 分类应用：
    ├─ input 阶段规则 → 在整理用户输入时应用（如语言规范整理）
    ├─ output 阶段规则 → 在审核模型返回时应用（如返回审核）
    └─ both → 两个阶段都应用
```

## 四、项目切换流程

### 4.1 触发条件
- 用户在 A 区点击"📁项目名 ▾"，在下拉列表中选择另一个项目

### 4.2 完整流程

```
用户选择新项目
    │
    ▼
① 保存当前项目数据
   ├─ 保存对话历史到 dsh.director.store.project.{currentProjectId}
   ├─ 保存项目总览（overview state → project_overview.md）
   ├─ 保存任务（tasks.json）
   ├─ 保存智能体/技能/执行逻辑配置（agents.json/skills.json/duties.json）
   └─ 保存当前分支状态

    │
    ▼
② 切换 currentProject
   ├─ 更新 currentProject state = 新项目 ID
   ├─ 写入 localStorage
   └─ 关闭项目下拉列表

    │
    ▼
③ 加载新项目数据
   ├─ 加载对话历史（从项目特定 key，无则空）
   ├─ 加载项目总览（project_overview.md）
   ├─ 加载任务（tasks.json）
   ├─ 加载智能体/技能/执行逻辑配置
   ├─ 加载分支列表（branches.json）
   └─ 重置 currentBranch = null

    │
    ▼
④ 刷新 UI
   ├─ 消息区显示新项目对话历史（或空状态）
   ├─ A 区项目名更新
   ├─ B 区项目总览更新
   ├─ D 区列表更新
   └─ 分支状态栏隐藏

    │
    ▼
⑤ 完成
   └─ toast"已切换到项目：{新项目名称}"
```

## 五、设置弹窗交互流程

### 5.1 触发条件
- 用户在 A 区点击"⚙️"按钮

### 5.2 完整流程

```
用户点击 ⚙️
    │
    ▼
① 打开弹窗
   ├─ settingsOpen = true
   ├─ settingsTab = "general"（默认通用设置 tab）
   └─ 弹窗显示在 ⚙️ 按钮下方

    │
    ▼
② 切换 tab
   ├─ 用户点击 tab 栏（通用/模型/执行逻辑/数据）
   ├─ 更新 settingsTab state
   └─ 内容区切换显示对应设置

    │
    ▼
③ 修改设置
   ├─ 开关/输入/滑块/下拉修改
   ├─ 实时更新 state.config
   ├─ 实时保存到 localStorage（dsh.director.config）
   └─ 部分设置即时生效（如外观主题色、自动转发）

    │
    ▼
④ 数据操作（数据 tab）
   ├─ 导出对话 → 生成 JSON 文件下载
   ├─ 导入对话 → 选择文件 → 解析 → 追加到当前对话
   ├─ 清除缓存 → 确认弹窗 → 删除缓存目录 → 提示重启
   └─ 重置数据 → 二次确认 → 清除所有总监数据 → 恢复默认

    │
    ▼
⑤ 关闭弹窗
   ├─ 点击"完成"按钮 → settingsOpen = false
   ├─ 点击弹窗外部 → settingsOpen = false
   └─ 按 ESC 键 → settingsOpen = false
```

## 六、查看/编辑/新建弹窗交互流程

### 6.1 查看弹窗

```
用户点击"查看"
    │
    ▼
① 打开查看弹窗
   ├─ viewModal = { type: "agent"|"skill"|"logic", data: 对应对象 }
   └─ 弹窗显示（只读）

    │
    ▼
② 查看内容
   ├─ 智能体：名称/描述/状态/模型/创建时间/调用次数 + system prompt（只读滚动）
   ├─ 技能：触发词/描述/状态/使用次数 + skill prompt（只读滚动）
   └─ 执行逻辑：名称/描述/状态/触发方式/触发次数 + 规则内容（只读滚动）

    │
    ▼
③ 操作
   ├─ 点击"编辑" → 关闭查看弹窗 → 打开编辑弹窗（预填数据）
   ├─ 点击"调用"/"强制执行" → 执行对应操作（见流程一/二/三）
   └─ 点击 × / 外部 / ESC → 关闭弹窗
```

### 6.2 编辑弹窗

```
用户点击"编辑"（或从查看弹窗进入）
    │
    ▼
① 打开编辑弹窗
   ├─ editModal = { type, data: 原对象副本 }
   └─ 表单预填原数据

    │
    ▼
② 修改表单
   ├─ 名称/图标/描述/prompt或规则/启用状态等
   ├─ 实时更新 editModal.data
   └─ 不立即保存

    │
    ▼
③ 保存或取消
   ├─ 点击"保存" →
   │   ├─ 验证必填字段（名称/prompt或规则）
   │   ├─ 验证通过 → 写入对应 JSON 文件 → 更新 state → 关闭弹窗 → toast"已保存"
   │   └─ 验证失败 → 显示错误提示，不关闭
   └─ 点击"取消"/×/外部/ESC → 不保存，关闭弹窗
```

### 6.3 新建弹窗

```
用户点击"+ 新建"
    │
    ▼
① 打开新建表单
   ├─ newModalOpen = true
   ├─ 根据当前 dNavTab 决定表单类型（智能体/技能/执行逻辑）
   └─ 表单空白，有默认值

    │
    ▼
② 填写表单
   ├─ 智能体：名称（必填）/图标/描述/system prompt（必填）/模型/启用
   ├─ 技能：名称（必填）/触发词（自动生成 /name，可修改）/描述/prompt（必填）/启用
   └─ 执行逻辑：名称（必填）/描述/规则内容（必填）/触发方式/启用

    │
    ▼
③ 创建或取消
   ├─ 点击"创建" →
   │   ├─ 验证必填字段
   │   ├─ 生成 id（名称转小写+时间戳）
   │   ├─ 写入对应 JSON 文件
   │   ├─ 更新 state（列表新增）
   │   ├─ 关闭弹窗
   │   └─ toast"已创建：{名称}"
   └─ 点击"取消" → 不保存，关闭弹窗
```

## 七、分支管理流程

### 7.1 查看分支列表
```
用户点击 A 区"🚀驾驶舱" → "📋 分支管理"
    │
    ▼
打开分支管理面板
    ├─ 显示所有 active 分支列表
    ├─ 每项：智能体图标 + 名称 + 创建时间 + 消息数 + 最后活跃时间
    ├─ 当前分支高亮显示
    └─ 操作按钮：切换 / 重命名 / 归档
```

### 7.2 切换分支
```
用户点击分支的"切换"
    │
    ▼
① 保存当前分支状态（消息数/最后活跃时间）
② 更新 currentBranch = 目标分支
③ 过滤消息（目标分支创建后的消息）
④ 显示分支状态栏
⑤ toast"已切换到分支：{名称}"
```

### 7.3 返回主线
```
用户点击分支状态栏的"返回主线"
    │
    ▼
① 保存当前分支状态
② currentBranch = null
③ 显示全部消息
④ 隐藏分支状态栏
⑤ toast"已返回主线对话"
```

## 八、交互异常处理总览

| 异常场景 | 处理方式 |
|----------|---------|
| Ollama 未连接 | 智能体/技能调用时显示明确提示，仍创建分支但使用规则模板 |
| 数据文件读写失败 | 回退到 localStorage，显示警告"文件写入失败，已保存到浏览器存储" |
| 表单验证失败 | 显示具体错误提示，不关闭弹窗，高亮错误字段 |
| 分支创建失败 | 显示错误，不切换视图，保留当前状态 |
| 智能体初始化失败 | 不影响分支使用，插入系统消息"智能体初始化失败：{原因}"，用户可手动输入 |
| 技能执行失败 | 插入系统消息"技能执行失败：{原因}"，状态恢复为idle，用户可重试 |
| 项目切换时数据加载失败 | 使用空数据，显示警告"项目数据加载失败，将使用默认配置" |
| 弹窗外部点击 | 关闭弹窗，未保存的修改丢弃（编辑/新建） |
| ESC 键 | 关闭所有弹窗 |
| 列表为空 | 显示空状态提示+引导新建（见D区设计文档§11.1） |
| 搜索无结果 | 显示"未找到匹配项"+清除搜索按钮（见D区设计文档§11.2） |
| 删除操作 | 二次确认对话框，确认后才删除（见D区设计文档§11.3） |
| 新建重名 | 不关闭弹窗，显示红色提示"该名称已存在"（见D区设计文档§11.4） |
| 技能触发词冲突 | 不关闭弹窗，显示红色提示"触发词已被使用"（见D区设计文档§11.5） |
