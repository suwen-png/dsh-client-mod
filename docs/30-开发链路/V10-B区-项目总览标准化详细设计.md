# B 区 · 项目总览标准化详细设计文档

> **版本**: V10-design-v1.0
> **日期**: 2026-09-02
> **区域定位**: 总监页面 A 区下方的项目总览条，可折叠，数据全部由总监文档维护
> **核心原则**: 数据驱动，不前端写死；文档是唯一数据源，UI 只读展示+自动统计

---

## 一、区域概述

B 区是项目总览信息展示条，位于 A 区导航栏下方。点击 header 可展开/收起。展开时显示 7 张信息卡片，所有数据从项目文档加载，自动统计，不再前端写死。

### 布局结构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ ▾ 项目总览（定位 / 目标 / 阶段 / 进度 / 风险 / 待办 / 项目资产）  点击收起 │ ← header（可点击折叠）
├─────────────────────────────────────────────────────────────────────────────┤
│ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────┐ ┌──────┐ ┌──────────┐ │
│ │  定位     │ │  目标     │ │  阶段     │ │  进度     │ │ 风险   │ │ 待办 │ │ 项目资产  │ │ ← 7张卡片
│ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └────────┘ └──────┘ └──────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 折叠状态
- 收起时：只显示 header 行（高度 28px），文字为"▶ 项目总览（定位/目标/进度/风险/待办）"
- 展开时：显示 header + 7 张卡片（高度约 80px）
- 折叠状态持久化到 localStorage（`dsh.director.overview.collapsed`）

### 2.4 进度卡片

| 属性 | 值 |
|------|-----|
| 标题 | 进度 |
| 数据来源 | 自动计算（待办完成率）或手动覆盖 |
| 显示内容 | 百分比数字 + 进度条 |
| 进度条颜色 | ≥80% 绿色 / ≥50% 蓝色 / <50% 橙色 |
| 交互 | 悬停显示"自动计算（待办完成率）"或"手动设置"；编辑模式可手动输入 |

**计算公式**:
```
进度 = Math.round(已完成待办数 / 总待办数 × 100)
```
- 总待办数 = 0 时，进度显示为"—"（不计算）
- 用户手动覆盖后，显示"手动"标记，不再自动计算
- 取消手动覆盖后，恢复自动计算

### 2.7 项目资产卡片（新增）

| 属性 | 值 |
|------|-----|
| 标题 | 项目资产 |
| 数据来源 | `assets.json`（apply.ps1 生成，非实时扫描） |
| 显示内容 | "53 文档 · 8 包 · 17 脚本"（单行） |
| 颜色 | 绿色文字 |
| 交互 | 悬停显示详细统计 tooltip；点击"刷新统计"按钮重新生成 |

**资产统计项**:
| 统计项 | 说明 | 来源 |
|--------|------|------|
| 文档数 | docs/ 目录下 markdown 文件数 | apply.ps1 扫描 |
| 包数 | workspace/@deepseek-ai/ 下的包数 | 固定 8 个 |
| 脚本数 | scripts/ 目录下 .ps1 文件数 | apply.ps1 扫描 |
| 代码行数 | client.js 总行数（可选） | apply.ps1 统计 |
| 快照数 | snapshots/ 目录数 | apply.ps1 扫描 |

**刷新机制**:
- 不做实时扫描（性能考虑）
- apply.ps1 执行时自动生成 `config/assets.json`
- client.js 启动时读取该 JSON
- 提供"刷新统计"按钮，点击后调用 apply.ps1 的统计逻辑（或提示用户重新 apply）

## 三、文档数据源格式定义

### 3.1 project_overview.md

**位置**: `docs/00-统筹入口/project_overview.md`（或项目根目录）

**格式**: Markdown + YAML Front Matter

```markdown
---
positioning: "DeepSeek Harness 原客户端修改工作区，实现总监对话模式"
goal: "完成 V10 总监驾驶舱重构，三tab共存，文档索引53篇"
phase: "开发中"
progress: 65
progressManual: false
createdAt: "2026-08-27"
updatedAt: "2026-09-02"
---

# 项目总览

## 详细描述
（项目的详细背景、范围、约束等，自由文本）

## 里程碑
- [x] V7 基础总监对话
- [x] V8 文档体系
- [x] V9 总监驾驶舱 UI
- [ ] V10 布局重构（进行中）
- [ ] V11 智能体体系完善
```

**字段说明**:
| 字段 | 类型 | 说明 |
|------|------|------|
| positioning | string | 项目定位（B区定位卡片） |
| goal | string | 项目目标（B区目标卡片） |
| phase | string | 当前阶段（B区阶段卡片+A区阶段标签） |
| progress | number | 进度百分比（0-100），progressManual=false 时被自动计算覆盖 |
| progressManual | boolean | 是否手动设置进度，true 时不自动计算 |

---

### 3.2 risks.md

**位置**: `docs/00-统筹入口/risks.md`

**格式**: Markdown 列表，每项有元数据

```markdown
# 项目风险记录

## 未关闭

### [高] 编译产物修改风险高
- **发现日期**: 2026-08-28
- **描述**: 修改 client.js 编译产物，语法错误会导致 Harness 白屏
- **缓解措施**: 每次修改后 node --check 验证，apply 前自动快照
- **状态**: open

### [中] Ollama 服务不稳定
- **发现日期**: 2026-09-01
- **描述**: 本地模型调用超时或失败，总监回退到规则模板模式
- **缓解措施**: 增加超时重试，未连接时显示明确引导
- **状态**: open

## 已关闭

### [低] PowerShell 5.1 中文乱码
- **发现日期**: 2026-09-01
- **关闭日期**: 2026-09-01
- **解决方案**: 所有 .ps1 文件加 UTF-8 BOM
- **状态**: closed
```

**解析规则**:
- `## 未关闭` 下的所有 `###` 项 = 未关闭风险
- 未关闭风险数 = B 区风险卡片显示的数字
- 严重程度从标题 `[高]/[中]/[低]` 提取

---

### 3.3 tasks.json

**位置**: `config/tasks.json`（项目目录下，非 docs/）

**格式**: JSON 数组

```json
[
  {
    "id": 1,
    "title": "完成 V10 布局重构设计文档",
    "status": "done",
    "priority": "high",
    "createdAt": 1756800000000,
    "completedAt": 1756886400000,
    "branch": "main"
  },
  {
    "id": 2,
    "title": "A 区整合导航栏代码实现",
    "status": "todo",
    "priority": "high",
    "createdAt": 1756886400000,
    "branch": "main"
  }
]
```

**字段说明**:
| 字段 | 类型 | 说明 |
|------|------|------|
| id | number | 唯一标识 |
| title | string | 任务标题 |
| status | string | todo / doing / done |
| priority | string | high / medium / low |
| createdAt | number | 创建时间戳 |
| completedAt | number/null | 完成时间戳 |
| branch | string | 所属分支 |

**统计规则**:
- 未完成待办数 = status !== "done" 的数量
- 已完成数 = status === "done" 的数量
- 进度 = 已完成数 / 总数 × 100%（progressManual=false 时）

## 四、数据加载流程

### 4.1 启动时加载

```
DirectorView 挂载
  ↓
loadOverviewFromDocs() 并行加载:
  ├─ 读取 project_overview.md → 解析 YAML → positioning/goal/phase/progress
  ├─ 读取 risks.md → 解析未关闭风险数
  ├─ 读取 tasks.json → 解析待办数/已完成数
  └─ 读取 assets.json → 项目资产统计
  ↓
computeStats() 自动计算:
  ├─ progress = 已完成待办/总待办 × 100（progressManual=false 时）
  ├─ riskCount = 未关闭风险数
  └─ todoCount = 未完成待办数
  ↓
setOverview() 更新 state → UI 渲染
```

### 4.2 编辑后保存

```
用户点击"编辑" → 打开编辑面板
  ↓
修改字段 → 点击"保存"
  ↓
saveOverviewToDocs() 并行写入:
  ├─ 更新 project_overview.md 的 YAML Front Matter
  ├─ 新增/关闭风险 → 更新 risks.md
  └─ 新增/完成任务 → 更新 tasks.json
  ↓
重新 loadOverviewFromDocs() + computeStats()
  ↓
UI 刷新显示最新数据
```

## 五、代码架构说明（AI 修改指南）

B 区代码分为 **三层**，新增功能时按层修改：

### 第一层：文档层（数据源）
- **位置**: `docs/00-统筹入口/project_overview.md`、`risks.md`、`config/tasks.json`、`config/assets.json`
- **修改场景**: 新增项目信息字段、修改文档格式、增加统计维度
- **注意**: 修改文档格式后必须同步修改解析函数

### 第二层：状态层（React State）
- **位置**: DirectorView 中的 `overview` state、`loadOverviewFromDocs()` 函数、`saveOverviewToDocs()` 函数
- **修改场景**: 新增 state 字段、修改加载/保存逻辑、增加数据转换
- **注意**: state 字段必须与文档字段一一对应

### 第三层：统计层（自动计算）
- **位置**: `computeStats()` 函数
- **修改场景**: 新增统计指标、修改计算公式、增加统计条件
- **注意**: 统计函数必须纯函数（输入 state，输出统计结果，无副作用）

### 第四层：展示层（JSX）
- **位置**: DirectorView return 中的 B 区 JSX
- **修改场景**: 新增卡片、修改卡片样式、增加交互
- **注意**: 卡片只从 overview state 读数据，不直接操作文档
