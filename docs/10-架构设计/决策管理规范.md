## 一、文档概述

### 1.1 目的

本文档定义**决策分级、决策流程、影响分析、追溯、复盘**的完整规范，确保：
1. 决策按级别分配权限，不越权不推诿
2. 决策有结构化流程，不凭感觉拍脑袋
3. 决策影响被充分评估，不忽视副作用
4. 决策可追溯，知道谁在什么时候基于什么做了什么决策
5. 决策有复盘，从成功和失败中学习
6. AI 正确辅助决策，不替人类做最终决策

### 1.2 适用范围

| 决策类型 | 是否适用 | 说明 |
|---------|:-------:|------|
| 项目方向/战略调整 | ✅ 强制适用 | 战略级决策，必须完整流程 |
| 架构设计/技术选型 | ✅ 适用 | 战术级决策，需完整流程 |
| 任务执行方式选择 | ⚠️ 简化适用 | 操作级决策，可简化流程 |
| 简单明确的选择 | ❌ 不适用 | 无需走决策流程 |
| 紧急情况决策 | ⚠️ 特殊适用 | 可简化流程，但事后必须补记录和复盘 |

### 1.3 与其他文档关系

| `人机协作规范.md` | 决策中的人机协作边界，本文档定义决策流程 |

## 二、决策分级

### 2.1 三级决策体系

| 级别 | 名称 | 定义 | 决策者 | 流程要求 | 记录要求 |
|:----:|------|------|:------:|:--------:|:--------:|
| **D1** | 战略决策 | 影响项目方向/核心规则/长期目标/不可逆操作 | 人类 | 完整7步流程+影响分析+风险评估 | 完整记录+复盘 |
| **D2** | 战术决策 | 影响架构/技术选型/流程变更/中等范围 | AI建议+人类确认 | 简化5步流程+影响评估 | 记录+可选复盘 |
| **D3** | 操作决策 | 影响单个任务/执行方式/小范围选择 | AI自主 | 3步快速决策 | 简要记录 |

### 2.2 各级别决策示例

| 级别 | 示例 |
|:----:|------|
| D1 战略 | 项目方向调整、核心规则变更、技术栈切换、不可逆操作、生产环境部署、安全策略变更 |
| D2 战术 | 架构设计、技术选型、流程变更、工具选择、规范文档修改、目录结构调整 |
| D3 操作 | 任务执行顺序、代码实现方式、文档组织结构、简单工具选择、命名选择 |

### 2.3 决策级别判断流程

```
决策是否影响项目方向/核心规则？
├─ 是 → D1 战略决策
└─ 否 → 决策是否不可逆？
    ├─ 是 → D1 战略决策
    └─ 否 → 决策是否影响架构/流程/规范？
        ├─ 是 → D2 战术决策
        └─ 否 → 决策是否影响多个任务/多人？
            ├─ 是 → D2 战术决策
            └─ 否 → D3 操作决策
```

### 2.4 决策权限矩阵

| 决策级别 | AI提议 | AI分析 | AI执行 | 人类确认 | 人类决策 |
|:--------:|:------:|:------:|:------:|:--------:|:--------:|
| D1 战略 | ✅ | ✅ | ❌ | ✅ | ✅ |
| D2 战术 | ✅ | ✅ | ✅ | ✅ | ❌ |
| D3 操作 | ✅ | ✅ | ✅ | ❌ | ❌ |

**规则**：
- AI 可以提议和分析任何级别的决策
- AI 可以执行 D2/D3 决策，D1 决策由人类执行
- D1/D2 决策必须人类确认，AI 不能自行决策
- 紧急情况下 AI 可临时执行 D1 决策，但必须立即通知人类并事后补确认

## 三、决策流程

### 3.1 7步标准决策流程（D1战略决策）

```
1.问题定义 → 2.信息收集 → 3.方案生成 → 4.方案评估 → 5.决策 → 6.执行 → 7.复盘
```

### 3.2 各步骤详解

#### 步骤1：问题定义

**输入**：决策需求/问题描述
**输出**：清晰的问题定义+决策目标

| 检查项 | 说明 |
|--------|------|
| 问题是什么 | 清晰描述需要决策的问题 |
| 为什么需要决策 | 决策的背景和动机 |
| 决策目标是什么 | 决策要达到什么效果（SMART） |
| 决策范围是什么 | 决策包含什么，不包含什么 |
| 决策时限 | 什么时候必须做出决策 |
| 决策者是谁 | 谁负责做最终决策 |

#### 步骤2：信息收集

**输入**：问题定义
**输出**：决策所需的完整信息

| 检查项 | 说明 |
|--------|------|
| 相关规范 | 项目规范/标准/约束 |
| 历史数据 | 类似决策的历史记录和结果 |
| 现状分析 | 当前状态和问题分析 |
| 外部信息 | 行业最佳实践/工具能力/资源情况 |
| 利益相关方 | 受决策影响的人和他们的诉求 |
| 风险信息 | 相关风险和约束 |

**信息不足时**：
- 明确列出缺失的信息
- 评估信息缺失对决策的影响
- 如关键信息缺失，暂缓决策或做有条件决策

#### 步骤3：方案生成

**输入**：问题定义+收集的信息
**输出**：至少2个可行方案

| 检查项 | 说明 |
|--------|------|
| 方案数量 | 至少2个可行方案（不包括"不做"） |
| 方案多样性 | 方案应有本质差异，不是细微调整 |
| 方案可行性 | 每个方案都应是可执行的 |
| 方案描述 | 每个方案包含：做法/步骤/资源需求/时间预估 |
| 极端方案 | 考虑最优/最差/折中方案 |
| 创新方案 | 考虑非传统的创新方案 |

**方案生成方法**：
- 头脑风暴：先不评价，尽可能多生成方案
- 类比法：参考类似问题的解决方案
- 逆向思维：从目标倒推方案
- 组合法：组合不同方案的优点

#### 步骤4：方案评估

**输入**：多个可行方案
**输出**：方案评估矩阵+推荐方案

| 评估维度 | 说明 | 权重 |
|---------|------|:----:|
| 有效性 | 能多大程度解决问题 | 30% |
| 可行性 | 执行难度和资源需求 | 20% |
| 成本 | 时间/人力/资源成本 | 15% |
| 风险 | 方案的风险和不确定性 | 15% |
| 影响 | 对其他方面的影响（正面/负面） | 10% |
| 可持续性 | 长期效果和可维护性 | 10% |

**评估方法**：
- 评分法：每个方案每个维度1-5分，加权求和
- 对比法：方案两两对比，列出优缺点
- 风险矩阵：评估每个方案的风险概率和影响
- 成本收益分析：量化成本和收益

**输出**：
- 方案评估矩阵（评分表）
- 每个方案的优缺点
- 推荐方案及理由
- 不推荐方案的原因

#### 步骤5：决策

**输入**：方案评估结果
**输出**：最终决策+决策依据

| 检查项 | 说明 |
|--------|------|
| 决策者确认 | 正确级别的决策者做出决策 |
| 决策依据 | 基于什么信息和分析做出决策 |
| 决策内容 | 明确选择了哪个方案 |
| 决策条件 | 决策的前提条件和假设 |
| 决策范围 | 决策适用的范围和边界 |
| 异议记录 | 如有异议，记录异议内容 |
| 决策时间 | 决策做出的时间 |

**D1决策必须**：
- 人类明确确认
- 完整记录决策依据
- 评估所有方案的风险
- 考虑长期影响

#### 步骤6：执行

**输入**：最终决策
**输出**：执行结果

| 检查项 | 说明 |
|--------|------|
| 执行计划 | 详细的执行步骤和时间线 |
| 资源准备 | 所需资源已准备好 |
| 风险应对 | 执行中的风险应对措施 |
| 分步执行 | 按计划分步执行，每步验证 |
| 进度跟踪 | 实时跟踪执行进度 |
| 异常处理 | 遇到异常及时调整 |
| 执行记录 | 记录执行过程和结果 |

#### 步骤7：复盘

**输入**：执行结果
**输出**：复盘报告+经验教训

详见 §六 决策复盘

### 3.3 简化决策流程（D2战术决策）

```
1.问题定义 → 2.信息收集 → 3.方案生成(≥2个) → 4.方案评估 → 5.决策(人类确认) → 6.执行
```

- 跳过正式复盘（可选）
- 记录决策依据和结果
- 如决策结果不佳，补做复盘

### 3.4 快速决策流程（D3操作决策）

```
1.明确问题 → 2.考虑选项 → 3.选择并执行
```

- AI 自主决策
- 简要记录决策内容
- 如决策错误，记录并改进

### 3.5 紧急决策流程

```
1.评估紧急程度 → 2.快速收集关键信息 → 3.选择最安全方案 → 4.执行 → 5.立即通知人类 → 6.事后补记录+复盘
```

**紧急决策原则**：
- 安全第一，选择风险最低的方案
- 不可逆操作不做紧急决策
- 执行后立即通知人类
- 事后必须补完整记录和复盘

## 四、决策影响分析

### 4.1 影响范围评估

| 影响维度 | 说明 | 评估内容 |
|---------|------|---------|
| 范围影响 | 影响哪些项目/模块/文档 | 直接影响+间接影响 |
| 人员影响 | 影响哪些人 | 开发者/用户/审核者/其他 |
| 时间影响 | 影响时间线 | 短期/中期/长期 |
| 资源影响 | 影响资源分配 | 人力/工具/环境/预算 |
| 技术影响 | 影响技术架构 | 兼容性/性能/可维护性 |
| 流程影响 | 影响工作流程 | 流程变更/新增步骤/减少步骤 |
| 规范影响 | 影响规范体系 | 需更新哪些规范文档 |
| 风险影响 | 引入或消除哪些风险 | 新增风险/消除风险/风险变化 |

### 4.2 影响程度评估

| 影响程度 | 定义 | 说明 |
|:--------:|------|------|
| 🔴 严重 | 不可逆/影响核心/影响多人/长期影响 | 必须D1决策，完整影响分析 |
| 🟠 较大 | 可恢复但成本高/影响多模块/中期影响 | D1/D2决策，详细影响分析 |
| 🟡 中等 | 可恢复/影响单个模块/短期影响 | D2决策，基本影响分析 |
| 🟢 轻微 | 易恢复/影响小范围/临时影响 | D3决策，简要影响评估 |

### 4.3 副作用评估

| 检查项 | 说明 |
|--------|------|
| 正面副作用 | 决策带来的意外好处 |
| 负面副作用 | 决策带来的意外问题 |
| 连锁反应 | 决策引发的连锁影响 |
| 机会成本 | 选择此方案放弃的其他机会 |
| 长期影响 | 长期来看的潜在影响 |

## 五、决策追溯

### 5.1 决策记录要求

| 决策级别 | 记录要求 | 记录位置 |
|:--------:|---------|---------|
| D1 战略 | 完整记录（问题/信息/方案/评估/决策/执行/复盘） | 10-决策日志.md + 单独决策文档 |
| D2 战术 | 基本记录（问题/方案/决策/结果） | 10-决策日志.md |
| D3 操作 | 简要记录（决策内容+结果） | 任务记录中 |
| 紧急决策 | 事后补完整记录 | 10-决策日志.md + 复盘 |

### 5.2 决策日志字段

详见 `10-决策日志.md`，包含：
- 决策编号（DEC-XXX）
- 决策标题
- 决策级别（D1/D2/D3）
- 决策背景
- 可选方案
- 决策结果
- 决策依据
- 决策者
- 决策日期
- 影响分析
- 预期结果
- 实际结果（复盘时填写）
- 复盘结论（复盘时填写）

### 5.3 决策可追溯性

| 追溯需求 | 实现方式 |
|---------|---------|
| 谁做的决策 | 决策者字段 |
| 什么时候做的 | 决策日期字段 |
| 基于什么信息 | 决策依据字段+信息收集记录 |
| 考虑了哪些方案 | 可选方案字段 |
| 为什么选这个方案 | 决策依据+方案评估记录 |
| 决策影响什么 | 影响分析字段 |
| 决策结果如何 | 实际结果+复盘结论字段 |

### 5.4 决策变更管理

| 场景 | 处理方式 |
|------|---------|
| 决策条件变化 | 重新评估决策，必要时变更 |
| 决策执行受阻 | 分析原因，调整执行方式或变更决策 |
| 决策效果不佳 | 启动复盘，分析原因，必要时变更决策 |
| 新信息出现 | 评估新信息对决策的影响，必要时变更决策 |

**决策变更必须**：
- 记录变更原因
- 重新走决策流程（至少简化流程）
- 通知受影响的人
- 更新决策日志

## 六、决策复盘

### 6.1 复盘时机

| 时机 | 说明 | 决策级别 |
|------|------|:--------:|
| 决策执行完成后 | 验证决策效果 | D1必须，D2可选 |
| 决策效果不佳时 | 分析失败原因 | 所有级别 |
| 定期复盘 | 回顾一段时间内的决策 | 月度/季度 |
| 重大事故后 | 分析决策是否导致事故 | 必须 |

### 6.2 复盘流程

```
1.回顾决策 → 2.对比预期与实际 → 3.分析偏差原因 → 4.总结经验教训 → 5.提出改进 → 6.更新知识库
```

### 6.3 复盘内容

| 检查项 | 说明 |
|--------|------|
| 决策回顾 | 当时的问题、方案、决策是什么 |
| 预期结果 | 决策后期望达到什么效果 |
| 实际结果 | 实际达到了什么效果 |
| 偏差分析 | 预期与实际的偏差是什么 |
| 原因分析 | 为什么会有偏差（信息不足/分析错误/判断失误/外部变化/执行问题） |
| 做得好的 | 决策中哪些做得好，值得保持 |
| 做得不好的 | 决策中哪些做得不好，需要改进 |
| 经验教训 | 从这次决策中学到了什么 |
| 改进措施 | 未来如何改进决策质量 |

### 6.4 根因分析（决策失败时）

使用5Why法分析决策失败的根因：

**示例**：决策选择了错误的技术方案
1. Why：为什么选择了错误的方案？→ 方案评估时高估了可行性
2. Why：为什么高估了可行性？→ 信息收集不充分，不了解技术限制
3. Why：为什么信息收集不充分？→ 决策流程中跳过了信息收集步骤
4. Why：为什么跳过了信息收集步骤？→ 急于决策，没有严格按流程执行
5. Why（根本原因）：没有强制执行决策流程，决策质量依赖个人自觉

**改进措施**：
- 强制执行决策流程检查清单
- D1/D2决策必须有信息收集记录
- 决策前必须有至少2个方案的评估

### 6.5 经验教训沉淀

| 沉淀方式 | 说明 |
|---------|------|
| 更新决策规范 | 将经验教训更新到本文档 |
| 更新检查清单 | 将经验教训更新到决策检查清单 |
| 记录到决策日志 | 在决策日志的复盘结论中记录 |
| 分享最佳实践 | 将成功的决策方法分享给团队 |
| 更新培训材料 | 将经验教训纳入新人培训 |

## 七、AI在决策中的角色

### 7.1 AI 可以做的

| 角色 | 说明 | 决策级别 |
|------|------|:--------:|
| 问题定义辅助 | 帮助清晰定义问题和决策目标 | 所有级别 |
| 信息收集 | 主动收集相关信息和数据 | 所有级别 |
| 方案生成 | 生成多个可行方案 | 所有级别 |
| 方案评估 | 分析各方案的优缺点和风险 | 所有级别 |
| 推荐方案 | 基于分析推荐最优方案 | 所有级别 |
| 执行决策 | 按决策执行 | D2/D3 |
| 跟踪效果 | 跟踪决策执行效果 | 所有级别 |
| 复盘辅助 | 辅助复盘，分析偏差原因 | 所有级别 |

### 7.2 AI 不能做的

| 禁止行为 | 原因 |
|---------|------|
| 替人类做D1战略决策 | 战略决策必须人类负责 |
| 隐瞒不利信息 | 决策需要完整信息，不能只报喜不报忧 |
| 只提供一个方案 | 必须提供至少2个方案，避免锚定效应 |
| 伪造分析数据 | 方案评估必须基于真实数据 |
| 跳过决策流程 | 必须按流程执行，不跳步 |
| 隐瞒方案风险 | 必须充分披露每个方案的风险 |
| 决策后不跟踪 | 必须跟踪决策效果，验证是否达到预期 |

### 7.3 AI 决策辅助原则

| 原则 | 说明 |
|------|------|
| **客观中立** | 不偏向任何方案，客观分析优缺点 |
| **完整披露** | 完整披露信息、方案、风险，不隐瞒 |
| **多方案对比** | 至少提供2个方案，对比分析 |
| **数据驱动** | 基于数据和事实分析，不凭感觉 |
| **风险敏感** | 充分评估每个方案的风险 |
| **可解释** | 分析过程和推荐理由清晰可解释 |
| **尊重人类决策** | AI只提供建议，最终决策由人类做出 |

### 7.4 AI 决策质量自检

决策辅助完成后，AI必须自检：

- [ ] 问题定义是否清晰
- [ ] 信息收集是否充分
- [ ] 是否提供了至少2个方案
- [ ] 方案评估是否客观
- [ ] 风险是否充分披露
- [ ] 推荐理由是否清晰
- [ ] 影响分析是否完整
- [ ] 决策级别判断是否正确
- [ ] 是否需要人类确认
