## 一、文档概述

### 1.1 目的

本文档定义**项目依赖管理、环境配置、版本控制、影响分析**的完整规范，确保：
1. 项目依赖清晰可追溯，不遗漏关键依赖
2. 依赖版本稳定，不出现意外升级导致的问题
3. 环境配置一致，减少"在我机器上能跑"的问题
4. 依赖变更有评估，不盲目升级
5. 关键依赖有替代方案，不出现单点故障
6. 环境问题能快速诊断和解决

### 1.2 适用范围

| 场景 | 是否适用 | 说明 |
|------|:-------:|------|
| 项目环境搭建 | ✅ 强制适用 | 新项目/新环境必须按规范搭建 |
| 依赖安装/升级 | ✅ 强制适用 | 任何依赖变更必须按规范执行 |
| 环境配置修改 | ✅ 适用 | 环境配置变更必须记录和验证 |
| 环境问题排查 | ✅ 适用 | 按诊断流程排查环境问题 |
| 简单任务执行 | ⚠️ 简化适用 | 只需检查关键依赖是否可用 |
| 普通办公/闲聊 | ❌ 不适用 | 不走环境管理流程 |

### 1.3 与其他文档关系

| 文档 | 关系 |
|------|------|
| `项目风险管理规范.md` | 依赖变更风险是风险的一种，本文档定义具体管理方法 |
| `应急与回滚规范.md` | 环境问题应急处理，本文档定义预防和诊断 |
| `决策管理规范.md` | 依赖升级是D2战术决策，需按决策流程执行 |
| `人机协作规范.md` | 环境问题需要人类介入时，按协作规范执行 |

## 二、依赖分类与清单

### 2.1 六类依赖

| 类别 | 说明 | 示例 |
|------|------|------|
| **工具依赖** | 项目使用的工具和软件 | Node.js、Python、Git、PowerShell、WebStorm |
| **库依赖** | 项目引用的代码库和框架 | React、Vue、Lodash、SuiteScript API |
| **服务依赖** | 项目依赖的外部服务 | NetSuite API、GitHub、npm、云存储 |
| **环境依赖** | 运行环境要求 | OS版本、浏览器版本、网络环境、VPN |
| **配置依赖** | 项目依赖的配置项 | 环境变量、配置文件、权限设置 |
| **数据依赖** | 项目依赖的数据和文件 | 数据库、配置数据、模板文件、参考文档 |

### 2.2 依赖清单模板

每个项目必须维护依赖清单，包含以下字段：

| 字段 | 说明 | 必填 |
|------|------|:----:|
| 依赖编号 | DEP-XXX | ✅ |
| 依赖名称 | 依赖的名称 | ✅ |
| 依赖类别 | 工具/库/服务/环境/配置/数据 | ✅ |
| 版本号 | 当前使用的版本 | ✅（如适用） |
| 用途说明 | 这个依赖用来做什么 | ✅ |
| 重要程度 | 关键/重要/一般/可选 | ✅ |
| 安装方式 | 如何安装/配置这个依赖 | ✅ |
| 官方文档 | 官方文档链接 | 推荐 |
| 替代方案 | 如不可用，有什么替代方案 | 关键依赖必填 |
| 最后验证日期 | 最后一次验证可用的日期 | ✅ |
| 备注 | 其他需要记录的信息 | 可选 |

### 2.3 依赖清单维护规则

| 规则 | 说明 |
|------|------|
| **新增依赖** | 新增任何依赖必须更新依赖清单，说明用途和版本 |
| **移除依赖** | 移除依赖必须更新清单，说明移除原因 |
| **版本变更** | 依赖版本变更必须更新清单，记录变更原因和日期 |
| **定期验证** | 每月验证关键依赖是否可用，更新最后验证日期 |
| **清单位置** | 依赖清单存放在 `docs/00-统筹入口/12-依赖清单.md` |
| **项目特殊依赖** | 各项目可在项目文档中维护自己的特殊依赖 |

### 2.4 重要程度定义

| 级别 | 定义 | 管理要求 |
|:----:|------|---------|
| **关键** | 没有它项目无法运行/构建/部署 | 必须有替代方案，版本锁定，定期验证 |
| **重要** | 没有它核心功能受影响 | 建议有替代方案，版本锁定 |
| **一般** | 没有它部分功能受影响，可临时绕过 | 版本建议锁定，定期检查 |
| **可选** | 没有它不影响核心功能，只是优化 | 版本自由，按需更新 |

## 三、版本管理

### 3.1 版本锁定策略

| 依赖级别 | 版本策略 | 说明 |
|:--------:|---------|------|
| 关键依赖 | 精确版本锁定 | 锁定到具体版本号（如 18.17.0），不自动升级 |
| 重要依赖 | 次版本锁定 | 锁定主版本.次版本（如 ^18.17.0），补丁版本可自动升级 |
| 一般依赖 | 主版本锁定 | 锁定主版本（如 ^18.0.0），次版本和补丁可升级 |
| 可选依赖 | 版本自由 | 不锁定，使用最新版本 |

### 3.2 版本升级策略

| 升级类型 | 触发条件 | 流程要求 | 测试要求 |
|---------|---------|---------|---------|
| 补丁升级 | 安全补丁/bug修复 | 可自动升级，记录变更 | 基本功能验证 |
| 次版本升级 | 新功能/性能优化 | 需评估影响，D3操作决策 | 相关功能测试 |
| 主版本升级 | 重大变更/不兼容 | 必须完整评估，D2战术决策 | 全量回归测试 |
| 安全紧急升级 | 严重安全漏洞 | 立即评估，紧急升级流程 | 安全验证+基本功能 |

### 3.3 兼容性检查

升级依赖前必须检查：

| 检查项 | 说明 |
|--------|------|
| 向后兼容性 | 新版本是否向后兼容，是否有breaking changes |
| 依赖冲突 | 新版本是否与其他依赖冲突 |
| API变更 | 使用的API是否有变更或废弃 |
| 性能影响 | 新版本是否影响性能 |
| 安全影响 | 新版本是否引入安全问题 |
| 许可证变更 | 许可证是否变更，是否影响项目 |

### 3.4 版本锁定文件

| 文件 | 用途 | 说明 |
|------|------|------|
| package-lock.json | Node.js依赖锁定 | npm自动生成，必须提交到版本控制 |
| yarn.lock | Yarn依赖锁定 | Yarn自动生成，必须提交 |
| requirements.txt | Python依赖锁定 | 手动维护，必须提交 |
| .nvmrc | Node.js版本锁定 | 指定Node版本，必须提交 |
| 配置文件 | 其他依赖版本 | 在项目配置中记录 |

**规则**：所有版本锁定文件必须提交到版本控制，不加入.gitignore。

## 四、环境配置管理

### 4.1 环境分类

| 环境 | 用途 | 数据 | 访问权限 |
|------|------|------|---------|
| **开发环境** | 日常开发和测试 | 测试数据/模拟数据 | 开发者可读写 |
| **测试环境** | QA测试和集成测试 | 测试数据/脱敏数据 | 测试人员可读写 |
| **预发布环境** | 发布前验证 | 生产数据副本/脱敏 | 有限访问 |
| **生产环境** | 正式运行 | 真实数据 | 严格控制，只读为主 |

### 4.2 环境配置管理

| 配置项 | 管理方式 | 说明 |
|--------|---------|------|
| 环境变量 | .env文件+环境变量管理 | 敏感信息不提交版本控制，使用.env.example模板 |
| 配置文件 | 按环境分离（config.dev.json/config.prod.json） | 不同环境使用不同配置 |
| 依赖版本 | 版本锁定文件 | 见§三版本管理 |
| 工具版本 | 版本管理工具（nvm/pyenv等） | 统一工具版本 |
| 权限设置 | 按环境分配权限 | 生产环境严格控制权限 |

### 4.3 环境差异记录

必须记录不同环境之间的差异：

| 记录项 | 说明 |
|--------|------|
| 环境差异清单 | 列出各环境的配置差异 |
| 差异原因 | 为什么有这个差异 |
| 同步计划 | 何时同步差异，或永久保持差异 |
| 影响评估 | 差异可能导致什么问题 |

### 4.4 环境检查清单

任务执行前必须检查环境：

| 检查项 | 说明 |
|--------|------|
| 工具版本 | 所需工具是否安装，版本是否正确 |
| 依赖安装 | 依赖是否安装，版本是否匹配 |
| 环境变量 | 必要的环境变量是否设置 |
| 网络连接 | 网络是否正常，VPN是否开启（如需） |
| 服务可用性 | 依赖的外部服务是否可用 |
| 权限检查 | 是否有足够的权限执行操作 |
| 磁盘空间 | 是否有足够的磁盘空间 |

## 五、依赖变更影响分析

### 5.1 变更评估流程

```
提出变更申请
  ↓
评估变更类型（补丁/次版本/主版本/安全紧急）
  ↓
检查兼容性（见§3.3）
  ↓
评估影响范围
  ↓
制定测试计划
  ↓
制定回滚方案
  ↓
按决策级别确认（D2/D3）
  ↓
执行变更
  ↓
验证效果
  ↓
更新依赖清单和文档
```

### 5.2 影响范围评估

| 评估维度 | 说明 |
|---------|------|
| 直接影响 | 直接使用该依赖的代码/功能 |
| 间接影响 | 通过其他模块间接依赖的部分 |
| 性能影响 | 对系统性能的影响 |
| 安全影响 | 对安全性的影响 |
| 兼容性影响 | 与其他依赖/环境的兼容性 |
| 部署影响 | 对部署流程的影响 |
| 数据影响 | 是否需要数据迁移/转换 |

### 5.3 测试要求

| 变更类型 | 测试要求 |
|---------|---------|
| 补丁升级 | 基本功能验证+安全验证 |
| 次版本升级 | 相关功能测试+性能测试 |
| 主版本升级 | 全量回归测试+性能测试+安全测试 |
| 安全紧急升级 | 安全验证+基本功能验证 |
| 新增依赖 | 集成测试+性能测试+安全扫描 |
| 移除依赖 | 回归测试（确认移除后无影响） |

### 5.4 回滚方案

任何依赖变更必须有回滚方案：

| 回滚方式 | 适用场景 | 操作步骤 |
|---------|---------|---------|
| 版本回退 | 版本升级失败 | 恢复到旧版本号，重新安装依赖 |
| 配置回滚 | 配置变更失败 | 从备份恢复配置文件 |
| 环境回滚 | 环境变更失败 | 从快照/镜像恢复环境 |
| 代码回滚 | 代码变更失败 | Git revert/reset到变更前版本 |

**回滚验证**：回滚后必须验证系统是否恢复正常。

## 六、替代方案管理

### 6.1 关键依赖替代方案

关键依赖必须有替代方案：

| 字段 | 说明 |
|------|------|
| 原依赖 | 关键依赖名称 |
| 替代方案 | 替代的工具/库/服务 |
| 替代成本 | 切换需要多少时间/资源 |
| 功能差异 | 替代方案与原依赖的功能差异 |
| 切换条件 | 什么情况下切换到替代方案 |
| 切换流程 | 切换的具体步骤 |
| 回切流程 | 如何切回原依赖 |
| 最后验证日期 | 替代方案最后一次验证可用的日期 |

### 6.2 单点故障预防

| 预防措施 | 说明 |
|---------|------|
| 关键依赖有替代 | 所有关键依赖必须有替代方案 |
| 多供应商策略 | 关键服务不依赖单一供应商 |
| 本地缓存 | 关键依赖/数据本地缓存，网络中断时可用 |
| 降级方案 | 依赖不可用时，系统可降级运行 |
| 定期演练 | 定期演练替代方案切换，确保可用 |

### 6.3 替代方案切换流程

```
发现原依赖不可用
  ↓
评估影响范围和持续时间
  ↓
决定是否切换（短期故障不切换，长期故障切换）
  ↓
按切换流程执行
  ↓
验证替代方案可用
  ↓
通知相关方
  ↓
原依赖恢复后，评估是否回切
  ↓
记录事件和改进措施
```

## 七、环境问题诊断

### 7.1 常见环境问题

| 问题类型 | 常见原因 | 解决方法 |
|---------|---------|---------|
| 依赖缺失 | 未安装依赖/版本不对 | 安装依赖/切换版本 |
| 权限不足 | 文件/目录权限不够 | 调整权限/使用管理员 |
| 端口占用 | 端口被其他进程占用 | 更换端口/关闭占用进程 |
| 网络不通 | 网络故障/VPN未开/防火墙 | 检查网络/开启VPN/配置防火墙 |
| 配置错误 | 配置文件错误/环境变量未设 | 修正配置/设置环境变量 |
| 磁盘满 | 磁盘空间不足 | 清理文件/扩容 |
| 缓存问题 | 缓存过期/损坏 | 清除缓存/重启服务 |
| 版本冲突 | 依赖版本冲突 | 调整版本/升级依赖 |

### 7.2 诊断流程

```
发现环境问题
  ↓
记录错误信息（完整错误日志/截图）
  ↓
初步判断问题类型（参考§7.1）
  ↓
按对应类型排查
  ↓
找到原因？
  ├─ 是 → 执行解决方法 → 验证解决 → 记录问题和解决方案
  └─ 否 → 扩大排查范围 → 搜索错误信息 → 寻求帮助
  ↓
无法解决？→ 升级到人类/专家，提供完整诊断信息
```

### 7.3 诊断信息收集

遇到环境问题时，必须收集以下信息：

| 信息 | 说明 |
|------|------|
| 完整错误信息 | 错误日志/错误码/堆栈跟踪 |
| 操作步骤 | 执行了什么操作导致问题 |
| 环境信息 | OS版本/工具版本/依赖版本 |
| 配置信息 | 相关配置文件/环境变量 |
| 复现步骤 | 如何复现这个问题 |
| 已尝试的解决方法 | 已经试过什么，结果如何 |
| 截图/录屏 | 问题现象的可视化记录 |

### 7.4 问题知识库

解决的环境问题必须记录到知识库：

| 记录项 | 说明 |
|--------|------|
| 问题描述 | 问题现象和错误信息 |
| 根本原因 | 问题的根本原因 |
| 解决方法 | 具体的解决步骤 |
| 预防措施 | 如何避免再次发生 |
| 相关依赖 | 涉及哪些依赖/工具 |
| 发生日期 | 问题发生的日期 |
| 解决日期 | 问题解决的日期 |

## 八、AI在环境与依赖管理中的职责

### 8.1 AI 必须做的

| 职责 | 说明 | 频率 |
|------|------|:----:|
| 环境检查 | 任务执行前检查环境是否满足要求 | 每次任务 |
| 依赖检查 | 检查所需依赖是否安装，版本是否正确 | 每次任务 |
| 依赖清单维护 | 新增/移除/变更依赖时更新清单 | 每次变更 |
| 版本锁定 | 确保版本锁定文件正确维护 | 持续 |
| 环境问题诊断 | 遇到环境问题按流程诊断 | 每次问题 |
| 问题记录 | 解决的环境问题记录到知识库 | 每次解决 |
| 替代方案验证 | 定期验证关键依赖的替代方案 | 每月 |
| 依赖更新提醒 | 依赖有重要更新时提醒用户 | 持续 |

### 8.2 AI 不能做的

| 禁止行为 | 原因 |
|---------|------|
| 擅自升级依赖 | 依赖升级必须评估影响，用户确认 |
| 擅自修改环境配置 | 环境配置变更可能影响其他任务 |
| 安装未授权的软件 | 安全风险，必须用户确认 |
| 隐瞒环境问题 | 环境问题必须及时报告，不隐瞒 |
| 跳过环境检查 | 任务前必须检查环境，不跳过 |
| 删除版本锁定文件 | 版本锁定文件必须保留 |
| 在生产环境做实验 | 生产环境严格控制，不在生产做实验 |

### 8.3 AI 何时请求人类介入

| 场景 | 介入方式 |
|------|---------|
| 需要安装新软件/工具 | 请求用户确认安装 |
| 依赖主版本升级 | 请求用户确认升级方案 |
| 环境配置重大变更 | 请求用户确认变更 |
| 环境问题无法解决 | 请求人类/专家帮助 |
| 生产环境操作 | 必须人类确认和监督 |
| 安全相关变更 | 必须人类确认 |
