## 一、文档概述

### 1.1 目的

本文档定义项目风险管理的**完整流程、分类体系、评估方法、应对策略和监控机制**，确保：
1. 风险被系统性地识别，不遗漏关键风险
2. 风险被量化评估，优先级清晰
3. 每个风险都有明确的应对措施和负责人
4. 风险状态被持续监控，异常时及时预警
5. AI 执行任务时主动识别和管理相关风险

### 1.2 适用范围

| 场景 | 是否适用 | 说明 |
|------|:-------:|------|
| 项目任务执行 | ✅ 适用 | 任务开始时必须检查相关风险 |
| 高风险操作（R3/R4） | ✅ 强制适用 | 必须包含风险评估和应对措施 |
| 简单一次性任务 | ⚠️ 简化适用 | 只需识别是否有高风险，无需完整流程 |
| 普通办公/闲聊 | ❌ 不适用 | 不走风险管理流程 |

## 二、风险管理流程

### 2.1 五阶段流程

```
识别 → 评估 → 应对 → 监控 → 复盘
 ↓      ↓      ↓      ↓      ↓
发现   分级   措施   跟踪   改进
风险   排序   执行   预警   沉淀
```

### 2.2 阶段一：风险识别

**触发时机**：
- 新项目启动时
- 新任务开始时（10步链路步骤1）
- 高风险操作执行前（R3/R4）
- 定期风险回顾时（每周/每月）
- 外部环境发生重大变化时

**识别方法**：

| 方法 | 说明 | 适用场景 |
|------|------|---------|
| 检查清单法 | 对照风险分类清单逐项检查 | 任务开始时的快速识别 |
| 历史复盘法 | 回顾类似任务/项目的历史风险 | 有历史经验的任务 |
| 假设分析法 | 分析任务的关键假设，假设不成立即为风险 | 复杂任务/新领域任务 |
| 影响范围法 | 分析任务影响的系统/文档/数据，影响越大风险越多 | 高风险操作 |
| 专家咨询法 | 向有经验的人咨询潜在风险 | 不确定的领域 |

**AI 必须执行的识别动作**：
1. 任务开始时，对照§三风险分类清单逐项检查
2. 高风险操作（R3/R4）必须输出风险识别清单
3. 识别到的风险必须立即登记到风险登记册

### 2.3 阶段二：风险评估

**评估维度**：

| 维度 | 定义 | 评分标准 |
|------|------|---------|
| 概率 | 风险发生的可能性 | 1-5分（1=极低，5=极高） |
| 影响 | 风险发生后的后果严重程度 | 1-5分（1=轻微，5=灾难） |
| 可检测性 | 风险发生前能否被提前发现 | 1-5分（1=极易发现，5=无法发现） |

**风险等级 = 概率 × 影响**（可检测性作为调整因子）

| 风险等级 | 分数范围 | 含义 | 响应时间 |
|:--------:|:--------:|------|:--------:|
| P0 极高 | 20-25 | 可能导致项目失败/数据丢失/安全事故 | 立即处理 |
| P1 高 | 12-19 | 严重影响进度/质量/成本 | 24小时内 |
| P2 中 | 6-11 | 一定影响，但可控制 | 本周内 |
| P3 低 | 1-5 | 影响很小，可接受 | 下次更新时 |

**评估输出**：
- 每个识别到的风险必须完成评估
- 评估结果必须记录在风险登记册中
- P0/P1 风险必须在任务方案中包含应对措施

### 2.4 阶段三：风险应对

**四种应对策略**：

| 策略 | 定义 | 适用场景 | 示例 |
|------|------|---------|------|
| 规避 | 消除风险源，改变计划以避免风险 | 高概率高影响且可避免 | 不使用不稳定的工具，改用成熟方案 |
| 转移 | 将风险转移给第三方 | 风险影响大但自身无法控制 | 使用云服务备份，将数据丢失风险转移给服务商 |
| 减轻 | 降低风险概率或影响 | 无法规避但可降低 | 创建备份/快照，降低操作失败的影响 |
| 接受 | 承认风险存在，不主动处理 | 低概率低影响，处理成本大于收益 | 记录风险，定期监控，发生时再处理 |

**策略选择原则**：
1. P0/P1 风险优先考虑规避或减轻，不允许仅接受
2. 选择策略时需考虑成本效益（处理成本 vs 风险损失）
3. 每个风险必须有明确的应对策略和具体措施
4. 应对措施必须可执行、可验证

**AI 必须执行的应对应作**：
1. P0/P1 风险必须在方案中包含应对措施
2. 高风险操作（R3/R4）必须有减轻措施（备份/快照/回滚方案）
3. 应对措施执行后必须验证效果

### 2.5 阶段四：风险监控

**监控频率**：

| 风险等级 | 监控频率 | 监控方式 |
|:--------:|:--------:|---------|
| P0 极高 | 每天 | 主动检查状态，异常立即通知 |
| P1 高 | 每周 | 每周回顾，更新状态 |
| P2 中 | 每两周 | 双周回顾 |
| P3 低 | 每月 | 月度回顾 |

**预警阈值**：
- 风险概率上升 1 级 → 预警
- 风险影响上升 1 级 → 预警
- 风险等级从 P2 升至 P1 → 立即通知
- 风险等级从 P1 升至 P0 → 立即通知+暂停相关任务

**状态流转**：

```
已识别 → 评估中 → 已评估 → 应对中 → 已缓解 → 已关闭
                ↓                    ↓
              已接受              已发生（启动应急）
```

### 2.6 阶段五：风险复盘

**触发时机**：
- 风险发生后（无论是否造成损失）
- 项目阶段结束时
- 定期复盘（每月/每季度）

**复盘内容**：
1. 风险是否被提前识别？
2. 评估是否准确？
3. 应对措施是否有效？
4. 监控是否及时？
5. 有什么经验教训？
6. 如何改进风险管理流程？

**复盘输出**：
- 经验教训记录在项目记忆中
- 流程改进建议加入 PDCA 循环
- 高频风险更新到风险检查清单

## 三、风险分类体系

### 3.1 六大类风险

| 类别 | 说明 | 典型风险 |
|------|------|---------|
| **技术风险** | 技术方案、工具、代码相关的风险 | 技术方案不可行、工具不稳定、代码bug、兼容性问题、性能问题 |
| **进度风险** | 时间、计划、依赖相关的风险 | 任务延期、依赖未就绪、估算不准、资源冲突 |
| **质量风险** | 交付物质量相关的风险 | 需求理解偏差、测试不充分、文档错误、回归问题 |
| **资源风险** | 人力、工具、环境、数据相关的风险 | 工具不可用、环境问题、数据丢失、权限不足 |
| **外部风险** | 外部环境、第三方、政策相关的风险 | 网络中断、第三方服务故障、政策变化、VPN不可用 |
| **合规风险** | 法律、伦理、安全相关的风险 | 数据隐私泄露、安全漏洞、违规操作、知识产权问题 |

### 3.2 AI 执行任务时的高频风险

| 风险 | 类别 | 概率 | 影响 | 等级 | 典型场景 |
|------|:----:|:----:|:----:|:----:|---------|
| 误删文件/数据 | 技术 | 中 | 极高 | P1 | 执行删除操作时误删 |
| 修改范围越权 | 合规 | 中 | 高 | P1 | "顺手"修改不在任务范围内的文件 |
| 规范理解偏差 | 质量 | 高 | 中 | P2 | 未正确理解项目规范，执行方向错误 |
| 工具/环境不可用 | 资源 | 中 | 中 | P2 | VPN未开、工具未安装、环境配置错误 |
| 文档不同步 | 质量 | 高 | 低 | P3 | 母本更新后子项目未同步 |
| 过度执行 | 合规 | 中 | 中 | P2 | 超出用户要求范围，主动扩展任务 |
| 回滚方案缺失 | 技术 | 中 | 高 | P1 | 高风险操作前未创建备份/快照 |
| 网络连接失败 | 外部 | 中 | 中 | P2 | 需要外网但VPN未开或网络故障 |

## 四、风险评估方法

### 4.1 概率评分标准

| 分数 | 等级 | 描述 | 量化参考 |
|:----:|:----:|------|---------|
| 5 | 极高 | 几乎肯定发生 | >90% 概率 |
| 4 | 高 | 很可能发生 | 60-90% 概率 |
| 3 | 中 | 可能发生 | 30-60% 概率 |
| 2 | 低 | 不太可能发生 | 10-30% 概率 |
| 1 | 极低 | 几乎不可能发生 | <10% 概率 |

### 4.2 影响评分标准

| 分数 | 等级 | 描述 | 量化参考 |
|:----:|:----:|------|---------|
| 5 | 灾难 | 项目失败/数据丢失/安全事故/不可逆损失 | 损失>项目总投入50% |
| 4 | 严重 | 严重影响进度/质量/成本，需重大调整 | 损失>项目总投入20% |
| 3 | 中等 | 一定影响，需额外资源处理 | 损失>项目总投入5% |
| 2 | 轻微 | 影响小，可在正常流程内处理 | 损失<项目总投入5% |
| 1 | 可忽略 | 几乎无影响 | 可忽略 |

### 4.3 风险矩阵

```
影响↑
5    | P1  P1  P0  P0  P0
4    | P2  P1  P1  P0  P0
3    | P2  P2  P1  P1  P0
2    | P3  P2  P2  P1  P1
1    | P3  P3  P2  P2  P1
     ------------------------→ 概率
       1   2   3   4   5
```

### 4.4 可检测性调整

可检测性作为调整因子：
- 可检测性=1（极易发现）→ 风险等级可降1级
- 可检测性=5（无法发现）→ 风险等级必须升1级

**示例**：概率3×影响3=9（P2），但可检测性=5（无法发现）→ 调整为P1

## 五、风险应对策略

### 5.1 策略选择决策树

```
风险发生？
├─ 是 → 启动应急响应（见应急与回滚规范）
└─ 否 → 风险可规避？
    ├─ 是 → 规避（改变计划/方案）
    └─ 否 → 风险可转移？
        ├─ 是 → 转移（第三方/保险/服务）
        └─ 否 → 处理成本 < 风险损失？
            ├─ 是 → 减轻（降低概率/影响）
            └─ 否 → 接受（记录+监控）
```

### 5.2 各等级风险的最低应对要求

| 风险等级 | 最低应对要求 | 必须包含 |
|:--------:|------------|---------|
| P0 极高 | 规避或减轻 | 应对措施+负责人+完成时间+验证方法 |
| P1 高 | 减轻（不允许仅接受） | 应对措施+负责人+完成时间 |
| P2 中 | 减轻或接受 | 应对措施或接受理由+监控频率 |
| P3 低 | 接受 | 记录+定期监控 |

### 5.3 常见风险的应对模板

| 风险 | 推荐策略 | 具体措施 |
|------|---------|---------|
| 误删文件/数据 | 减轻 | 操作前创建备份/快照，操作后验证，准备回滚方案 |
| 修改范围越权 | 规避 | 严格按任务清单执行，修改范围外文件前必须获得确认 |
| 规范理解偏差 | 减轻 | 执行前复述理解，关键节点确认，对照规范检查 |
| 工具/环境不可用 | 减轻 | 执行前检查环境，准备替代方案，记录环境依赖 |
| 回滚方案缺失 | 规避 | 高风险操作前必须创建备份/快照，无备份不执行 |
| 网络连接失败 | 减轻 | 需要外网前检查VPN，准备离线方案，记录网络依赖 |

## 六、风险监控机制

### 6.1 定期风险回顾

| 回顾类型 | 频率 | 参与人 | 内容 |
|---------|:----:|-------|------|
| 每日快速回顾 | 每天 | AI | P0风险状态检查 |
| 每周风险回顾 | 每周 | AI+用户 | P0/P1风险状态更新，新风险识别 |
| 每月全面回顾 | 每月 | AI+用户 | 全部风险回顾，风险趋势分析，流程改进 |
| 项目阶段回顾 | 阶段结束 | AI+用户 | 风险复盘，经验教训沉淀 |

### 6.2 风险预警与升级

**预警触发条件**：
- 风险概率上升 1 级
- 风险影响上升 1 级
- 风险等级上升 1 级
- 应对措施未按计划执行
- 新识别到 P0/P1 风险

**升级机制**：
- P2→P1：通知用户，更新应对措施
- P1→P0：通知用户，暂停相关任务，紧急评估
- 风险发生：启动应急响应（见应急与回滚规范）

### 6.3 风险状态定义

| 状态 | 定义 | 转换条件 |
|------|------|---------|
| 已识别 | 风险已发现但未评估 | 完成评估后→已评估 |
| 已评估 | 风险已完成评估，有等级 | 制定应对措施后→应对中/已接受 |
| 应对中 | 正在执行应对措施 | 措施生效后→已缓解 |
| 已缓解 | 风险概率/影响已降低 | 持续监控，风险消除后→已关闭 |
| 已接受 | 接受风险，不主动处理 | 定期监控，状态变化后重新评估 |
| 已发生 | 风险已经发生 | 启动应急响应，处理后→已关闭 |
| 已关闭 | 风险已消除或不再相关 | 记录关闭原因和日期 |

| 计划完成日期 | 应对措施计划完成时间 | P0/P1必填 |
| 实际完成日期 | 应对措施实际完成时间 | 完成后填写 |
| 关闭日期 | 风险关闭日期 | 关闭时填写 |
| 备注 | 其他需要记录的信息 | 可选 |

### 7.3 更新规则

| 操作 | 时机 | 要求 |
|------|------|------|
| 新增风险 | 识别到新风险时 | 24小时内完成评估和登记 |
| 更新状态 | 风险状态变化时 | 立即更新，记录变化原因 |
| 更新评估 | 风险概率/影响变化时 | 重新计算等级，更新应对措施 |
| 定期回顾 | 每周/每月 | 全部风险检查状态，更新过期信息 |
| 关闭风险 | 风险消除或不再相关时 | 记录关闭原因，保留历史记录 |

### 7.4 查询方法

| 查询需求 | 方法 |
|---------|------|
| 查看所有P0/P1风险 | 按风险等级筛选 |
| 查看某类别的风险 | 按风险类别筛选 |
| 查看应对中的风险 | 按状态筛选 |
| 查看本月新增风险 | 按发现日期筛选 |
| 查看已关闭的风险 | 按状态筛选，作为历史参考 |

## 八、AI在风险管理中的职责

### 8.1 AI 必须做的

| 职责 | 执行时机 | 输出 |
|------|---------|------|
| 风险识别 | 任务开始时/高风险操作前 | 风险识别清单 |
| 风险评估 | 识别到风险后24小时内 | 风险等级+评估依据 |
| 风险登记 | 评估完成后 | 更新风险登记册 |
| 应对措施制定 | P0/P1风险 | 具体可执行的应对措施 |
| 风险监控 | 定期回顾 | 风险状态更新+预警 |
| 风险预警 | 风险状态恶化时 | 通知用户+建议措施 |
| 风险复盘 | 风险发生后/阶段结束 | 经验教训+改进建议 |

### 8.2 AI 不能做的

| 禁止行为 | 原因 |
|---------|------|
| 隐瞒风险 | 风险必须透明，不能因为怕麻烦而不报告 |
| 低估风险 | 不能为了推进任务而故意降低风险等级 |
| 未经确认接受P0/P1风险 | P0/P1风险必须用户确认后才能接受 |
| 跳过风险评估 | 高风险操作必须完成风险评估才能执行 |
| 删除风险记录 | 风险记录必须保留历史，不能删除 |

### 8.3 AI 何时必须请求人类介入

| 场景 | 介入方式 |
|------|---------|
| 识别到P0风险 | 立即通知用户，暂停相关任务，等待指示 |
| P0/P1风险需要接受策略 | 必须用户确认，AI不能自行决定接受 |
| 风险应对措施需要额外资源 | 向用户说明需求，等待确认 |
| 风险已经发生 | 立即通知用户，启动应急响应，等待指示 |
| 风险评估不确定 | 向用户说明不确定性，请求专家意见 |

## 九、风险管理检查清单

### 9.1 任务开始时（步骤1-2）

- [ ] 对照风险分类清单，识别本次任务的潜在风险
- [ ] 高风险操作（R3/R4）已输出风险识别清单
- [ ] 识别到的风险已登记到风险登记册
- [ ] P0/P1风险已完成评估
- [ ] P0/P1风险已制定应对措施

### 9.2 方案制定时（步骤3-7）

- [ ] 方案中包含风险评估部分
- [ ] P0/P1风险的应对措施已纳入方案
- [ ] 高风险操作有备份/快照/回滚方案
- [ ] 风险应对措施的成本效益已评估
- [ ] 用户已确认P0/P1风险的应对策略

### 9.3 执行中（步骤8）

- [ ] 按计划执行风险应对措施
- [ ] 监控风险状态，发现变化及时更新
- [ ] 风险预警时立即通知用户
- [ ] 风险发生时启动应急响应
- [ ] 不隐瞒、不低估任何风险

### 9.4 完成时（步骤9-10）

- [ ] 全部相关风险状态已更新
- [ ] 已缓解的风险验证效果
- [ ] 已关闭的风险记录关闭原因
- [ ] 风险复盘已完成（如适用）
- [ ] 经验教训已记录到项目记忆

### 9.5 定期回顾（每周/每月）

- [ ] P0风险每日检查状态
- [ ] P0/P1风险每周回顾
- [ ] 全部风险每月全面回顾
- [ ] 过期信息已更新
- [ ] 风险趋势已分析
- [ ] 流程改进建议已记录
